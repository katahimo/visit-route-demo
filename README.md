# 訪問ルートAI デモ版

訪問型サービスの「だれを・どの順で」行かせるかを、ブラウザだけで試せるデモ。
訪問を入れると担当を自動で組み、急な欠勤の振り直しと連絡文、問い合わせへの空き状況の答えまでを1つの画面で扱う。相性・スタッフの特性・顧客の希望は、項目と重み（0〜5）・必須で組み立てられる（エキスパート機能）。

- データは**このブラウザの中だけ**に保存（localStorage）。サーバーへは送らない。実在の個人情報は入れない
- 同梱のデータは架空（仙台市の公共施設を擬人化したスタッフ・訪問先）
- 本体：`katahimo-dev/visit-route-poc`（Firebase 版 PoC）

設計：[docs/prd.md](docs/prd.md)／[docs/design.md](docs/design.md)／[docs/adr/](docs/adr/)。AI エージェント向けのルールは [AGENTS.md](AGENTS.md)。

公開先：https://staff-assign-demo.katahimo.com/ （Cloudflare Workers の静的アセット。ADR-0071）。main に push すると GitHub Actions がテスト→ビルド→公開

## 使い方（デモ）

1. 初めて開くと2問（デモで試す／自分のデータで始める、単発の予約が中心／定期の訪問が中心）。「デモで試す」は架空のデータを作り、今日〜翌月末の担当なしを1回自動で組んでから始まる（PRD D379・D409）
2. メニューは 予定・空き状況・〈利用者さん〉・〈スタッフ〉・設定（スマホは下のタブ）。予定は月・週・日を［月｜週｜日］で切り替え、上の要対応の帯（担当なし・重なり・休みの人）から手当ての要る訪問へ移る。「予定を入れる」で訪問・繰り返しを足すと、入れた分の担当を自動で組む
3. 急な欠勤・キャンセルは予定の「欠勤・キャンセルを登録」：何が起きたかを選ぶと振り直しの見込みが出て、［この案で決める］→ 人ごとの連絡文をコピー・メール（アプリは送らない）
4. 空き状況：曜日・時間帯・所要のチップで、受けられる曜日・時間帯を答えのカードに出し［要約をコピー］
5. 設定の管理者設定で機能を入り切りする。エキスパート機能を入れると、条件の重み（項目・重み0〜5・必須）・組み方の標準・担当を組む（AI の提案）・案を比べる・確定（伝えた）が出る
6. 設定のデータで控えの書き出し・読み込み・Excel の書き出しと読み込み・初期状態に戻す

## ローカルで動かす

```bash
npm ci
npx playwright install chromium   # e2e のブラウザ（PLAYWRIGHT_BROWSERS_PATH に入っていれば不要）
npm run dev        # http://localhost:5173
npm test && npm run lint && npm run typecheck && npm run check:code && npm run check:prd && npm run build
npm run e2e        # 本物のブラウザの e2e（ビルドと配信も。ADR-0029）
```
