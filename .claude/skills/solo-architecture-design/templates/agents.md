# AGENTS.md

このリポジトリで作業するAIコーディングエージェント向けのルール。
設計の正は `docs/design.md`、API契約の正は `docs/api/`。これらと矛盾する実装をしない。

## 作業の原則
- 担当範囲（作業指示書に書かれたコンポーネント）以外のファイルを変更しない
- API契約にない入出力・エラー・デフォルト値を勝手に追加しない。必要なら作業を止めて質問する
- 他コンポーネントの内部（DB・非公開の関数）を直接使わない。公開されたAPI（入口）だけを使う
- 仕様が不明なときは推測で埋めず、`QUESTIONS:` として最後にまとめて報告する

## 設計・実装の原則（Clean / SOLID）
詳しくは solo-architecture-design スキルの `references/code-principles.md`。
- 依存は内側へだけ：domain は他の層を import しない。業務ロジックは React・DB・外部 SDK に依存しない
- 1ファイル 600 行・1関数（部品）150 行を超えない。超えそうなら、計算は純粋関数、状態と処理はフック、見た目は小さい部品に分ける
- 計算（データを作る・数える・判定する）は画面に書かず、純粋関数にしてテストを付ける
- 新しい関数を作る前に、同じ働きのものを grep で探す。同じ処理を2か所に書かない。同じ名前で別の意味のものを作らない
- 種類ごとの分岐は1か所に集め、switch は `never` で網羅を型で確かめる
- 使われなくなったコード・CSS・テストは同じ変更で消す
- 違反は `code-rules.json` の検査（下の「コマンド」）で増やさない。直して減らしたら基準を更新する

## ディレクトリ構成
```
src/
  modules/<コンポーネント名>/
    index.ts        … 公開する入口（他モジュールはここだけをimportする）
    domain/         … 業務ルール・型（他の層をimportしない）
    application/    … ユースケース
    infrastructure/ … DB・外部APIの実装
docs/
  design.md
  api/openapi.yaml
  adr/
```
