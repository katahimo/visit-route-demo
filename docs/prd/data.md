| D253 | **e2e の確かめを1つずつ報告に出す**（ADR-0041）：e2e の報告で、スクリプトの段（step）ごと・確かめ（`OK`／`NG` の1行）ごとに合否が見える（名前は今のまま。1つ落ちても続きの確かめは走る）。落ちた test には trace・動画・止まったときのスクリーンショット・記録が付き、CI では成果物に残る。押したあとの待ちは固定の時間でなく画面の状態（描き直し・遅らせた処理が終わった・目印が出た）で待つ（速さの計測の待ちと、偽のサービスの遅れを待つ所は固定のまま）。相性の画面の速さの関門（300人×60人でセルを1回押して描き終わるまで中央値 100ms 以下）は、ならし3回のあと9回の中央値、超えたら1秒置いて最大3回りまで測り直し一番よい回りで比べる（ほかの処理と CPU を取り合った回りを外し、どの回りも遅いなら落とす）。競合の印（行頭の `<<<<<<<`・`>>>>>>>`）がコミットされていたら `npm run lint` と PR の CI で落とす | Must |
| D254 | `npm test`（vitest）は負荷のあるときも終了コードが揺れない：各 test の前にイベントループを1回まわして worker が親からの返事を読めるようにし、1つの test の同期の計算を短く分け（AI案と素朴な案の比べは日ごと）、worker の連絡（`onTaskUpdate`。60秒）を時間切れにしない。重い test の時間切れは 60秒。CI（deploy.yml の `npm test`）も同じ設定 | Must |

## フォーム（入力と保存）

| ID | 要件 | 優先度 |
|---|---|---|
| D250 | 入力の誤りは赤い文で欄の近くに出す。保存を押したときの誤りは出たら読み上げ（`role="alert"`。同じ誤りで押し直しても読み上げ直す）、打つたびに検査する欄の誤りは読み上げで割り込まない。誤った入力欄には誤りの印（`aria-invalid`）と誤りの文へのつながり（`aria-describedby`）を付ける。必須の欄は見出しに小さな「必須」の札を付け、読み上げにも必須と伝える。見た目は今までの赤い文のまま | Must |
| D251 | 入力の欄（訪問・〈利用者さん〉・〈スタッフ〉・種類・欠勤・仮押さえ・呼び方）は Enter で保存（複数行の欄は除く。欄の中の定期パターン・休みの入力の Enter はそのまとまりの保存）。保存して誤りがあれば最初の誤った欄へフォーカス。訪問の入力は開いたら最初の欄へフォーカスし、閉じたら開いたボタン（無ければ「訪問を追加」）へ戻す。日の予定の日を変えても入力を捨てずに引き継ぐ（日を変えて保存する日が表示中の日と違えば知らせ、表示中の日にするボタンを出す）。開いた後に消された・取り消された訪問は保存せず知らせる | Must |
