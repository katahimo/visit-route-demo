# PRD §3 要件：AI の提案・条件・点数

共通の決まり・読み方・索引は [../prd.md](../prd.md) §3。画面の細部は `docs/design.md`・`docs/design/`。

## 提案・条件・点数（ADR-0008・ADR-0010・ADR-0065・ADR-0088）

| ID | 要件 | 優先度 |
|---|---|---|
| D7 | **条件**を並べ、各々に**重み 0〜5**（0＝無効。1＝1件あたり移動10分ぶん）か**必須**。型：必要条件・希望（満たすと加点）・相性・担当の継続（いつもの担当）・負担の均等・移動と待ち・続く訪問は同じ人（D453）・夕方は自宅に近い人（D455） | Must |
| D9 | ブラウザ内（Web Worker・焼きなまし）で**提案（担当と順番）**を作る。時間の約束・稼働時間帯・必須の条件は破らず、重み付きの条件は移動と同じ分換算で足して最小化。計算中も画面は固まらない | Must |
| D10 | 同じ入力・同じ seed からは同じ提案 | Must |
| D12 | 訪問ごとに「なぜこの担当か」（相性◎・希望○ 女性・資格✓・継続・移動12分 など。見せ方は D229）。入らなかった訪問は原因の条件 | Must |
| D17 | 各〈スタッフ〉の件数を、稼働時間に比例した目安へ寄せる（外れた件数の2乗で重く）。必須なら目安の上限＋1件を超えない。既定は重み3 | Must |
| D20 | 条件の**プリセット**（初期：バランス・移動を短く・人の組み合わせ重視）。プリセットの重み・必須は変えられず、条件の重みの表で直すと「調整した重み」（1つだけ）に保存して点数の基準にする（最大6つ。D286）。名前・一言の編集・消す・点数の基準に選ぶは条件の重みの「考え方（プリセット）の管理」（D235）。提案を比べるで考え方として使う（重みは変えない。D318）。**点数はいつも「点数の基準」のプリセット**（条件の重みのプリセットの一覧の行の丸で1つ選ぶ。初期はバランス）で付ける | Must |
| D25 | 今の担当の**条件ごとの達成の件数**（例 希望 18/20件・相性◎○ 6件・△ 1件・負担の均等 7/8人。分母はその条件が関わる訪問）を「詳しく」とカードの要約で。点数の基準の物差しで数える | Should |
| D173 | 今の担当の1行で点数の横に「点を下げているいちばんの理由」（今の採点の内訳から）：必須の違反があれば「必須の違反 N件」、入らない訪問があれば「入らない訪問 N件」、減点 0.5点未満なら出さない、ほかは減点の最大の成分（「移動が長め（N分）」「相性△が N件」「「条件名」に合わない訪問 N件」「件数の偏り（N人）」など） | Should |
| D229 | **理由は符号の無い言葉で**：訪問ごとの理由（D12）は「✓ 相性◎（選ばれやすい）」「! 移動12分（やや遠い）」のように印と言葉で出し、内部の値（費用の符号つきの数）は title だけ。点数の説明に内部の費用を出さない。点を下げているいちばんの理由（D173）のすぐ後ろ（今の担当の1行の中）に**次の一手**（移動が長い→「移動を短く」で作る、入らない→受けられる人を見る、相性△→相性の表を開く） | Should |
| D233 | **条件の重みの画面＝AI で担当を組むときの重み（点数の基準）を決める画面**（ADR-0035・ADR-0100）：メニュー「組む」の子（D355）とパレットから開く。見出しの下に「AI で担当を組むとき（予定を入れたときの自動の組み・担当を組む）に、どの条件を重く見るかを決めます。保存すると次に組むときから使います」。並びは 重みの表（上に基準のプリセットの名前と［値を入れる：〈プリセット名〉］。D286）→ 考え方（プリセット）の管理（畳む。D235）→ 詳細設定。名前・種類は条件、重み・必須は点数の基準のプリセットの型のもの（同じ型の条件は同じ重み）。担当を組む・自動の組み・初期データの検査・画面の点数はこの重み。重みを保存しても今の担当は変わらず、次に組むときから使う（伝えるのは保存の確認の本文。ADR-0088） | Must |
| D235 | 条件の重みの「考え方（プリセット）の管理」（表の下の畳んだ節 `details`。読み直すと畳む）：プリセットの一覧1つで、各行の左の丸で点数の基準に選ぶ（別のラジオの並び・行の「点数の基準」の札は置かない。ADR-0088）。重み・必須は読み取り専用（行を開くと型ごとの一覧。点数の基準のプリセットは上の重みの表と同じなので一覧を出さず「重み・必須は上の条件の表のとおり」）。名前・一言の編集・消す（初期の3つと最後の1つは不可）・点数の基準に選ぶ だけ（初期の3つは変わらないので、戻すときはそれを点数の基準に選ぶ）。説明（ⓘ）は節の見出しの1つで「丸で選んだプリセットが点数の基準（ふだんの考え方）。担当を組むと点数に使う。上の表で直して保存すると「調整した重み」に書き、それを点数の基準にする」。用語「点数の基準」の説明も同じ考え方 | Should |
| D271 | **条件の名前は文字で出す**（ADR-0044）：ふだんは文字、［名前を変える］で入力欄（Enter・欄を離れると決め、Esc で取り消す。空なら型の名前）。必須の条件を消す確認の本文は「必須の条件です。消すと「守らなければ担当にしない」決まりが無くなり、合わない人にも担当が入ることがあります。」 | Should |
| D286 | **重みの表は下書きにして保存**（ADR-0048・ADR-0100）：重みのスライダー・必須の切り替えは画面の中の下書きに置く。表の上の［値を入れる：〈プリセット名〉］（今の基準以外のプリセット）を押すと、そのプリセットの重み・必須を下書きに入れる（保存はしない）。保存済みと違う行は左に注意の色の帯と淡い地、「変更あり 3→2.5」の印。下書きがある間だけ画面の下（下のタブの上）に貼り付く帯に主ボタン「保存（N件）」と文字のボタン「取り消す」（「条件を追加」は枠）。保存は確認（「重みを保存しますか？（N件）」。名前の欄は無い）で、変わる条件と重み（前→後）・次に組むときから使う・今の担当は変わらず組み直すなら担当を組むで提案を出す、を出し、保存で「調整した重み」（1つだけ。無ければ足し、あれば重みだけ上書き）に書いて点数の基準にしトースト「重みを保存しました。次に組むときから使います」。ほかのプリセットは変えない。調整した重みがまだ無くプリセットが6つなら保存できず、使わない考え方を消すよう出す。取り消すは確認なしで捨てる。下書きは型ごとに触った欄（重み・必須）だけを持ち、保存済みに重ねて出す（別のタブで変わった触っていない欄を上書きしない）。確認の間に別のタブで点数の基準が替わったら保存しない。下書きのまま画面を離れる（アプリの中のリンク・パレット）と確認（「捨てて移る」／「編集を続ける」）、再読込・タブを閉じるはブラウザの確認。ブラウザの戻るは止めない。点数の基準を替える・基準のプリセットを消すと下書きを捨てる（基準のラジオは確認「点数の基準を「〈名前〉」に替えますか？」（「捨てて替える」／「編集を続ける」））。条件を消して型が無くなる・保存済みと同じ値に戻ると、その型の下書きは消える。名前・条件を足す・消す・プリセットの管理・乱数の種はすぐ保存 | Should |
| D453 | **続く訪問は同じ人**（ADR-0116）：同じ〈利用者さん〉の同じ日の訪問で、前の訪問の終わりから次の開始（開始（早））まで 0〜30分のもの（サービスの内容で時間を分けた訪問）を組にし、同じ〈スタッフ〉が続けて回らない（担当が違う・間に別の訪問を挟む・どちらかが担当なし）組1つにつき 重み×10点。重なる訪問（2人で入る）は組にしない。続く先は1つの訪問につき1組だけ（同じ時刻の印の無い2件のあとに続く訪問があっても、組は1つ。減点が残り続けない）。組み込みの条件で、データにいつも1つある（初期データに入れ、無い古いデータ・ブックは読み込みで最後に足す）。消せず、足す種類にも出さない（使わないときは重み0）。必須にはできない。重みは初期のプリセット バランス2・移動を短く2・人の組み合わせ重視3、重みの無い古いプリセットは2 | Should |
| D454 | 続く訪問（D453）は採点（合計点・点数）・条件ごとの達成（組の数のうち同じ人が続けて回る組）・案の比較の条件ごとの点・減点の内訳（「続く訪問が別の人」）・点を下げているいちばんの理由（「続く訪問が別の人（N組）」）に入る。採点・達成のキーは続く訪問の条件の ID（ID の衝突で別の ID になってもずれない）。AI の提案と画面の採点は同じ点 | Should |
| D455 | **夕方は自宅に近い人**（ADR-0116）：開始（早）が 17:00 以降の訪問で、その訪問から担当の自宅までの移動1分につき 重み×0.2点（割当費用）。訪問ごとの理由に「夕方：自宅まで N分」。条件ごとの達成は、夕方の訪問のうち自宅までの移動が15分以内の訪問を数える。条件の重みの画面の「条件を追加」で足す（初期データには無く、足すまで今までと同じ）。足したときの重みは点数の基準のプリセットのもの（初期のプリセット・重みの無い古いプリセットは2）。必須にはできない | Should |
| D456 | **開始時刻をずらして組む**（機能の入り切りのスイッチ。ADR-0116）：入（既定・今までの動き）は、時間に幅のある訪問を幅の中で遅らせて組み、欠勤の振り直しの「受けられる人」と「担当を変える ▾」に「N分遅らせれば入る」を出す。切ると、時間に幅のある訪問も開始（早）を約束の時刻として組み・検査し（AI は開始をずらさず、間に合わない訪問は担当なしに残す）、「N分遅らせれば入る」を探さない。空き状況の問い合わせの仮の訪問は時刻を探すので幅のまま。グループは「担当の決め方」。どのひな形でも入 | Should |
