# PRD §3 要件：空き状況・問い合わせ

共通の決まり・読み方・索引・廃止した D番号は [../prd.md](../prd.md) §3。各表は D番号の昇順。画面の細部は `docs/design.md`・`docs/design/`。

## 空き状況・問い合わせ

| ID | 要件 | 優先度 |
|---|---|---|
| D45 | **空き状況の表**（曜日×30分刻み）：その時刻から〈所要〉分の訪問を受けられる人数（勤務から訪問と移動を引いた空き。先4週の案から）。種類・所要・条件（特性）で絞る | Must |
| D46 | **問い合わせの試算**：新しい〈利用者さん〉の場所・種類・所要・希望の曜日と時間帯・週の回数・開始日から、曜日×開始時刻ごとに先4週の案へ移動込みで入るか（○ すべての週・△ 入らない週あり（日付）・× 入らない）と入れられる人。案は変えない（ほかを動かさず空き時間に入れて判定）。要約（「火・木の 10:00〜11:30 なら対応できます」）をコピー | Must |
| D47 | 試算から**仮の〈利用者さん〉と定期パターン**を登録して押さえる（相談受付・仮押さえ。本登録・取り消し） | Should |
| D67 | 期間（今週／来週／先4週）と種類で**空き枠の案内文**（事業所名入り）を作りコピー。今週・来週は日付ごと、先4週は毎週続けて受けられる曜日ごと。案の無い日は入れず画面で知らせる | Must |
| D79 | 試算の結果に希望の曜日×週のマス（行＝一番良い開始時刻と判定、マス＝その日受けられる人数） | Should |
| D184 | 空き状況の画面（`#/vacancy`）を段階で上から：1 いつ・何を（入れると 300ms 後に下を計算）→2 場所（任意。D118〜D121）→3 受けられる曜日・時間帯（見出しに「目安。移動を前後15分で見込む」か「〈場所〉への移動を含む」・要約・D79・表）→4 次の一手（要約をコピー・仮押さえ・案内文・紹介元へメール） | Should |
| D185 | 入っていない段階は畳むか要約の行に（場所ははじめ畳む。案内文・メールは4段目で畳む）。畳んでも入力は消さない。案内文は開いているときだけ計算し、計算し直すまでコピー・メールを押せない | Should |
| D186 | 主ボタンは「要約をコピー」だけ。仮押さえできないときは理由を出す | Should |
| D187 | 記号：○ どの週も受けられる（人数。目安は「約」）・△ 受けられない週がある（a/b 週）・× 受けられない・？ 案が無く数えていない（×・？は数字なし）。凡例と用語の説明 | Should |
| D204 | 右の欄の日ごとの結果に、日付ごとに「その日の案を見る」（`/plan?date=…`） | Should |
| D258 | **空き状況の答えを1枚目に**：結果の先頭に答えのカード（「受けられます：火・木 10:00〜12:00 に 3人」。週の回数に足りない・受けられない週がある・受けられない・案が無く数えられないも同じ形。時刻は開始の時刻、人数はどの週でも受けられる人数の幅）。凡例（印・色・数字の読み方）は表の上の1か所。種類を選ばないときは「指定なし」（要約の行は「種類の指定なし」）。入力（条件・場所・曜日・時間帯・案内文の期間と種類）はタブの間だけ覚える（sessionStorage。画面を移って戻る・読み直すと残り、閉じれば消える。データ・書き出しには入れない） | Should |
