# PRD §3 要件：最初の2問・決まった予定・情報量・顧客台帳

共通の決まり・読み方・索引・廃止した D番号は [../prd.md](../prd.md) §3。各表は D番号の昇順。画面の細部は `docs/design.md`・`docs/design/`。試作は `docs/prototype/simple-flow.html`。

## 最初の2問・型ごとのデータ（ADR-0073）

| ID | 要件 | 優先度 |
|---|---|---|
| D379 | **最初の2問**：保存データが無く初めて開いたとき、1画面で 問1（デモで試す／自分のデータで始める）と 問2（単発の予約が中心（例：ベビーシッター）／定期の訪問が中心（例：訪問介護・看護、家事代行の定期））を聞き、主ボタン「はじめる」で始める。決まるもの：呼び名（単発＝お客様／シッター、定期＝利用者さん／スタッフ）・最初に開く画面（単発＝週の予定、定期＝月の予定）・ひな形（単発＝「単発のみ」、定期＝「基本」。エキスパート機能は切）。ツアーの「どこまで使いますか」（D276）はこれで置き換える | Must |
| D380 | **型ごとのデモデータ**：デモで試すなら、定期は今の初期データ、単発は架空の単発の予約（今日から2週間分）とお客様・シッターのデータで始める。同梱は架空のデータだけ | Must |
| D381 | **自分のデータで始める・やり直す**：空のデータ（訪問の種類と呼び名だけ）で始め、1画面1項目の3段（①〈利用者さん〉②〈スタッフ〉③予定。上に「1/3」）で登録を案内する。①②は「CSV・Excel を読み込む」と「1人ずつ入れる」。設定（管理者設定の下）に「最初の設定をやり直す」（確認のあと2問へ戻り、データを作り直す。元に戻すの対象外なので先に控えを書き出す案内） | Must |

## 決まった予定（ADR-0073）

| ID | 要件 | 優先度 |
|---|---|---|
| D382 | **確定の段階を無くす**（エキスパート機能が切のとき）：自動で組んだ日・手で直した日は、今日から1か月先まで決まった（伝えた）扱いにする（自動で記録。確定のボタンは出さない）。決まったあとの変更は訪問に「変更あり」の印、押すと連絡の一覧（未連絡の変更）。メールで送る・予約するときの伝えた記録は今どおり。エキスパート機能が入なら今の確定（伝えた）の操作も出す | Must |

## 画面と情報量（ADR-0073）

| ID | 要件 | 優先度 |
|---|---|---|
| D383 | **メニューは4つ**（エキスパート機能が切のとき）：予定・〈利用者さん〉・〈スタッフ〉・設定。ホームは無くし、予定の画面の上に要対応の帯1本（担当なし・重なり・休みの人。無ければ出さない）。空き状況は予定の「その他 ▾」から。エキスパート機能が入なら今のメニュー | Must |
| D384 | **例外だけ見せる**：正常な訪問の札は時刻・名前・担当の1行。目立たせるのは担当なし・重なり・休みの人だけ。点数・理由・移動の分数・件数の内訳・凡例・進み具合は「詳しく」の中か、エキスパート機能が入のときだけ。主ボタンは1つ、操作の行のボタンは2つまで（ほかは「その他 ▾」）。画面の上の説明は1行で、初回だけ出し閉じたら出さない。標準・提案・反映・ピン・プリセットの言葉はふだんの画面に出さない | Must |
| D385 | **人の画面は畳む**：〈利用者さん〉の詳細は 名前・住所・予定（繰り返し）を出し、相性・担当を限る・段階・決まりごとは「詳しく ▾」。〈スタッフ〉は 名前・勤務日・勤務時間を出し、資格・特性・勤務の見込みは「詳しく ▾」。一覧の列も同じ。日の予定の地図はボタンで開く | Should |
| D388 | **月・週の主ボタンは「予定を入れる」**（エキスパート機能が切のとき。入は今のまま）：月・週の操作の行の主ボタンを「予定を入れる」にし、押すと引き出しで〈利用者さん〉を選んで入れる。定期（繰り返しを使う）は 曜日・くり返し・時刻・所要（〈利用者さん〉の繰り返しを足す）、単発は 日付・時刻・所要（その日の訪問を足す）→「入れる」。入れたら担当なしの分は自動で組む（D372）。操作の行は主ボタン1つ＋「欠勤・キャンセルを登録」（当日の変更のほかの入口が無い）。「担当なしの訪問を組む N件」は「その他 ▾」へ（担当なしは上の要対応の帯から見に行け、入れた分は自動で組むので、いつも要る操作ではない）。日の予定の主ボタンも言葉は「予定を入れる」にそろえる（切のとき。開く欄は今の訪問の欄＝種類・時間の約束・担当の候補つきのまま、欄の見出しも「予定を入れる」。入は「訪問を追加」のまま。スマホは文字を残す） | Must |
| D389 | **〈利用者さん〉・〈スタッフ〉の小さいタブ**（エキスパート機能が切のとき。入は基本情報のタブのまま）：一覧の画面の上（見出しの下）に、〈スタッフ〉＝一覧・勤務（勤務時間（シフト）・勤務の見込み）・相性、〈利用者さん〉＝一覧・相性 のタブを出し、行き先の相性・勤務の画面にも同じタブを出して行き来できる。メニューは4つのまま（D383）で、メニューの印はタブ先の画面でも〈スタッフ〉／〈利用者さん〉に付く（相性は来た側の1つ）。予定と相性（#/basics）など旧画面のタブは出さない。相性・勤務の画面にも、標準・提案・反映・ピン・プリセットの言葉と点（点数・条件の重みの話）を出さない（D384） | Should |

## 顧客台帳の CSV（ADR-0073）

| ID | 要件 | 優先度 |
|---|---|---|
| D386 | **顧客台帳の形を読む**：〈利用者さん〉の名簿の読み込みで、列名から顧客台帳の形（利用者名・利用者カナ・利用者生年月日・性別・郵便番号・都道府県・市区町村・町名以下・建物名・利用者電話番号・利用者携帯電話番号・請求方法 … 口座名義名カナ・利用者状態・備考の29列）を見分けて読む。区切りはカンマ／タブ、文字コードは UTF-8／Shift_JIS（BOM 有無・改行 CRLF／LF とも） | Must |
| D387 | **顧客台帳から読むもの**：名前（利用者名）・よみ（利用者カナ。カタカナはひらがな、空白は詰める）・郵便番号（7桁の数字で持ち、ハイフン付きで見せる）・住所（都道府県＋市区町村＋町名以下＋建物名）・電話（利用者電話番号・携帯を備考の先頭に1行）・状態（利用中＝利用中、ほか＝終了）・備考。請求・口座・生年月日・性別・続柄・顧客番号は読まず、データに残さない。突き合わせは名簿と同じ（名前）。読み込みの結果に「読まなかった列」の一覧を出す | Must |


## ほかのソフトの CSV（ADR-0075）

| ID | 要件 | 優先度 |
|---|---|---|
| D396 | **ほかのソフトの形を足せる**：名簿・予約の CSV は、1行目の列名から形を見分けて読む。形は「形の一覧」に1つずつ足す（ソフト・会社ごとに列名と写し方を書く。読み込み・突き合わせ・確認の画面は共通）。確認の文に読んだ形の名前と「読まなかった列」を出す。区切りはカンマ／タブ、文字コードは UTF-8／UTF-16／Shift_JIS（BOM 有無・改行 CRLF／LF とも） | Must |
| D397 | **予約システムのスタッフ・顧客の CSV を名簿として読む**：スタッフ（ID・氏名・住所・mail address・緯度・経度・退職日 …）は〈スタッフ〉の名簿で、名前・メール・住所・緯度経度・最終勤務日（退職日。今日より前なら休止）を読む。氏名の無い行は飛ばす。顧客（顧客ID・姓・名・姓名のカナ・電話・会員状況・住所・駐車場・緯度・経度 …）は〈利用者さん〉の名簿で、名前（姓＋名。無ければカナ。同じ名前は2人目から「名前（顧客ID）」）・よみ・郵便番号（住所の先頭の〒）・住所・緯度経度・駐車場（決まりごと）・電話（メモの先頭）・状態（無効＝終了、ほか＝利用中）を読む。TEL（スタッフ）・パスワード・管理者・性別・年代・会費・緊急連絡先・避難場所・世帯の情報・住所2 は読まず、データに残さない | Must |
| D398 | **予約の CSV を訪問として読む**：データの画面の「予約の CSV」で、予約（予約番号・予約日・予約時・所要時間・メニュー名・状況・氏名）を単発の訪問（時刻固定・担当なし・メモにメニュー名）として入れる。〈利用者さん〉は名前で突き合わせ、いない・同じ名前が2人の予約は入れずに名前と件数を出す。同じ予約番号は読み直すと直す（担当・ピンは残す）、ファイルに無い訪問は消さない。状況がキャンセルなら取り消しの訪問。新規登録者（予約を入れた人）は担当にしない。件数（追加・更新・変更なし）を見せて確かめてから入れ、直前の状態に戻せる | Must |
