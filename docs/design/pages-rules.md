### 条件の重み（`#/rules`）

考え方（プリセット）の中身と、ふだん使う考え方（点数の基準）を決める画面。組み方の標準の「2. 案をくらべる」の寄り道（`standard-rules-link`）とコマンドパレットから開く。メニューの子・予定を組むの段・設定のタブには無い（メニューの印は組み方の標準、標準があれば担当を組む）。見出しに段は出さず、右に［組み方の標準へ戻る］（`rules-back`。`/standard`。下書きがあれば「下書きのまま離れる」の確認）。

- `lead`「ふだんの考え方（点数の基準）の重みを決めます。触らなくても、初期の考え方で組めます」
- 並び：プリセットの節（行の丸で点数の基準を選ぶと下の表の重みが替わる）→ 条件の表 → 詳細設定
- 条件の表のカードの先頭に「点のしくみ」（重み1＝1件あたり移動10分ぶん・必須）、その下に基準のプリセットの名前（`rules-basis`。「点数の基準」は `Term`。「基準は上のプリセットの丸で替えられます」）。次の段の案内の文は置かない（今の担当が変わらないことと担当を組むでの反映は保存の確認の本文、組み方の標準へは見出しの［組み方の標準へ戻る］。ADR-0088）

#### 条件

- 条件ごとの行：名前（ふだんは文字 `rule-name`、文字のボタン［名前を変える］（`rule-rename`）で入力欄 `rule-name-input`。Enter・欄を離れると決め（変わっていなければ書かない）、Esc で取り消してフォーカスはボタンへ。変換中の Enter・Esc は変換のもの。空なら型の名前）・種類・重みのスライダー（0〜5）・必須の切り替え・消す。重み・必須は `scoreRulesOf(data)` に下書きを当てて出す。同じ型の条件は同じ重み。名前・足す・消すはすぐ保存（`update`）、重み・必須は下書き
- 消すときは独自の確認「条件「〈名前〉」を消しますか？」。必須の条件は本文に「必須の条件です。消すと「守らなければ担当にしない」決まりが無くなり、合わない人にも担当が入ることがあります。」
- 条件を追加するときの重み・必須は `addRule`（基準のプリセットのその型。無ければ型ごとの既定）
- 狭い画面（600px 以下）：条件の表（`narrow-rules`）は1条件1枚のカード（[pages.md](pages.md) の「狭い画面の表」）。1行目に名前と「必須」、続けて「種類」（札と説明）・「重み」（スライダーは幅いっぱい）、消すは右下
- 「詳細設定」（`rules-advanced`。`details`。読み直すと畳む）：乱数の種（`Term` `seed`）

#### 重み・必須の下書き（`lib/weightDraft`）

- スライダー・必須は保存せず画面の state（型ごとに触った欄だけ。基準のプリセットの id と組）に置き、保存済みに重ねて出す（別のタブで変わった触っていない欄はその値で出し、確定でも上書きしない）。保存済みと同じ値に戻した欄・型は外す
- 違う行（`is-draft`・`data-draft`）：左に注意の帯（`--warn-line`）と淡い地（`#fffaf0`。狭い画面はカードの枠と帯）、重みの欄に「変更あり 3→2.5」（`rules-draft-mark`。`changeText`。0 は「0（使わない）」、重みを使わない必須は「必須」）
- 確定の帯（`rules-draft-bar`。下書きがある間だけ。画面の最後に `position: sticky; bottom: calc(var(--bottom-tabs-h) + 8px)`。390px はボタンを同じ幅で1行。印刷では出さない）：「変更あり」の札と「重みの変更は、確定するまで保存しません」、文字のボタン「取り消す」（`rules-draft-discard`）と主ボタン「新しい考え方として保存（N件）」（`rules-draft-confirm`。N は変わった型の数）。帯の文「プリセットは書き換えません。保存すると新しい考え方として足し、ふだんの考え方（点数の基準）にします」。プリセットが6つなら主ボタンは `aria-disabled`、帯に「プリセットは6つまでです。使わない考え方を上の節で消してから保存してください」（`rules-draft-full`）
- 保存：独自の確認（見出し「新しい考え方として保存しますか？（N件）」、確定「保存する」・取り消し「編集を続ける」）。本文に名前の欄（`rules-draft-name`。既定「〈元の名前〉（改）」、重なれば「（改2）」…。空・重なる・長すぎは `addPresetError` の文で保存できない）と `confirmBody`：「変わる条件：」「・〈名前〉：前→後」、「「〈元の名前〉」はそのまま残ります。新しい考え方を点数の基準にし、AI で組む・点数・要対応の検査に使います。」「今の担当は変わりません。組み直したいときは、「担当を組む」の画面の「AI で組む」で提案を出して反映します。」。`update(d => saveDraftAsPreset(d, 下書き, 名前))`（基準の保存済みの重みに触った欄を重ねたプリセットを足し、`setScorePreset` で基準にする。確認の間に別のタブで基準が替わっていたら書かず「点数の基準が替わったので、保存しませんでした」、6つに達していたら書かず「プリセットが6つになったので、保存しませんでした。使わない考え方を消してから保存してください」）。知らせ「「〈名前〉」を保存して、ふだんの考え方にしました」。保存・取り消しのあとフォーカスは画面の見出し
- 取り消す：確認なしで捨て、知らせ「重みの変更を取り消しました」
- 下書きのまま離れる（`components/useLeaveGuard`・`lib/leaveGuard`）：アプリの中の別の画面へのリンク（メニュー・下のタブ・［組み方の標準へ戻る］・帯のリンク）は捕捉の段で止めて独自の確認（`leaveDialog`：「重みの変更を捨てて、画面を移りますか？」「確定していない重みの変更（N件）があります。移ると捨てます。」「捨てて移る」（危険の色）／「編集を続ける」）。確定なら同じリンクを押し直す。コマンドパレット・案内ツアーの「今日の予定を開く」・担当を組むの終わった知らせの［担当を組むを開く］・訪問の詳細の欄の「日の予定で見る」も移る前に `confirmLeave`。再読込・タブを閉じるは beforeunload。ブラウザの戻るは止めない。下書きがある間は別のタブの変更の知らせを「保存すると上書きします」の側にする（`useDirtyMark`）
- 整合：点数の基準を替える・基準のプリセットを消すと下書きを捨てる（下書きがあれば基準のラジオは確認「点数の基準を「〈名前〉」に替えますか？」「確定していない重みの変更（N件）は捨てます。」「捨てて替える」（危険の色）／「編集を続ける」。消すの確認の本文にも「確定していない重みの変更（N件）は捨てます。」）。条件が無くなった型・保存済みが同じ値になった型は外す（`pruneDraft`）。足した条件はその型の下書きの値で出る

#### プリセットの節（`preset-section`。条件の表の上）

- プリセットの一覧は1つ（`fieldset.preset-list`・`score-ruler-choice`。legend「左の丸で点数の基準（ふだんの考え方）を選びます」）。行（`.preset-row`）は左に点数の基準の丸（`score-ruler-radio`。`name="score-preset"`・読み上げ「「〈名前〉」を点数の基準にする」）と、畳める中身（`details.preset-edit`）。別のラジオの並び・行の「点数の基準」の札は置かない（ADR-0088）

- プリセットの重み・必須は変えられない（変えるのは下の表の「新しい考え方として保存」）。節でできるのは、名前・一言の編集（`preset-edit`。すぐ保存）・型ごとの重み・必須の読み取り専用の一覧（`preset-weights`。点数の基準のプリセットは下の条件の表と同じなので出さず、文 `preset-weights-basis`「重み・必須は下の条件の表のとおりです（点数の基準）。」）・消す・点数の基準に選ぶ だけ。初期に戻す操作は無い
- 消す（`preset-remove`。独自の確認）：初期の3つ（バランス・移動を短く・人の組み合わせ重視。`seed/presets` の id。`isInitialPreset`）と最後の1つは消せない（ボタンを出さず、初期の3つは見出しに「初期」の札）。基準のプリセットを消すと基準は残りの先頭へ移り、確認の文に出す
- 行の丸で1つ選ぶ（`data.rules` も新しい基準にそろえる。組み方の標準の表は変わらない）
- 狭い画面：見出し（`narrow-preset-summary`）の名前は1行（入らなければ「…」）、一言は次の行。重みの一覧もカード
- 説明（節の見出しの ⓘ の1つだけ）：丸で選んだプリセットが点数の基準（ふだんの考え方）。担当を組む・訪問ごとの検査・画面の点数（100点満点）はこの重み・必須で計算する。プリセットの重み・必須は変えられず、下の表は点数の基準の重みから始め、変えると新しいプリセットとして保存する。組み方の標準の「案をくらべる」はすべてのプリセットで案を作り、案から作った表を登録するとそのプリセットが点数の基準になる。6つまで・名前と一言はすぐ保存・初期の3つは消せない
- `rules` が切ならこの画面は開けず、作るときは点数の基準のプリセットの重み（`scoreRulesOf`）

### 特性と条件の入力（`components/conditions.tsx`）

- 特性のあり/なしは「未確認・あり・なし」
- 開始年は西暦の欄（1900〜2100 の整数。読めない文字は欄に残して値は null にし、誤りの文。判定は契約の `isStartYear`）と「年から（N年）」（今日の年までの年数）。条件は数値と同じ下限・上限の欄で、単位は「年以上」「年以下」
- 特性の表示（一覧のチップ・人の画面）は `lib/compatView` の `traitText`。開始年は「8年（2018年から）」
- 条件は相手の項目ごとの1行のチェック表。何も選ばない項目は問わない
- あり/なしの条件の「なし」は `is false`（未確認の相手は満たさない）。`not` は画面からは作らない（データにあれば「そのほかの条件」に出して消せる）
- 保存の形は `Condition[]`
- 使う所：人の画面の「求めること」の節・訪問の種類の担当に必要な条件・空き状況の〈スタッフ〉の条件

### 訪問の種類（`#/types`）

- `lead`「訪問の種類（介護・リハビリなど）と、担当する〈スタッフ〉に必要な条件を決めます」
- 一覧（`types-table`）：色の丸・名前・標準の所要・担当に必要な条件の文・使っている訪問とパターンの数
- 足す・直す：名前 1〜20字・色 0〜7・標準の所要 5〜720分・担当に必要な条件（`components/conditions.tsx`）・メモ。20を超えては足せない
- 消す：「〈名前〉を使っている訪問 N件・定期パターン M件は種類なしになります」の確認。`typeId` を null にする

### 特性の項目（`#/items`）

- `lead`「〈スタッフ〉や〈利用者さん〉の特性（資格・ペットなど）を決めます」
- 項目（型：choice・multi・flag・number など）と選択肢を足す・直す・消す（選択肢を消すときは独自の確認）。項目「資格」の選択肢は週の資格のチップ・バッジに使う
- 狭い画面：項目の表は1項目1枚のカード。1行目に名前の入力欄、続けて「種類」・「選択肢（人数）」（見出しを上、一覧と足す欄は幅いっぱい。`narrow-block`）・「使っている条件」、消すは右下

### 提案を比べる（`#/compare`）

- 担当を組むの「案を比べる」（`/compare?date=`。選んでいる日付をその日にする。日は上の帯の日付で選び直す）から開く。担当を組むからの寄り道なので予定を組むの段は出さない（条件の重みと同じ。ADR-0088。メニューの印は担当を組む）。見出し「提案を比べる」。`lead`「今の担当と、考え方（プリセット）ごとに作った提案を2つ選んで比べます。提案は保存しません。よければ「反映する」」。右に「担当を組むに戻る（〈日〉）」（`compare-back`。`/arrange?date=`）
- 比べる担当（`choices`）：欠勤前（`reassigns[date].baseRoutes`。振り直しを反映した日だけ）・今の担当・担当を組むの提案のその日の分（`monthBatch.proposal`。「〈名前〉の提案（担当を組む）」。反映する・捨てると消える。この画面で消すと隠す）・この画面で作った提案（`proposals`。日付を変える・読み直すと消える）。A・B を選ぶ（同じものを選ぶと入れ替え）
- 合計点・移動・待ち・距離・入らなかった訪問・必須の違反、条件ごとの達成/違反（`scoreRulesOf` で採点）。合計点の下に点数の理由（`compare-reason`）
- 担当ごとの順番の左右比較・地図（A：点線、B：実線。線は担当の色）・入らなかった訪問の一覧
- 提案の行：「反映する」（`compare-apply`。`writeRoutes`。作ったあとに訪問が変わっていれば古い印 `compare-stale` で、反映せずに知らせる）・消す（ゴミ箱）
- 提案を作る（`compare-another`）：考え方の select（`compare-another-select`。すべてのプリセット）・主ボタン「提案を作って比べる」（`compare-another-make`）。点数の基準の重みにプリセットを当てた条件で compile し（ピンを渡す）`runSolve`。進み具合と［止める］。画面を離れる・日付を変えると止めて捨てる。計算できる訪問が無ければ理由（`compare-another-why`）
- 狭い画面：表は1つを1枚のカード。印刷では提案を作る欄を出さない
- 空（`compare-empty`。`compareEmptyGuide`：「この日には訪問がありません」と［日の予定で訪問を追加］）
