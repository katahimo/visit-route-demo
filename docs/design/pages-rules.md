### 条件の重み（`#/rules`）

考え方（プリセット）の中身と、ふだん使う考え方（点数の基準）を決める画面（ADR-0035・ADR-0065。PRD D233）。メニューの「予定を組む」の子の1つ目（予定を組むの3段：条件の重み → 組み方の標準 → 担当を組む。PRD D359）。見出しの下に予定を組むのタブ（`ArrangeTabs`）。設定のタブには無い。`lead`「ふだんの考え方（点数の基準）の重みを決めます。担当を組むはこの重みで組み、組み方の標準ではプリセットごとに案を作ってくらべます」。「点のしくみ」の説明（重み1＝1件あたり移動10分ぶん・必須）、その下に直している基準のプリセットの名前（`rules-basis`。「点数の基準」は `Term`）と、次の段の案内（`rules-next-note`）「重みを変えても今の担当は変わりません。標準の週を見直すなら「組み方の標準」で案を作り直し、標準で埋まらない所は「担当を組む」で提案を出して反映します」（どちらもリンク）

#### 条件

- 条件ごとの行：名前（`data.rules` の名前。ふだんは文字（`rule-name`）で、文字のボタン［名前を変える］（`rule-rename`）で入力欄（`rule-name-input`。Enter・欄を離れると決め（名前が変わっていなければ書かない）、Esc で取り消してフォーカスはボタンへ。変換中の Enter・Esc は変換のもの。空なら型の名前）。PRD D271）・種類・重みのスライダー（0〜5）・必須の切り替え・消す。重み・必須は `scoreRulesOf(data)`（基準のプリセットの型の重み）に下書きを当てて出す。同じ型の条件は同じ重みになる。名前・足す・消すはすぐ保存（`update`）、重み・必須は下書き（次の節）
- 消すときは独自の確認（「条件「〈名前〉」を消しますか？」）。必須の条件は本文に「必須の条件です。消すと「守らなければ担当にしない」決まりが無くなり、合わない人にも担当が入ることがあります。」（PRD D271）
- 重み・必須の下書き（PRD D286。ADR-0048。`lib/weightDraft`）：スライダー・必須の切り替えは保存せず画面の state（型ごとに触った欄（重み・必須）だけ。直している基準のプリセットの id と組）に置き、保存済みに重ねて出す（別のタブで変わった触っていない欄はその値で出し、確定でも上書きしない）。保存済みと同じ値に戻した欄・型は下書きから外れる
  - 違う行（`is-draft`・`data-draft`）：左に注意の帯（`--warn-line`）と淡い地（`#fffaf0`。狭い画面はカードの枠と帯）、重みの欄に印「変更あり 3→2.5」（`rules-draft-mark`。`changeText`。0 は「0（使わない）」、重みを使わない必須は「必須」）
  - 確定の帯（`rules-draft-bar`。下書きがある間だけ。画面の最後に置き `position: sticky; bottom: calc(var(--bottom-tabs-h) + 8px)` で巻いても見える。390px はボタンを横に同じ幅で1行。印刷では出さない）：「変更あり」の札と「重みの変更は、確定するまで保存しません」、文字のボタン「取り消す」（`rules-draft-discard`）と主ボタン「新しい考え方として保存（N件）」（`rules-draft-confirm`。N は変わった型の数）。帯の文は「プリセットは書き換えません。保存すると新しい考え方として足し、ふだんの考え方（点数の基準）にします」。プリセットが6つあるときは主ボタンを押せず（`aria-disabled`）、帯に「プリセットは6つまでです。使わない考え方を下の節で消してから保存してください」（`rules-draft-full`）
  - 保存（ADR-0065）：独自の確認（見出し「新しい考え方として保存しますか？（N件）」、確定「保存する」・取り消し「編集を続ける」）。本文に名前の欄（`rules-draft-name`。既定は「〈元の名前〉（改）」、同じ名前があれば「（改2）」…。空・重なる名前・長すぎは `addPresetError` の文で保存できない）と `confirmBody`：「変わる条件：」と「・〈名前〉：前→後」、「「〈元の名前〉」はそのまま残ります。新しい考え方を点数の基準にし、AI で組む・点数・要対応の検査に使います。」「今の担当は変わりません。組み直したいときは、「担当を組む」の画面の「AI で組む」で提案を出して反映します。」。保存で `update(d => saveDraftAsPreset(d, 下書き, 名前))`（d の点数の基準の保存済みの重みに触った欄を重ねたプリセットを足し、`setScorePreset` で基準にする。確認の間に別のタブで点数の基準が替わっていたら書かず「点数の基準が替わったので、保存しませんでした」。6つに達していたら書かず同じ文）と知らせ「「〈名前〉」を保存して、ふだんの考え方にしました」。保存・取り消しのあとフォーカスは画面の見出し
  - 取り消す：確認なしで下書きを捨て、知らせ「重みの変更を取り消しました」
  - 下書きのまま離れる（`components/useLeaveGuard`・`lib/leaveGuard`）：アプリの中の別の画面へのリンク（`#/…`。メニュー・下のタブ・予定を組むのタブ・帯のリンク）は捕捉の段で止めて独自の確認（`leaveDialog`：「重みの変更を捨てて、画面を移りますか？」「確定していない重みの変更（N件）があります。移ると捨てます。」「捨てて移る」（危険の色）／「編集を続ける」）。確定なら同じリンクを押し直す。コマンドパレットも移る前に確かめる。再読込・タブを閉じるは beforeunload。ブラウザの戻るは止めない（ADR-0052 と同じ）。下書きがある間は別のタブの変更の知らせを「保存すると上書きします」の側にする（`useDirtyMark`）
  - 整合：点数の基準を替える・基準のプリセットを消すと下書きを捨てる（下書きがあれば、基準のラジオは独自の確認「点数の基準を「〈名前〉」に替えますか？」「確定していない重みの変更（N件）は捨てます。」「捨てて替える」（危険の色）／「編集を続ける」で、断れば替えない。消すの確認の本文にも「確定していない重みの変更（N件）は捨てます。」）。案内ツアーの「今日の予定を開く」も移る前に `confirmLeave` で確かめる。条件を消して型の条件が無くなった型・プリセットの節で保存済みが同じ値になった型は外す（`pruneDraft`）。足した条件はその型の下書きの値で出る
- 条件を足すときの重み・必須は `addRule`（押した時点のデータで、基準のプリセットのその型。プリセットが無ければ型ごとの既定）
- 狭い画面（600px 以下。PRD D220）：条件の表（`narrow-rules`）は1つの条件を1枚のカードに（[pages.md](pages.md) の「狭い画面の表」）。1行目に名前（文字と［名前を変える］）と「必須」の切り替え、続けて「種類」（札と説明）・「重み」（スライダーは幅いっぱい）、消すは右下。スライダーと必須は横に巻かずに見える
- 「詳細設定」（`rules-advanced`。`details` で畳み、読み直すと畳む）：乱数の種（`Term` `seed`）

#### プリセットの節（`preset-section`。ADR-0008・ADR-0065）

- プリセットの重み・必須は変えられない（ADR-0065）。重みを変えると上の表の「新しい考え方として保存」で別のプリセットになる。この節はプリセットごとに、名前・一言の編集（`preset-edit`。変えるとすぐ保存。重みは変わらないので点・標準に影響しない）・型ごとの重み・必須の読み取り専用の一覧（`preset-weights`）・消す・点数の基準に選ぶ だけ
- 消す（`preset-remove`。独自の確認）：初期の3つ（バランス・移動を短く・人の組み合わせ重視。`seed/presets` の id。`isInitialPreset`）と最後の1つは消せない（ボタンを出さず、初期の3つは見出しに「初期」の札）。基準のプリセットを消すと基準はバランスへ移り、確認の文に出す
- 狭い画面（PRD D220）：見出し（`narrow-preset-summary`）の名前は1行（入らなければ「…」）、一言は次の行。重みの一覧もカード（1行目に条件の種類と必須、続けて重み）
- 見出しの印：基準のプリセットに「点数の基準」
- 初期に戻す操作は無い（初期の3つは変わらないので、戻すときはそのプリセットを点数の基準に選ぶ）。「基準の重みを写して保存」も無い（表で直して保存するのと同じになるため）
- 「点数の基準」のラジオ（`score-ruler-choice`。ADR-0010）でプリセットを1つ選ぶ（替えると `data.rules` も新しい基準にそろえる。ADR-0035。組み方の標準の表は変わらない）。基準のプリセットを消すと残りの先頭に移り、確認の文に出す
- 説明：ここで選んだプリセットがふだんの考え方。担当を組む・訪問ごとの検査はこの重み・必須で計算し、画面の点数（100点満点）もこれで付ける。上の表はこのプリセットの重みから始め、変えると新しいプリセットとして保存する。組み方の標準の「案をくらべる」はすべてのプリセットで案を作り、案から作った表を登録するとそのプリセットが点数の基準になる
- `rules` を切ると、この画面は開けず、作るときは点数の基準のプリセットの重みを使う（`planRulesOf`）

### 特性と条件の入力（`components/conditions.tsx`。ADR-0002）

- 特性のあり/なしは「未確認・あり・なし」
- 条件は相手の項目ごとの1行のチェック表で、何も選ばない項目は問わない
- あり/なしの条件の「なし」は `is false`（未確認の相手は満たさない＝安全側）。`not` は画面からは作らない（前からある `not` は「そのほかの条件」に出して消せる）
- 保存の形は `Condition[]` のまま
- 使う所：〈スタッフ〉・〈利用者さん〉の画面の「求めること」の節・訪問の種類の担当に必要な条件・空き状況の〈スタッフ〉の条件

### 訪問の種類（`#/types`。ADR-0012。PRD D36）

- `lead`「訪問の種類（介護・リハビリなど）と、担当する〈スタッフ〉に必要な条件を決めます」
- 種類の一覧（`types-table`）：色の丸・名前・標準の所要・担当に必要な条件の文・使っている訪問とパターンの数
- 足す・直す：名前 1〜20字・色 0〜7・標準の所要 5〜720分・担当に必要な条件（〈スタッフ〉の項目ごとの1行のチェック表＝`components/conditions.tsx`）・メモ。20を超えては足せない
- 消す：「〈名前〉を使っている訪問 N件・定期パターン M件は種類なしになります」の確認。消すと `typeId` を null にする

### 特性の項目（`#/items`）

- `lead`「〈スタッフ〉や〈利用者さん〉の特性（資格・ペットなど）を決めます」
- 項目（型：choice・multi・flag・number など）と選択肢を足す・直す・消す（選択肢を消すときは独自の確認）。項目「資格」の選択肢は週の資格のチップ・バッジに使う
- 狭い画面（PRD D220）：〈スタッフ〉・〈利用者さん〉の項目の表は1つの項目を1枚のカードに。1行目に名前の入力欄、続けて「種類」・「選択肢（人数）」（見出しを上に置き、選択肢の一覧と足す欄は幅いっぱい。`narrow-block`）・「使っている条件」、消すは右下

### 提案を比べる（`#/compare`。ADR-0005・ADR-0010・ADR-0053。PRD D317）

- 担当を組むの画面の「案を比べる」（`/compare?date=`。`?date=` があれば選んでいる日付をその日にする）から開く。見出しの下に予定を組むのタブ（`ArrangeTabs`。印は担当を組む）。見出し「提案を比べる」。`lead`「今の担当と、考え方（プリセット）ごとに作った提案を2つ選んで比べます。提案は保存しません。よければ「反映する」」。見出しの右に「担当を組むに戻る（〈日〉）」（`compare-back`。`/arrange?date=`）

#### 中身

- 比べる担当（`choices`）：欠勤前（`reassigns[date].baseRoutes`。振り直しを反映した日だけ）・今の担当（保存している担当）・担当を組むで出した提案のその日の分（`monthBatch.proposal`。「〈名前〉の提案（担当を組む）」。担当を組むで反映する・捨てると消える。この画面で消すと隠す）・この画面で作った提案（`proposals`。日付を変える・読み直すと消える）。A・B を選んで比べる（A と B に同じものを選ぶと入れ替え）
- 合計点・移動・待ち・距離・入らなかった訪問・必須の違反、条件ごとの達成/違反（点数の基準の物差し `scoreRulesOf` で採点）。表の合計点の下に点数の理由（`compare-reason`）
- 担当ごとの順番の左右比較・地図（A：点線、B：実線。線は担当の色）・入らなかった訪問の一覧
- 提案の行：「反映する」（`compare-apply`。`writeRoutes` で今の担当にする。作ったあとに訪問が変わっていれば古い印 `compare-stale` で、反映せずに知らせる）・消す（ゴミ箱）
- 提案を作る（`compare-another`）：考え方の select（`compare-another-select`。すべてのプリセット）・主ボタン「提案を作って比べる」（`compare-another-make`）。点数の基準の重みにプリセットを当てた条件で compile し（ピンを渡す）`runSolve`。進み具合と［止める］。画面を離れたら・日付を変えたら止めて捨てる。計算できる訪問が無いときは理由（`compare-another-why`）
- 狭い画面（PRD D220）：表は1つを1枚のカードに。印刷では提案を作る欄を出さない
- 空の画面（`compare-empty`。`compareEmptyGuide`：「この日には訪問がありません」と［日の予定で訪問を足す］）
