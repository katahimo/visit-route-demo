# e2e（本物のブラウザ）の走らせ方・書き方・確かめること

AGENTS.md「コマンド」から引く詳細。e2e を走らせる・足す・直すときだけ読む。決めた理由は ADR-0029・ADR-0041。

## 走らせ方

e2e（本物のブラウザ。ADR-0029）：`npm run e2e`（速さを見る5本を除く残りを4本ずつ並列）・`npm run e2e:perf`（速さを見る5本を1本ずつ）・`npm run e2e:all`（e2e のあとに e2e:perf。同時には走らせない）。1本だけは `npx playwright test --grep <スクリプトの名前>`（例 `--grep "e2e-details\.cjs"`。部分一致なので `e2e-details` だけでは e2e-details2 も走る）。サイトは webServer がビルドして `vite preview --port 4183` で出す。4183 で動いている配信があればビルドせずにそれを使い回すので、古いビルドの配信が残っていれば止めるか、確かめたい配信を `BASE=http://localhost:4183/` で渡す。報告は `npx playwright show-report`（落ちた test に記録が付き、`NG  ` の行が見える）。`playwright-report/` と `test-results/` は実行のたびに上書きされるので、`npm run e2e` のあと `npm run e2e:perf`（`e2e:all` も同じ）を走らせると残るのは perf の報告だけ。e2e の報告を見るなら e2e:perf の前に開く。`node scripts/e2e-xxx.cjs` で1本ずつ単独でも今どおり走る（先に `npm run build && npx vite preview --port 4183`）

## 書き方

e2e の書き方（段階2。ADR-0041）：スクリプトは段（`[名前, 関数]` の並び）を `module.exports = { steps }` で出し、末尾に `if (require.main === module) runSteps(steps)`。段の型は `scripts/lib/steps.cjs` の `sharedPage`（1つのページを使い回す）・`pagePerStep`（段ごとに新しい文脈）・`guard`。包みは段を `test.step`、`check` を `expect.soft`（名前はそのまま）に写すので、段を足すときは並びに1行足すだけ。押したあとの待ちは `settle(page, ms)`（描画・DOM の変化・終わりのある CSS の動き・期限の近いタイマーが落ち着くまで。最長 max(3×ms, 1500ms)）か目印（`locator.waitFor`・`until(fn)`）で待ち、`waitForTimeout` は速さの計測・外の遅れ・時間そのものを見る所だけ（前の行に理由と「固定の待ち」と書く）。`E2E_SETTLE_LOG=1` で落ち着かずに最長まで待った所を、`=2` で1回ずつの待った時間を出す（`E2E_SETTLE=fixed` で前の固定の待ちに戻して切り分け）。1つの段は最長3分（`E2E_STEP_TIMEOUT_MS`）。保存した担当の入った訪問を用意する `planDays`（`scripts/lib/plan.cjs`。AI で組むので重い）は、初期データ（localStorage を消した直後・新しい文脈）から組む所なら `{ cache: true }` を付ける（2回目からは結果の写し。包みの中では `E2E_PLAN_CACHE_DIR`＝`test-results/.plan-cache` で同じ実行のスクリプトと分け合う。画面の手順そのものは e2e-arrange が確かめる）。落ちた test には trace・動画（perf は取らない）・`-fail-` のスクリーンショット・記録が付く（`npx playwright show-report`・`npx playwright show-trace`）

### 画面の位置を知る共通の手（`scripts/lib/ui.cjs`。ADR-0074 段0）

エキスパート機能が入の画面は、段1〜5 でメニュー・操作の行・「詳しく ▾」が切の作りに寄っていく（段1で入のメニューは 予定・〈利用者さん〉・〈スタッフ〉・組む・設定 の5つになりホームは無くなった。`#/home` は予定へ移る。段2で予定の操作の行は入切とも「予定を入れる」＋1つ（入は月・週が「担当を組む」、日が「確定（伝えた）」、切は欠勤・キャンセル）と「その他 ▾」になり、元に戻す・欠勤（入）・表示の切り替え・使い方・メールで送るは「その他 ▾」の中、点数・進み具合・凡例・1行の状態は「詳しく ▾」の中。「詳しく ▾」の開け閉めは月・週・日の画面ごとに端末に覚える）。画面の位置（どのボタンがどこにあるか）を e2e の中に直に書かず、次の手を使う。位置が変わったら `ui.cjs` の表（`SCREENS`・`MENU_KEYS`・`TOOLS`）だけを直す。データを書き換えて読み直すだけの出発点には、軽いデータの画面（`#/data`）を使う（ホームは無い）。

- `goTo(page, 行き先, { ready, timeout, h1, settleMs })`：URL で画面へ行く（about:blank を挟む）。行き先は名前（`月`・`週`・`日`・`利用者さん`・`スタッフ`・`設定`・`基本情報`・`組む`・`空き状況`・`欠勤` ほか（ホームは無い）。表は `SCREENS`）か `/path?query`。メニューや帯を押して移る代わり。各スクリプトの `open(page, hash, ready)` の多く（e2e-nav・mobile・dialog・links・panel-foot・person-page・view・visit-panel・words・tour・home と `lib/features.cjs`）はこれの薄い包み（待つ長さ・落ち着くまでの待ちの既定だけがスクリプトごとに違う）。`goTo` を使わない `open`（e2e-progress・details・week・arrange・features など読み直す形のもの）と、画面ごとの `open1`（e2e-simple-menu）・`openView`（e2e-schedule-v4）・`openPlan`・`freshPlan`（e2e-absence・details2・plan-menu・words・mobile-v5・panel-foot・visit-panel）は、それぞれの待ちがあるので自前のまま
- `clickMenu(page, 行き先, scope)`：左のメニューの項目を名前で押す（畳んだ親の中なら開いてから。`MENU_KEYS` に候補の key を前から並べる。名前は 予定・利用者さん・スタッフ・設定・基本情報・組む・担当を組む・組み方の標準。空き状況・欠勤はメニューに無く、`pressTool` で押す）。メニューを押して移ることそのものを確かめるときだけ使い、ただ移りたいなら `goTo`
- `pressTool(page, 操作, { where })`：操作の行のボタンを名前で押す。既定は行に出ていても「その他 ▾」の中でも押せる。`where: 'row'`（行にあるときだけ）・`where: 'more'`（「その他 ▾」の中だけ）は、位置そのものを確かめる所に付ける（`元に戻す`・`欠勤`（入は「その他 ▾」の中なので `where: 'more'`）・`勤務の見込み`・`印刷`・`担当なしを組む`・`訪問を追加`・`予定を入れる`・`担当を組む`・`確定`・`使い方`・`メールで送る` ほか。表は `TOOLS`。表に無い名前は testid として行→「その他 ▾」の順に探す。例 `pressTool(page, 'plan-view-order')`）。`openMore` は「その他 ▾」を開いて中の一覧を返し、`closeMore` は閉じる
- `undoState(page)`・`toolCount(page, testId)`：「元に戻す」の状態（押せるか・手の名前の説明）を「その他 ▾」を開いて読む（フォーカスは元へ戻す）／行と「その他 ▾」の中を合わせた testid の数（入り切りで出る・出ないを位置によらず確かめる）
- `openScreenDetails(page)`：画面の「詳しく ▾」（月・週・日）を開く。点数・凡例・進み具合を続けて何か所も読む e2e が着いたあとに1回呼ぶ（開け閉めは覚えるので、その画面は以後開いて始まる）
- `openDetails(page, testId)`・`reveal(page, testId)`：「詳しく ▾」を開く（無い・もう開いているなら何もしない）／要素が見えるまで待つ（その要素を含む畳んだ「詳しく ▾」だけ開いてから）。畳んだ中の点数・移動・凡例などを読む前に `reveal` を呼ぶ
- 使い分け：その画面そのものの作り（メニューの並び・操作の行の中身・「詳しく ▾」の開け閉め）を確かめる e2e は、位置を直に見てよい（段で直す）。ほかの確かめのために「移る・押す・開く」だけの所は共通の手を使う

## 環境変数

e2e の環境変数（どのスクリプトも同じ。読むのは共通の部品 `scripts/lib/env.cjs`）：`BASE` は開くサイト（既定 `http://localhost:4183/`）、`OUT_DIR` はスクリーンショットの置き場所（既定は OS の一時フォルダの `e2e-<名前>`。止まったときは `<名前>-fail-<段階>.png`）、`FAKE_NOW` はページの時計を止める時刻（ISO 8601。既定は次の水曜の日本時間 12:00。テストの「今日」もアプリと同じく日本時間で決めるので、日曜に実行しても今週に動かし先の日が残る。`npm run e2e` では設定ファイルが1回だけ決めて全部の worker にそろえる）、`CHROMIUM` は Chromium の実行ファイル、`PLAYWRIGHT` は Playwright のモジュールの場所（単独で走らせるとき。既定は `require('playwright')`、無ければ `/opt/node22/lib/node_modules/playwright`）、`PERF_MS_COMPAT`・`PERF_MS_NAV`・`PERF_MS_PROGRESS`・`PERF_MS_VACANCY`・`PERF_MS_DETAILS` は速さの上限（ミリ秒。無ければ `PERF_MS`）
