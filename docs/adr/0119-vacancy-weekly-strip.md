# ADR-0119：空き状況に「週の空きの帯」を常に出す

- 日付：2026-11-21
- 状態：採用
- 関連：ADR-0078・0080・PRD D78・D187・D258・D412・D472

## 背景
顧客から「文字よりもパッと見て分かる空き状況だとわかりやすい」との意見。今の画面は、答えのカードと要約が文字で、色の表（曜日×開始時刻のマス、凡例つき）は「詳しく ▾」の中に閉じていて、開かないと見えない。表は1マス38px・26列前後で横に巻くため、開いても全体を一目では見られない。

## 選択肢
1. 〈スタッフ〉×曜日の表を色の濃さで塗る：vacancy の結果は人数（どの週でも受けられる人数）で、人ごとの空きは持たない（`VacancyCell.byDate` に人の ID はあるが、人ごとの表は人数が多いと縦に伸び、問い合わせへの答え「何曜日の何時に受けられるか」から離れる）
2. 曜日ごとの時間帯の帯（曜日7行×開始時刻の30分区画を1本の帯に）を答えのカードの下に常に出す
3. 今の表を「詳しく ▾」から出して開いて始める（横に巻く・縦に長くなり、答えのカードの「一番上」が崩れる）

## 決定
- 案2。`lib/vacancyStrip.ts` の `vacancyStrip(result, answerResult, weekdays)`（純粋関数。判定は `verdictOf`・段階は `vacancyLevel`）で行と区画を作り、`pages/vacancyStrip.tsx` が描く。答えのカード（`vacancy-answer`）の下・「いつ・何を」の1行（`vacancy-when-line`）の上に置く
- 帯は曜日（月〜日）ごとに1行。区画は開始時刻（30分）で、幅は列数で等分する（横に巻かない。390px でも収まる）。色は既存の `lv-*`（`components/glance.css`。PRD D78・D228）をそのまま使い、新しい色は足さない（アプリにダークモードは無く、淡い地＋濃い文字の組はもとの凡例と同じ）
- 色だけに頼らない：区画に人数の数字（○ のとき）・△・？、行の右に印つきの文（「○ 10:00〜12:00・約3人」「△ 受けられない週がある」「× 受けられない」「？ 数えられない日」）。区画は `aria-hidden` で、読み上げは行の文（と `title`）。印刷は `print-color-adjust: exact` で色を残し、文は常に出る
- 時間帯のチップ・希望の曜日の外は薄く描き（区画は `opacity`、行は曜日と文を灰）、行の文は希望の範囲の中だけで作る（答えのカードと同じ範囲）
- 390px は右の文を帯の下の行へ回す。目盛りは3時間ごと（9:00・12:00・15:00・18:00）
- 今の文（答えのカード・要約・「詳しく ▾」の表・週ごとのマス・凡例・日付ごとの人）は消さず、切り替えも付けない。帯は答えの要約で、表は細部（マスを押すと日付ごとの人）という分担。帯の区画は押せない（押す先は表）
- 凡例は増やさない（D258 の「1か所」）。帯の下に1行の読み方だけ置き、印と色の凡例は表の上の1か所のまま

## 捨てた案
- 表／一覧の切り替え：状態が増え、既定をどちらにするかで顧客ごとに見え方が割れる。帯は常に出しても縦に約270pxで、答えのカードと次の一手の距離をあまり変えない
- 〈スタッフ〉別の表：上の選択肢1のとおり、問い合わせの答えと離れる。〈スタッフ〉ごとの稼働は日の予定・勤務の見込みにある
- 色の階調を足す・グラフの凡例を別に作る：既存の `lv-*` と食い違い、凡例が2か所になる

## 理由とトレードオフ
- 得るもの：開いてすぐ、曜日ごとの空き時間と人数の多さが分かる。データ・契約・計算は変えない（`DATA_VERSION`・保存の形も変えない）
- 失うもの：結果の縦が約270px 伸びる。26前後の区画のため390px では1区画が約10px で、数字は小さい（右の文が主、区画は補助）

## 影響
