# ADR-0068：名簿の書き出し・読み込みを〈利用者さん〉一覧・〈スタッフ〉一覧へ移し、CSV（文字コードの自動判別）を足す

- 日付：2026-10-27
- 状態：採用（ADR-0020 の「名簿はデータの画面の Excel の欄で対象を選ぶ」を置き換え。名簿の読み方・突き合わせ・総入れ替えは ADR-0020 のまま）

## 背景
- 名簿（〈利用者さん〉・〈スタッフ〉のシート1枚）の入出力は、データの画面の Excel の欄で「全体／〈利用者さん〉の名簿／〈スタッフ〉の名簿」を選んで行っていた。人を直す画面（予定を組むの〈利用者さん〉一覧・〈スタッフ〉一覧。ADR-0067）から離れていて、見つけにくい
- 利用者の声：Excel が入っていない端末もある。CSV でも出し入れしたい。CSV は Shift_JIS（Excel の「CSV（コンマ区切り）」の保存）・UTF-8 などが混ざるので、文字コードを選ばせずに読みたい

## 選択肢
1. 置き場所
   - 1-A：データの画面に残す（今のまま）
   - 1-B：各一覧の見出しの「Excel・CSV」で開く名簿の欄へ移し、データの画面は全体のブックだけにする
   - 1-C：両方に置く
2. CSV の文字コード
   - 2-A：読み込むときに選ばせる
   - 2-B：BOM → UTF-8・Shift_JIS・EUC-JP の順に誤りなく読めるもの（Shift_JIS の漢字の先頭のバイトは EUC-JP では読めないので、漢字があれば取り違えない）→ どれも誤りがあれば読めない文字の少ないほう、で見分ける
3. CSV の読み方
   - 3-A：CSV 用の読み取りを別に作る
   - 3-B：CSV を名簿のシート1枚のブック（ExcelJS）に写し、名簿のブックと同じ読み方（`rosterRows`）に渡す

## 決定
- 1-B・2-B・3-B
- 書き出しは BOM 付きの UTF-8（Excel で開いても文字化けしない）・カンマ区切り・CRLF。列と値は名簿のブックと同じ。数式と読まれる先頭（= + - @。数は除く）の値は「'」を前に付け（数式の差し込み・#NAME? を防ぐ）、読み込みで外す
- CSV の郵便番号の列の数字だけの値（Excel で開いて保存すると先頭の0が落ちる）は、名簿のブックの数のセルと同じく先頭を0で埋めて7桁に戻す
- 読み込むファイルの形は中身で決める（先頭が zip の「PK」なら .xlsx、ほかは CSV。拡張子は見ない）。区切りは1行目のカンマとタブの数で決める（タブ区切りも読める）
- 確認の本文に読んだ形（「Excel のブックとして読みました。」「CSV（文字コード Shift_JIS）として読みました。」）を出し、見分けの取り違えに気づけるようにする
- 読み込みで最終勤務日が入った〈スタッフ〉は、〈スタッフ〉一覧の「最終勤務日のある〈スタッフ〉」の欄（ADR-0015）に出るので、データの画面にあった知らせの帯（PRD D209）は無くし、トーストでその欄を指す
- 機能の入り切りは今の `excel` のまま（切れば名簿の欄も出さない）

## 理由とトレードオフ
- 得るもの：人を直す画面で名簿を出し入れでき、Excel の無い端末でも直せる。文字コードを選ばずに読める。読み方が1つなので、列・止める決まり・誤りの文が Excel と CSV で同じ
- 失うもの：
  - データの画面から名簿を出し入れできなくなる（データの画面に一覧へのリンクを置く）
  - CSV には書式・プルダウンが無い。Excel で CSV を開いて保存すると、日付の形などが変わることがある（郵便番号の先頭の0は戻す。読めない値は今までどおり行付きで止める）
  - 数式よけの「'」が、メモ帳などで開くと見える
  - 文字コードの見分けは推定なので、短い・特殊な文字の CSV で取り違えることがある（確認の本文の形の文で気づける）
  - CSV の誤りの文も「シート『〈呼び方〉』の N行目」の形（名簿のブックと同じ）
- 1-C は入口が2つになり迷う。2-A は利用者が文字コードを知らないと選べない。3-A は読み方が2つになり、決まりがずれる
