# ADR-0021：〈利用者さん〉の絞り込みを共通の欄にし、地区は住所から取り出す

- 日付：2026-10-18
- 状態：採用
- 関連：PRD D108〜D112・D285

## 背景
〈利用者さん〉を探す場所は、検索欄 `ClientPicker`（PRD D61・D62）で「人を選ぶ」形にそろえていた。

- 週間の時間軸（8人まで）と〈利用者さん〉×曜日の表（上限なし）が同じ選択を共有し、表は選ばないと空で、時間軸の上限に引きずられる
- 〈利用者さん〉の画面の一覧は、検索欄と段階の6つのボタンで絞る。ふだん見たいのは「終了でない人」と、地区や手当てが要る人（担当が決まっていない・パターンが無いなど）
- 地区を持つ項目はデータに無い（住所の文字だけ）。データの版は変えたくない

## 選択肢
1. 案A：表と一覧は「選ぶ」をやめて「絞り込む」にする。共通の部品 `ClientFilter` と純粋関数 `lib/clientFilter`。地区は住所から毎回取り出す（`lib/area`）。時間軸は今の `ClientPicker` のまま
2. 案B：`ClientPicker` に地区・チップを足し、表でも選ぶ形のまま
3. 案C：〈利用者さん〉に地区の項目を足し、画面で手直しできるようにする（データの版を上げる）

## 決定
案A。

- 週間の表は時間軸と選択を分け、最初からこの週に訪問がある人を全員出す（チップ「この期間に訪問がある人」を既定で押す。終了でもこの週に訪問がある人は出す）。状態は URL の `?cf=`（既定のままなら書かない）。表から時間軸へ移るときは、絞り込んだ人の先頭8人を引き継ぐ
- 絞り込みはすべて AND。チップの人数は「押したら何人になるか」で、0人のものは薄くして押せない。判定に使う集まり（期間に訪問がある人・担当が決まっていない訪問がある人・休み・パターン・〈スタッフ〉が担当する人など）は `filterFacts` で、週の訪問から作る
- 地区は 政令市＋区／市・町・村（郡＋町村）と、その続きの町名を住所から取り出す。取り出せない人は「住所なし」。手直しの欄・データの項目は作らない
- 〈利用者さん〉の画面の段階の6つのボタンは「終了の人も出す」のチェック1つに
- 訪問の種類（`visitTypes`）で絞る欄を足す。押した種類の訪問が期間にある人に絞る（複数はどれか＝OR、ほかの絞り込みとは AND）。種類が0件のときは欄を出さず、種類の無い訪問の人はどの種類にも入らない
- `ClientPicker` は週間の時間軸と月間だけで使う（近道「仮押さえの人」は月間だけ）

## 理由とトレードオフ
- 得るもの：表で全員がすぐ見え、時間軸の8人の上限に引きずられない。2つの画面で同じ絞り方・同じ言葉になる。地区はデータの版を上げずに使え、Excel・JSON の形も変わらない。判定は純粋関数なのでテストで固められる
- 失うもの：
  - 表で「好きな数人だけ」を並べることはできない（名前の検索で絞る）
  - 住所の書き方が崩れていると地区がずれ、手で直す場所は無い
  - 〈利用者さん〉の画面は1週間分の訪問から判定の集まりを作るので、データを変えるたびに少し計算が増える
- 捨てた案：B は表でも選ぶ形が残り全員を見にくい。C はデータの版を上げることになる

## 影響
- 主なモジュール：`lib/area`・`lib/clientFilter`・`components/ClientFilter`、週間・〈利用者さん〉の画面。契約・store・excel は変えない
- 見直す条件：住所の表記ゆれで地区が割れる（「ケ」「ヶ」・旧町名など）という声が出たら、正規化の表か地区の手直しの欄（案C）を検討する。〈利用者さん〉が数百人になり判定の計算が重くなったら、画面を開いている間だけ計算する・チップを押したときだけ計算するなどに変える
