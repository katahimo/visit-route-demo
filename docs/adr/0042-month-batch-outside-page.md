# ADR-0042：AI で範囲を組む計算を画面の外（モジュールの入れ物）で回す

- 日付：2026-10-20
- 状態：採用（結果は提案として出し、訪問には「反映する」で書く点は ADR-0053・ADR-0054。使う画面は担当を組むの画面で ADR-0063）
- 関連：PRD D256・D257、ADR-0039（よく変わる値を外の入れ物に置く。`lib/valueStore`）

## 背景
日・週・月の範囲を AI で組む計算は、1日ずつ Worker で解くので一月分（20日前後）は1〜2分かかる。計算の流れ（いま何日目か・止める・Worker の手）を画面の state に閉じていると、画面を離れると止まり、待つ間にほかの画面（今日の予定の確認など）を開けない。
制約：サーバーは無い（ADR-0001）。データを書き換えるのは store の `update(fn)` だけ。ページを閉じたあとの再開はしない（Worker は持ち越せず、作りかけの状態を保存すると壊れたときの直し方が増える）。

## 選択肢
1. 案A：画面に置き、離れる前に確認を出す。捨てた理由：待つ間に何もできないまま
2. 案B：App の直下に Provider（context と state）を置き、計算をそこで回す。捨てた理由：進みのたびに Provider の下を描き直し、進み具合だけを読む部品に分ける手間が案C と同じだけ要る
3. 案C：計算をモジュールの入れ物（`lib/monthBatch`。`createValueStore` の値）に置き、App の直下の小さな部品（`MonthBatchHost`）が store の `data`・`update` をつなぐ。画面は始める・止める・進み具合を読むだけ

## 決定
案C。

- `createMonthBatch(solve)` が入れ物を作る（アプリでは1つ）。`start`（作っている間は始めず false）・`stop`・`abort`・`connect`。進み具合（`run`）・終わった知らせ（`done`）・提案（`proposal`）を外の値として持つ
- 1日ずつ組んだ結果は提案（日ごとの担当・時刻の変更）としてその場だけ持ち、訪問には書かない。「反映する」で、組み始めたときのままの日だけを1回の update で書く
- `MonthBatchHost`（App の直下）は描いたデータを計算に読ませ、終わったら知らせを出す。上の帯（`BatchBand`）は担当を組むの画面・月の予定では出さない（画面の中に進み具合を出す）
- データを丸ごと差し替える操作（JSON・Excel の読み込み・初期状態に戻す・直前の状態に戻す・別のタブの変更の読み直し）では、古いデータから作った結果を書かないよう計算を捨てる。store が差し替えた回数 `replacedCount` を持ち、`MonthBatchHost` が変わったのを見て `abort()`
- ページを閉じる・読み直すと JavaScript ごと止まり、提案は消える。再開しない

## 理由とトレードオフ
- 得るもの：ほかの画面へ移っても止まらない。進み具合は外の入れ物なので、100ms ごとの進みで App 全体を描き直さない（ADR-0039 と同じ考え）。二重に始めない決まりが1か所になる。計算を Worker なしで差し替えてテストできる
- 失うもの：作っている間に別の画面で同じ日を直せる。そのため反映のときに、組み始めたときと訪問・その日の問題の入力が変わった日は書かない。欠勤の振り直しの案B と同時に Worker が2つ動くことがある（CPU を分け合うだけで結果は変わらない）。React の外に状態が1つ増える
- 見直す条件：再開（閉じても続きから）を求める声が出たとき、ほかの長い計算（まとめて地図に置く・比較）も画面の外へ出すとき
