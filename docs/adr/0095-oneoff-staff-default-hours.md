# ADR-0095：単発の予約では新しい〈スタッフ〉の既定の勤務を毎日 7:00〜22:00 にし、勤務に入らない予約を読み込み前に知らせる

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0008・0028・0072・0075・0092

## 背景
予約システムの形のスタッフ CSV（ADR-0075）には勤務日・勤務時間の列が無く、読み込んだ新しい〈スタッフ〉は既定の月〜金 9:00〜18:00 になる。ベビーシッターの予約（使い方「単発の予約」。ADR-0072）は夜（17〜20時ごろ）と土日が多く、その予約は担当に入れず「担当なし」で残る。原因が勤務時間の既定だと、読み込んだ人にもアプリにも見えにくい。

## 選択肢
1. 案A：使い方が単発の予約のときだけ、新しい〈スタッフ〉の既定を毎日（月〜日）・7:00〜22:00 に広げる。名簿の確認で既定にした人を知らせ、予約の CSV の確認で勤務に入らない予約を知らせる
2. 案B：すべての使い方で既定を広げる
3. 案C：既定は変えず、読み込みの確認で「勤務時間を直してください」と促すだけにする

## 決定
- 案A。既定を決める純粋関数は `lib/staffDefaultHours`（`defaultStaffHours(features)`）の1か所。単発の予約かどうかは、繰り返し（`patterns`）が切かで見分ける（`lib/addPlan` の `addPlanKind` と同じ。ひな形の「単発の予約」は `patterns` を切にする。ADR-0072）。それ以外の使い方は今までの月〜金 9:00〜18:00
- 使う場所は2つ：名簿の読み込みで勤務する曜日・勤務開始・勤務終了の列が無い（か空の）新しい〈スタッフ〉（`excel/rosterRows`）、〈スタッフ〉の「追加」の初期値（`lib/staffEdit` の `blankStaff(features)`）。今いる人の値は変えない。最初の2問の「自分のデータ」は〈スタッフ〉0人の空のデータで始めるので既定の置き場が無く、デモの単発の予約の〈スタッフ〉（`seed/oneOff`）は曜日を人ごとに決めた架空のデータなので揃える対象にしない
- 値の根拠：終了の 22:00 は、夜の予約（17〜20時の開始で2〜3時間）が収まる遅さ。開始の 7:00 は朝のお預かりが収まる早さ。曜日は予約が土日にも入るので毎日。入れすぎて夜中に担当が付くのを避けるため 0〜24時にはしない。実際の勤務に合わなければ〈スタッフ〉の画面の勤務時間で直す（既定は多めにとり、狭めるのは1人ずつ）
- 名簿の読み込みの確認の本文の最後に、広い既定にした人がいれば「勤務する曜日・時間の列が無い N人は、既定（毎日 7:00〜22:00）にしました。〈スタッフ〉の画面の勤務時間で直せます」を足す（`RosterImportResult.hoursDefaulted`・`rosterDefaultHoursNote`）
- 予約の CSV の読み込みの確認に、足す・直す予約のうちどの〈スタッフ〉の勤務日・時間にも入らないものがあれば「N件はどの〈スタッフ〉の勤務日・時間にも入りません（例：11/5（木）17:00〜20:00）。〈スタッフ〉の勤務時間を広げると組めます」を足す（`lib/bookingFit` の `bookingsOutsideHours`）。勤務は日ごとの上書きを含めて見て、窓（開始（早）〜（遅））があれば窓の中の開始で収まればよい。休止・最終勤務日後の人と取り消した予約は数えない。担当できる人の限り・相性・性別などの条件は見ない（勤務時間の話だけ）

## 理由とトレードオフ
- 得るもの：ベビーシッターの CSV を読んだだけで、夜・土日の予約にも担当が付く。勤務に入らない予約は、組む前の確認で原因が分かる
- 失うもの：単発の予約の既定が実際より広く、直さないと遅い時間・早い時間にも担当が付く（確認の文で知らせ、画面で直せる）。使い方で既定が変わるので、同じ名簿でも使い方により勤務が違う
- 捨てた案：案B は定期の訪問（日中・平日）で夜・土日に担当が付き、今までの挙動を変える。案C は担当なしが残る原因の大半が残る
