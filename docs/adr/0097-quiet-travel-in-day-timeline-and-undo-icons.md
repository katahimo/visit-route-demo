# ADR-0097：日の時間軸に移動の分数を控えめに戻す・予定の操作の行にアイコンだけの［元に戻す］［やり直す］

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0054・0073・0074・0093、PRD D58・D329・D384・D393・D402・D431・D432

## 背景
- 日の時間軸は帯の間に「移動 N分」の線を出していたが、ADR-0073 段(4)の2（コミット 386cbb3。PRD D384「例外だけ見せる」）で、エキスパート機能が切のときは「移動の分数は例外ではない」として出さなくなった（入には残った。D393）。実際には、訪問と訪問の間・自宅との行き帰りの移動は、誰が見ても組みの無理のなさを読む手がかりになり、消えたのは惜しいという声が出た。消した理由は「うるさい（情報が多い）」であり、移動が無意味だからではない
- 全体の元に戻す・やり直す（D329）は、切では「その他 ▾」の中の項目とトーストの「元に戻す」だけだった（ボタン2つまでの決まり。D402）。キー操作以外でもすぐ押せる所に欲しいという声が出た

## 選択肢
移動の表示：
1. 案A：入と同じ「移動 N分」の吹き出し付きの線を切にも出す（元に戻す）
2. 案B：切には点線と小さな薄い文字だけで出す（待ちの枠は出さない）
3. 案C：出さないまま（今まで）

元に戻す・やり直すの置き場所：
1. 案A：今のまま「その他 ▾」の中
2. 案B：操作の行に、ボタン2つまでの数に入れないアイコンだけの補助ボタンとして常に出す
3. 案C：上の帯（ナビの行・状態の1行）に置く

## 決定
- 移動：案A（入切とも同じ表示）。当初は案B（切は点線と薄い文字だけ、待ちの枠は出さない）を選んだが、後日、ユーザーの確認で入切とも同じ表示にした。D384 の「移動の分数は出さない」を、日の時間軸だけ覆す（札の中・順番・一覧・月・週は出さないまま）。分数は組みの結果の時刻から取り（`lib/timeline` の `legsOf`。距離は計算し直さない）。入切とも「移動 15分」の線と、待ちの点線の枠「待ち 30分」を出し、移動は次の訪問の始まりに接して置く（待ちはその前。担当ごとの1日の横棒と同じ並び）。位置が未登録の区間は「30分（見込み）」（ADR-0093 の見込み。移動時間を手で決めた〈利用者さん〉の区間は位置に関わらず見込みにしない。ADR-0096）、着く時刻が「いつまでに始める」を過ぎる区間は `--warn-ink` と三角の印（`lib/timeline` の `markLegs`）。隙間が狭い区間は文字を出さず線だけ（title・読み上げに分数）
- 元に戻す・やり直す：案B。D402 に例外を足す（ボタン2つまでには数えない補助。主ボタンは1つのまま）。`UndoIconButtons`（`components/undo`）を `ToolbarRow` の「その他 ▾」の左に入切とも常に出す。aria-label・title は手の名前つき、戻せないときは `aria-disabled`。「その他 ▾」の中の項目は重ねて持たず外す（`useHistoryMenuItems` を消す）

## 理由とトレードオフ
- 得るもの：移動と待ちを一目で読める（組みの無理が見える）。入切で見え方が同じなので、切り替えても読み方が変わらず、説明も1つで済む。ボタンで戻せるので、キーを知らない人・タッチの人も使える。操作の行は3画面で共通の部品なので、置き場所が画面を移っても動かない。案C（上の帯）は画面ごとに作りが違い、位置が動くため選ばない
- 失うもの：切の時間軸に線・文字・待ちの枠が増え、「例外だけ見せる」（D384）の静けさが少し減る。操作の行にアイコンが2つ増える（スマホは 44px ×2 で横幅を使うが、行は横に巻ける）
- 捨てた案：移動の案B（切だけ点線と薄い文字、待ちの枠なし）は当初の決定だったが、入切で読み方が変わり、待ちが見えないと組みの無理（長い待ち）が読めないため、ユーザーの確認でやめた。案C（出さない）は背景の声に応えない
