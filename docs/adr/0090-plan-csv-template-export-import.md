# ADR-0090：予定の CSV（このアプリの形）を「予定を入れる」から出し入れする

- 日付：2026-11-02
- 状態：採用（ひな形の中身は ADR-0091。単発のみ・基本にも `excel` が入った）

## 背景
単発の訪問をまとめて入れる口は、データの画面の「予約の CSV」（ADR-0075）だけだった。予定を入れる人が最初に開く予定の画面からはたどれず、読める形も予約システムの予約だけで、そのソフトを使わない事業所は使えない。単発の訪問を書き出す口も無く、全体の Excel のブックで出すしかなかった。

## 選択肢
1. 案A：「予定を入れる」の引き出しに、このアプリの形のテンプレート・書き出し・読み込みをまとめて置く。読み込みは予約の形の一覧に1行足す
2. 案B：読み込みだけ引き出しに置き、書き出しは予定の「その他 ▾」の書き出しに置く
3. 案C：データの画面に、このアプリの形の欄をもう1つ作る

## 決定
案A。
- 形：`excel/visitCsv.ts`（列 `VISIT_CSV_COLS`＝訪問ID・日付・開始・開始の上限・所要(分)・訪問先・メモ・取り消し・担当）。`BOOKING_FORMS` に `{ id: 'visit', label: 'このアプリの予定' }` を足し、読み込みは `importBookings` をそのまま使う
- 訪問ID の列があれば、その ID の訪問を直す（`Booking.visitId`）。空なら同じ日・開始・〈利用者さん〉の今の単発の訪問に当てる（`Booking.matchSlot`。2件以上なら読めなかった行、無ければ日付・開始・名前から決めた ID で足すので、読み直しても二重に入らない）
- 繰り返しの回（保存した回と、まだ保存していない計算した回 `${日付}_${パターンID}`）・別の〈利用者さん〉の訪問の ID は直さず読めなかった行にする（単発に変わる・担当とピンが前の人のまま残るのを防ぐ）
- 開始の上限の列に値があれば時間帯の訪問（`windowKind: 'window'`。開始と同じでも）。書き出しも時間帯なら上限を書く。予約システムの形は今までどおり時刻固定
- 取り消しの列は「取り消し」・○・はい で取り消し、空・×・なし・いいえ で取り消さない。ほかの値は読めなかった行。取り消しはファイルでは戻せない（予約の CSV と同じ）
- 確認・知らせの文は予約システムの形とこの形で共通の言葉（「訪問を読み込みますか？」）
- 担当の列は書き出すだけで、読むときは使わない（読まなかった列にも数えない）。担当・ピンは今の訪問のものを残す
- 書き出しは見ている日の月の単発の訪問（繰り返しの回は除く。`lib/planCsv` の `oneOffVisitsIn`）。テンプレートは列名の行だけ。どちらも BOM 付きの UTF-8
- 置き場所：「予定を入れる」の引き出し（`AddPlanPanel`）の下の「CSV でまとめて入れる」（`PlanCsvSection`）。ふだんは畳む。機能 `excel` の入り切りにかかわらず出す（単発のみ・基本のひな形は `excel` が切で、そこで使えないと目的を果たせない。登録の案内の名簿の読み込みと同じ扱い）。データの画面の「予約の CSV」も残す

## 理由とトレードオフ
- 得るもの：予定を入れる場所から、テンプレート → 記入 → 読み込み、書き出し → 直す → 読み込みの往復ができる。読み込みの本体・確認・控えは予約の CSV と共通
- 失うもの：引き出しが長くなる。書き出しは月単位だけ。日の予定の主ボタン（訪問の欄）からは出し入れできない
- 案B は入口が2か所に分かれ、往復の流れが見えにくい。案C は予定の画面からたどれない問題が残る

## 影響
- PRD D423（新規）・D402・D408。設計書の「予定を入れる」・`docs/design/pages-data.md` の予約の CSV
- 見直す条件：週・任意の期間で書き出したい、繰り返しの回も CSV で直したい要望が出たとき
