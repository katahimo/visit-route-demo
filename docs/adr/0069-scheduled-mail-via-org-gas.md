# ADR-0069：日の予定のメールを、事業所の Google Apps Script に確定のときにまとめて預け、前日の決めた時刻に送る（mailto は残す）

- 日付：2026-10-27
- 状態：採用
- 関連：PRD D361〜D364、ADR-0001（ブラウザ完結）・ADR-0016（外部送信の決まり）・ADR-0017（mailto）・ADR-0059（メールで確定）

## 背景
- 日の予定のメールは `mailto:` でメールアプリを開くだけで、送信は人が押す（ADR-0017）。毎日、担当の人数だけ押す手間が残り、前日の決まった時刻に自動で送りたいという要望が出た
- アプリは GitHub Pages の静的サイトでデータは端末の localStorage（ADR-0001）。サーバーが無く、ブラウザを閉じると何も動かない
- ブラウザだけで Gmail API を呼ぶ案は、ログインの権限が1時間で切れ、取り直しに人の操作が要る。開いたまま・スリープしない前提も当てにならない
- Google を使えない事業所もある

## 選択肢
1. 案A：事業所ごとに、GAS 付きのスプレッドシートのひな型をコピーしてもらい、アプリは確定のときにその GAS の Web アプリへメールを預ける。GAS が時刻トリガーで送る
2. 案B：アプリが Google のログインと Sheets・Drive・Apps Script の API でシートと GAS を作る
3. 案C：ブラウザから Gmail API で送り、時刻はアプリが数える（開いたまま）
4. 案D：PoC本体（サーバー・データベース）に戻し、サーバーから送る

## 決定
案A。mailto（ADR-0017）は今のまま残す。

- **預け先**：事業所の Google のアカウントでコピーしたシートの GAS（`gas/Code.gs`）。ひな型はコピー用のリンク（`GAS_TEMPLATE_URL`）で配り、メニュー「訪問予定 › 初期設定」で合言葉・5分ごとの時刻トリガー・シートを作る。Web アプリのデプロイ（実行：自分・アクセス：全員）と、URL・合言葉の貼り付けは人がする
- **やりとり**：`src/contracts/mailSchedule.ts`（版 `v`＝1）。`ping`・`queue`（日付のキーで上書き）・`cancel`。本文は JSON の文字で POST し、Content-Type・独自のヘッダーを付けない（確認の問い合わせを出さない。GAS は答えられない）。合言葉は本文に入れる
- **いつ預けるか**：日の予定の「予定をメールで送る」の欄の「N人分を予約して確定」を押したとき。メールアドレスのある担当全員分の全文（mailto の長さの目安は掛からない）を預け、その日を確定（伝えた）にする（確認は出さず知らせの「元に戻す」で戻せる。戻しても予約は残る）。確定のほかの道（「この割当で確定」・まとめて確定）では預けない
- **送る時刻**：訪問の前日の決めた時刻（既定 18:00、日本時間）。過ぎていればすぐ（次のトリガーで。最大5分遅れ）。過ぎた日は預けられない
- **予約し直す・取り消す**：同じ日を預け直すと、まだ送っていない分を置き換える。「予約を取り消す」はまだ送っていない分を取り消す（確定はそのまま）
- **設定の置き場**：URL・合言葉・送る時刻と、日ごとの預けた記録は、この端末の localStorage の別のキー（DemoData に入れない。書き出し・読み込み・初期化に入らず、合言葉をファイルに出さない）。管理者設定の下の「メールの予約送信」（メールの機能が入のときだけ）で入れ、「接続を試す」で確かめる
- **週のメール・連絡の一覧・空き枠の案内**は mailto のまま

## 理由とトレードオフ
- 得るもの：ブラウザを閉じても前日に届く。自前のサーバー・費用・Google Cloud の審査が要らない。送信元が事業所自身の Gmail で、予定・住所は提供側を通らない。本文の長さの制限が無くなる。Google を使えない事業所は今の mailto のまま使える
- 失うもの：
  - 予定・住所が事業所の Google アカウント（シート「予約」）を通り、残る（PRD §7 の外部送信に「押したときの予約送信」を足す）
  - 事業所ごとに初回の準備（コピー・許可・デプロイ・貼り付け）が要る。配ったコピーは提供側から直せず、版を上げたら貼り直してもらう
  - 合言葉は URL と同じく漏れれば第三者が預けられる。GAS が見るのは宛先の形・件数・長さだけで、宛先の範囲は限らない（漏れると事業所の Gmail から1日の上限まで誰にでも送れる）。合言葉はブラウザの localStorage にそのまま残り、GitHub Pages では同じ持ち主のほかのサイトと保存の場所（origin）を分け合う。漏れたら「合言葉を作り直す」
  - 送る時刻を過ぎた予約を預け直すと、もう送った人にももう一度届く（GAS は送信済みの行を置き換えない）。画面で確認を出してから預ける。訪問の日を過ぎた「予約」は送らず「期限切れ」、送れなければ3回まで次の回で送り直す
  - 1日の上限（無料の Gmail 100宛先、Workspace 1500）。送信は最大5分遅れる。送れたかはシートで見る（アプリは「預けた」までしか知らない）
  - 予約のあとに予定を変えても、自動では預け直さない（「予約し直す」を押す。確定し直しの印で気づける）
- 案B は API を入にする手間と審査の負担が増え、トリガーは API で付けられず手間が減らない。案C は時刻どおりに送れない。案D はデモの範囲（ADR-0001）を超える

## 影響
- 新しいもの：`src/contracts/mailSchedule.ts`・`src/lib/mailSchedule.ts`・`src/store/mailSchedule.ts`・`src/components/useMailSchedule.ts`・`src/pages/mailReserve.tsx`・`src/pages/mailScheduleSettings.tsx`・`gas/Code.gs`・`gas/README.md`
- 変えるもの：`lib/dayMail`（行に件名・全文）・`pages/mailPanels`（予約の枠）・`usePlanEdits` の `confirmByMail`（予約で確定）・管理者設定
- PRD：§4 のメールの「アプリからの送信・送信の記録」を「予約送信（事業所の Google）のほかの送信」に、§7 の外部送信に予約送信を足す
- 見直す条件：実データで使うなら、送ってよい宛先（ドメイン）をシートで限るか、専用のドメインで配る。送れたかをアプリで見たくなったら GAS に状態の問い合わせを足す（版を上げる）。予定を変えたら自動で預け直す要望が出たら、確定し直しと結ぶかを決める。事業所の準備がつまずくなら案B を考え直す
