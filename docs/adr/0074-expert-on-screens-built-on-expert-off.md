# ADR-0074：エキスパート機能が入の画面も切の作りを土台にする

- 日付：2026-10-31
- 状態：採用（段0＝ADR・要件・e2e の共通の手。段1＝メニュー・ホームを無くす・帯の入の種類・下のタブ・ツアー、段2＝予定の操作の行・「詳しく ▾」・説明1行（2026-10-31 実装）。画面の残りは段3〜5 で変える）
- 関連：PRD D390〜D395（置き換える既存の要件：D141〜D145・D247・D255・D263・D336・D349・D364・D383・D388・D389）、ADR-0067・ADR-0063・ADR-0044・ADR-0038、ADR-0073（切の画面の整理。段(4)の作りの土台）・ADR-0072（エキスパート機能）・ADR-0053（確定＝伝えた）・ADR-0029・ADR-0041（e2e）。検討書は作業の控え（2026-10-31。上の数はそこで測った）

## 背景
- 利用者の声（2026-10-31）：エキスパート機能が入のときの画面がごちゃごちゃ。切（ADR-0073）の考え方をうまく入れて、ふだんの作業をやりやすくしてほしい
- 入の画面を測ると（main d264243。時計は 2026-11-04 に固定）：
  - 左のメニューは 13項目（親5＋子8）＋畳むボタン3＋件数の印2（切は4項目）。〈利用者さん〉一覧への入口が3重（メニューの子・基本情報のタブ・ホームのカード）。スマホの下のタブにも〈利用者さん〉・〈スタッフ〉が無い
  - ホームはカード20枚で、要対応・担当なし・未確定の数は月の進み具合の帯と同じ。同じ件数が月の画面に4か所（帯・マス・マスの「担当なし」・右の欄）。「要対応」の語が59回
  - 日の予定は操作が31（切 11）、縦 3597px（切 2114px）、担当なしの札の下の「入れられない理由」が39個。主ボタンは月＝AI で組む・週＝なし・日＝確定とぶれ、足す操作は従のボタン
  - 〈利用者さん〉・〈スタッフ〉の一覧は札が 123・112 個（1人6〜14）で1画面に3人。設定は縦 4395px・スイッチの説明が常に2〜3行
  - 元は5つ：ナビの重複・同じ数の重複・常時の説明と凡例と理由・主ボタンのぶれ・専門の情報が一覧の列に直に出ている
- 制約：入では専門の機能（点数・移動・守れない条件・確定（伝えた）・組み方の標準・案を比べる・条件の重み・条件の印）を消さない（入らしさを守る）。e2e 34本のうち 31本が入で走るので、画面を変えるたびに多くの e2e が壊れる

## 選択肢
1. 方針：A＝切（ADR-0073 段(4)）の作りを土台にし、入は専門の操作・情報を「その他 ▾」・小さいタブ・「詳しく ▾」に足す／B＝今の入の画面を個別に削る（重複だけ消す）／C＝表示の密さ「すっきり／くわしく」を expert とは別の切り替えにする
2. 入のメニュー：a＝予定・〈利用者さん〉・〈スタッフ〉・組む・設定 の5つ（ホームは無くし要対応の帯へ）／b＝aにホームを残す／c＝今の5つ（ホーム・予定を組む・予定・空き状況・設定）で子だけ減らす
3. 入の主ボタン：a＝月・週は「予定を入れる」＋「担当を組む」、日は「予定を入れる」＋「確定（伝えた）」／b＝月は担当を組む・日は確定を主にし、足す操作は従／c＝切と全く同じで、組む・確定は「その他 ▾」
4. 入の「詳しく ▾」：a＝閉じて始め、見出しの1行に点数・移動・未確定などの数を出し、開け閉めは画面ごとに端末に覚える／b＝入は既定で開く
5. e2e の移り方：a＝段0で共通の手を先に整え、段ごとに直す所を1か所にする／b＝移行の間だけ「くわしい表示」の印を e2e に入れ、最後にまとめて直す

## 決定
1-A・2-a・3-a・4-a・5-a（利用者が推奨どおりに決めた。2026-10-31）。

1. **方針**：画面の骨組みは切と同じにする。切の部品（`exceptionView`・`peopleView`・要対応の帯・「詳しく ▾」・「その他 ▾」）をそのまま使い、入の差は部品の中の1か所に足す。機能は消さず、場所を変える・畳む・既定で閉じる
2. **入のメニューは5つ**：予定・〈利用者さん〉・〈スタッフ〉・組む・設定。ホームは無くし、起動は予定の画面。子の項目は「組む」だけ（基本情報・組み方の標準・担当を組む）。入だけの種類（未確定・組み直し・標準が無い）は要対応の帯に足す（D390・D391）
3. **入の主ボタン**：月・週＝「予定を入れる」＋「担当を組む」、日＝「予定を入れる」＋「確定（伝えた）」。ほかは「その他 ▾」（D392）。切の日の主ボタンは PR #140 で「訪問を追加」から「予定を入れる」に言葉をそろえてあり、入もそれに合わせる
4. **入の「詳しく ▾」**は閉じて始め、見出しの1行に点数・移動・未確定などの数を出す。開け閉めは画面ごとに端末に覚える（D393）
5. **e2e**：段0で共通の手 `scripts/lib/ui.cjs`（画面へ行く・メニューを押す・操作の行のボタンを押す・「その他 ▾」を開く・「詳しく ▾」を開く）を作り、入で走る e2e が画面の位置を直に押している所をそれに置き換える。以後の段で入の画面が切に寄っても、「移る・押す・開く」だけの所は `ui.cjs` の表（行き先・メニューの key・操作の名前）の1か所だけを直せばよくし、その段の画面そのものを確かめる e2e（メニューの並び・操作の行の中身・「詳しく ▾」の開け閉め）は段ごとに直す。位置を確かめる所は `pressTool` の `where: 'row'`・`'more'` で位置を指定する。移行の間の「くわしい表示」の印は作らない（二つの画面を持つ期間を作らない）

## 理由とトレードオフ
- 得るもの：入と切の画面が同じ骨組みになり、e2e・文書・ヘルプが1本に近づく。`exceptionView`・`peopleView`・`peopleTabs` の `only`（切のとき）の分岐を「入でも true」に寄せて減らせる。新しい部品は 入のメニュー項目「組む」・帯の入の種類・「詳しく ▾」の見出しの数・「くわしい列」の4つで足りる。利用者の声の「OFF のアイディアをうまく入れて」に合う
- 失うもの：入の人は月の進み具合・日の状態の行を開く手間が1回増える。ホームの「今日やること」の一覧は無くなる（帯と主ボタンへ移す）。入の人が慣れた画面が大きく変わる（段ごとに入と切の両方を撮って比べて確かめる）
- 捨てた案：B は小さく安全だが、入と切の二つの画面が残り主ボタンのぶれ・ナビの重複の根が残る（直すたびに2つを見る）。C は組み合わせが4つ（入切×密さ）になり文書・試験・分岐が倍で、「使われなくなったものは消す」（AGENTS.md）と逆。メニューのb は帯と重なるホームが残る。c は子を減らすだけで〈利用者さん〉・〈スタッフ〉が「予定を組む」の中に見える問題が残る。主ボタンの b・c は、足すのがふだんの作業なのに従に見える・入の要の操作（組む・確定）が見えなくなる。「詳しく」を既定で開く案は今の入と縦の長さがほぼ戻る
- 見直す条件：段1・2 のあと、入の人が「点数・移動・確定が見つからない」と言うなら見出しの数・開け閉めの覚えを見直す

## 第1段で決めたこと（2026-10-31 実装。PRD D390・D391）
- **メニュー**：判定は `lib/nav` の `menuSections` の1か所（`isSimpleMenu` は無くした）。入は 予定・〈利用者さん〉・〈スタッフ〉・組む・設定。「組む」だけが子（基本情報・組み方の標準（標準を登録したあとは出さない）・担当を組む）を持ち、設定は子を持たない（設定のタブは画面の上）。〈利用者さん〉・〈スタッフ〉は一覧・詳細の画面に印を付け、相性・勤務・予定と相性は「組む」の子「基本情報」に印（段3まで基本情報のタブが残るため）。予定に印を付けるのは月・週・日・空き状況（切はさらに比較・担当を組む）
- **件数の印**は「組む」の親の行に1つだけ（組み直しの知らせ、無ければ担当なしの日の数）。畳んでも見える。今日の「未確定」の印は帯の「未確定 N日」に移して無くした
- **下のタブ**は 予定・〈利用者さん〉・〈スタッフ〉・組む・探す・メニュー（設定は引き出しの中）。欠勤のタブは無くした（欠勤・キャンセルは予定の操作の行のボタン。段2で「その他 ▾」へ）。タブのキーは `lib/nav` の `bottomTabKeys(features)`
- **空き状況・欠勤**：空き状況は入切とも予定の「その他 ▾」（`lib/simpleMore`。入では「担当なしの訪問を組む」は足さない＝入は「担当を組む」の画面で組む）。欠勤・キャンセルは操作の行のボタンのまま（段2まで）
- **ホームを無くす**：`#/home`・`#/`・知らない URL・切った機能の URL は `homePath(features)`（繰り返しを使うなら月、使わないなら週。入切とも）。ホームの部品・`lib/home`・`home.css` は消した。月の後半の日（15）は `lib/scheduleMode` の `LATE_MONTH_FROM_DAY` へ移し、`planLabel`・`dayVisitRows`・`unassignedVisits`（ホームだけが使っていた）は消した
- **帯の入の種類**（`lib/attentionBand`）：「組み方の標準が無い」（標準を登録していない）・「基本情報が変わった（組み直す）」（標準を登録したあとで組み直しの知らせがあるとき。標準が無い間は知らせない。PRD D363）・「未確定 N日」（訪問があって伝えていない・未連絡の変更のある日。見る日は帯の他の種類と同じ今日から翌月末）。文の並びは 訪問の種類 → 標準が無い／組み直し → 未確定。押した先は並びの先頭の種類（訪問が最優先）：標準が無い→組み方の標準、組み直し→担当を組む（組む月）、未確定は1日だけならその日の日の予定・2日以上なら最初の日の月の右の欄（`?do=unconfirmed`。月は帯の日の月）。切った機能（`/standard`・`/arrange`）へ向かう種類は出さない。ホームの「今日の予定」の知らせ・来月のカードの15日の分け方・「担当なしの訪問を組む」のカードは帯の範囲（今日〜翌月末）と「その他 ▾」に置き換えた（来月の準備を始める日の分けはなくした）
- **条件に合わない・拘束超**（独立レビューの指摘で追加）：ホームの要対応が知らせていた「条件に合わない（必須の違反）の訪問」「出勤〜退勤が上限を超える日（拘束超）」も、入だけの種類として帯に足した（`lib/attentionBand` の `notAllowed`・`overSpan`。切は数えない：D384）。押した先は 条件に合わない＝最初のその訪問のある日の予定、拘束超＝最初の日の日の予定。文の並びは 訪問の3種類 → 条件に合わない → 拘束超 → 標準が無い／組み直し → 未確定
- **D364 は廃止**：基本情報の画面群の印とパレットの区分は D390 に書き、段3で D394 に置き換える
- **帯とほかの画面の同じ件数**：進み具合の帯・右の欄・マスの件数は段2まで今のまま（D391 の「ほかの画面は『詳しく ▾』へ回す」は段2）
- **ツアー**（D277）：ホームの枚を無くして 予定・欠勤 の2枚。予定の枚に帯の「見に行く」を書き、入は「組む」の「担当を組む」と帯の種類、切は「その他 ▾」の「担当なしの訪問を組む」と書く
- **切の担当を組むの言葉**：切のとき、担当を組むの画面の見出しの下の1行と注記は `proposalWords`・`reassignWords` と同じ言い方（案・この案にする・手で替えた訪問。`lib/exceptionView` の `arrangeWords`）。入は今のまま
- **e2e**：`scripts/lib/ui.cjs` の表からホームを消し、空き状況・欠勤は `pressTool`（メニューに無い）。データを書き換えて読み直す出発点は `#/data`。`e2e-home` は 起動・帯・月の `?do=`・まとめて確定・メニュー・スマホ を確かめる形に書き直した（ホームそのものの確かめは、帯の同じ数・押した先の確かめに置き換えた）


## 第2段で決めたこと（2026-10-31 実装。PRD D392・D393。D388 は D392 に置き換えて廃止）
- **操作の行は切の `SimpleToolbar` を入にも使う**（`components/simpleToolbar`）。入と切の差は `lib/exceptionView` の `mainTools(zoom, avail, expert)` の1か所（入の枝 `PRIMARY_EXPERT`・`SECOND_EXPERT`）。月・週＝主「予定を入れる」（切と同じ引き出し `AddPlanPanel`）＋「担当を組む」（担当を組むの画面のその月へ。`toolbar-assign`）、日＝主「予定を入れる」（`plan-visit-add`。日の主ボタンの言葉は入切とも `ADD_VISIT_LABEL`）＋「確定（伝えた）」。確定は段1までナビの行にあったが、操作の行へ移した（`AdoptButton`。ナビの行には伝えた状態の印と「次の確定していない日へ」だけ残す）。スマホの日は「予定を入れる」を「その他 ▾」に入れ、確定が主ボタン
- **「その他 ▾」の入の中身**：欠勤・キャンセルを登録（`sudden-open`。切は行のボタンのまま）・元に戻す／やり直す・表示の切り替え（月＝カレンダー／日ごとの一覧、日＝時間軸／順番／一覧）・使い方・予定をメールで送る（週・日）・印刷・勤務の見込み・空き状況。月の操作の行にあった見せ方の切り替えのボタン・日の表示の切り替えのボタン・使い方のボタン・週のナビの行のメールのボタンは無くした（CSS・部品も消した）
- **「詳しく ▾」は部品1つ**（`components/DetailsFold`）で入切とも使う。閉じて始め、開け閉めは画面ごと（月・週・日）に端末に覚える（`store/navOpen` の `detailsOpenKey`＝`details:<画面>`。入切で共通。読み直しても開いたまま。ほかの `DetailsFold`（人の詳細・理由・振り直し）は覚えない）。入は見出しの1行に数（`lib/detailsHeading`）：月＝担当 a/b日・確定 c/d日、週＝未確定 N日・要対応 M件、日＝点数・移動・入らない・守れない条件（0 は出さない）。切は数を出さない（「詳しく ▾」だけ）
- **畳むもの**：月＝進み具合の帯（次の一手のボタンを含む。上の帯の主ボタンは無くした）・月全体の件数・凡例、週＝1行の状態・時間軸の凡例、日＝今の担当の1行・担当ごとの1日、入の日はさらに「要対応の訪問 N件」の帯（`CareBand`）。**段1の要対応の帯との重なり**は、日の「要対応の訪問 N件」の帯を「詳しく」の中へ移して整理した（上の帯が件数の正。切は元から出さない）
- **札・時間軸に残すもの**（入らしさ）：ピン・資格✗・限✗の小さい印、日の時間軸の移動・待ちの線は今のまま。担当なしの札の入れられない理由は札ごとに「理由 N ▾」（`unplaced-reasons-fold`。閉じて始める）にした
