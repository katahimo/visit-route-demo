# ADR-0036：画面の見出しを1つの型にし、ボタンを塗り・枠・文字の3段に分ける

- 日付：2026-10-20
- 状態：採用（予定の3画面の［月｜週｜日］と期間の切り替えは ADR-0060・ADR-0061）
- 関連：PRD D236〜D239、ADR-0024・ADR-0025・ADR-0034

## 背景
日の予定は見出し・進み具合の帯・次の一手などの段が積まれ、本体が下に押し出されていた。主ボタンに見えるものも2つあった（塗りの確定と、赤い縁・太字の「欠勤・キャンセルを登録」）。ほかの画面も、塗り・枠・文字リンクの使い分けに決まりが無かった。左のメニューは項目の間隔が広く、1440×900 で最後のグループが切れていた。
制約：data-testid・URL・データは変えない。押せる所 44px（タッチ）は守る。

## 選択肢
- 見出し：A `PageHeader` を育てる（左に題名と1行の説明、右に主ボタン1つ）／B 切り替えを上の帯へ移す／C 今のまま
- ボタン：A 塗り・枠・文字の3段／B 塗りを2色にする／C 「欠勤・キャンセルを登録」を赤い縁のまま
- 上の段：A 次の一手を1行にまとめ、担当ごとの1日をマウスだけの端末で詰める／B 担当ごとの1日を畳む／C 2列にする

## 決定
いずれも A。

- 見出し：`PageHeader`（題名・1行の説明・右に主ボタンを1つまで）。全画面が同じ部品を使うので1か所でそろう。タブは role=tablist にせず、画面が移るリンクのナビ（`aria-current="page"`）にする
- ボタンの3段：塗り＝主（`.btn-primary`。1画面に1つ）／枠＝副（`.btn`）／文字＝ついで（`.btn btn-text`。戻す・送るなど無くても流れが進む操作）。押せる大きさは3段とも同じ
- 文字のボタンは灰（`--sub`）にする。朱の太字にすると枠より目立ち、段の順が逆になるため。重ねたときは下線で示し、地の色だけに頼らない
- 「欠勤・キャンセルを登録」は枠にし、アイコンだけ朱にして形と色で見分ける。操作の行の先頭という位置と、メニュー・ホーム・パレットの入口（ADR-0034）で見つけやすさを補う
- 日の予定の主は「この割当で確定」。確定済みの日は枠にして主ボタンを置かない
- 担当ごとの1日は、主の入力がマウスでタッチ・ペンを持たない端末（`pointer: fine` かつ `not any-pointer: coarse`）だけ行を詰める。押せる所を 44px にするのは、どれか1つでもタッチ・ペンを持つ端末（`any-pointer: coarse`）。`pointer` だけでは、タッチ付きノートで詰めた側になり指で押す所が小さくなる
- 左のメニューは項目 34px・グループの間 10px に詰め、1440×900 で最後の項目まで巻かずに見せる

## 理由とトレードオフ
- 得るもの：全画面の見出しが同じ形になり、塗りは各画面で1つだけになる。日の予定は本体の列の見出しと最初の訪問が初期表示に入る
- 失うもの：欠勤の入口の赤い縁が無くなり目立ち方が少し下がる。担当ごとの1日は人数に比例して高いまま
- 捨てた案：塗りを2色にすると結局どちらが主か迷う。担当ごとの1日を畳むと誰が詰まっているか開かないと見えない。2列は人どうしを縦に比べにくい
- 見直す条件：〈スタッフ〉が多い事業所で担当ごとの1日が本体を押し出すとき、人数の条件つきで畳む
