# ADR-0092：最初の2問の問2を「使い方」4つにし、ひな形の名前・並び・機能のグループと設定の置き場所を直す

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0028・0072・0073・0075・0091

## 背景
デモの相手は3つの事業所（単発のベビーシッター／定期の訪問介護・移動支援／定期の訪問看護）。最初の2問の問2は「単発／定期」の2つで、定期を選ぶと「基本」になり、訪問介護向けの「労務・契約管理」・訪問看護向けの「月次予定・現場共有」は管理者設定でひな形を適用し直さないと出なかった。ひな形の名前（単発のみ・労務・契約管理・月次予定・現場共有）は何のためのものか読み取りにくく、説明文は中身の列挙で、基本との差が見えなかった。
管理者設定は、機能のグループごとのカード（いちばん下が「データ」＝Excel の入出力）の下に「最初の設定をやり直す」のカードが同じ形で並び、機能の1つのように見えた。グループも「AI の条件」に担当を限る・相性と上級者向けの条件の重みが混ざり、「提案を比べる」が「予定」に入るなど、ひな形の差と並びが合わなかった。
また3つの事業所とも、自分の名簿・予約の CSV を最初に読み込んで試したい。訪問看護の事業所の CSV の形はまだ受け取っていない。

## 選択肢
1. 案A：問2を「使い方」（ひな形のうち すべての機能 を除く4つ）にし、ひな形の名前を使い方で付け直す。設定は 機能の入・切を1枚にまとめ、データを作り直す操作はデータの画面へ移す
2. 案B：問2は2つのまま、問3で事業所の型を聞く
3. 案C：問2に3つの事業所の名前で選択肢を出す

## 決定
- 案A
- 問2「2. 使い方の近いものはどれですか」：単発の予約（例：ベビーシッター）／定期の訪問（基本）／定期＋勤務・契約（例：訪問介護・移動支援）／定期＋月の予定・現場共有（例：訪問看護）。選んだひな形を当て、予約のかたち（単発の予約だけ単発）で呼び名・最初の画面・デモのデータを決める。初期の選択は デモ×定期の訪問（基本）（今までと同じ）。初期状態に戻す・前の版の印は予約のかたちのまま持つ
- ひな形の名前と並び：単発の予約 → 定期の訪問（基本） → 定期＋勤務・契約 → 定期＋月の予定・現場共有 → すべての機能。中身は ADR-0091 のまま。一覧に近い業種の例と、基本との差（「基本に足す」「基本から外す」）を出す
- 機能のグループ：予定の入れ方／当日・問い合わせ／担当の決め方／勤務・契約／現場との共有／入力の補助／上級（組み方の調整）。定期＋勤務・契約で足す機能は「勤務・契約」に集まる。管理者設定のスイッチは1枚のカード「機能の入・切」の中にグループの見出し（入っている数）で並べる
- 「最初の設定をやり直す」は「始め方を選び直す」と改め、データの画面のいちばん下の「最初からやり直す」に［デモの初期状態に戻す］と並べる（管理者設定からは外す）
- 登録の案内の③に予約の CSV の欄を置き、①顧客→②スタッフ→③予約 の順に事業所の CSV を読めるようにする。形の分からない事業所のため、名前らしい列から読む暫定の名簿の形（列名から読んだ名簿。PRD D425）を形の一覧の最後に足す
- 顧客の CSV そのものはリポジトリに置かない（取扱説明書のサンプルは架空のデータで作る）

## 理由とトレードオフ
- 得るもの：デモの入口で3つの事業所の型をそのまま選べ、設定を開かずに必要な機能が入る。ひな形の名前が使い方を表し、基本との差が読める。設定の画面が「機能」だけになり、データを消す操作と混ざらない。事業所の CSV で始められる
- 失うもの：ひな形・グループの名前が変わり、前の名前で覚えた人・説明書の直しが要る。問2の選択肢が2つから4つに増える。列名から読む形は推測なので、事業所の CSV を受け取ったら専用の形を足す必要がある
- 捨てた案：案B は質問が増える。案C は法人名を出さない決まり（ADR-0028）に反する
