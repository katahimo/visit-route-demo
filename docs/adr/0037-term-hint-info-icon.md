# ADR-0037：用語の説明の目印を ⓘ にし、同じ語の説明は1画面で1か所にする

- 日付：2026-10-19
- 状態：採用
- 関連：PRD D240〜D242、ADR-0025

## 背景
用語の説明（`components/Term`）は文字に点線の下線を引くボタンだった。説明を付ける語が増えると点線が1画面に何本も並び、名前のボタン（`PersonButton`。同じ点線）と見分けにくい。同じ語が設定・合計の表・日ごとの表に繰り返し出る画面では、同じ説明の入口が何度も出ていた。タッチでは文字の高さ（20px ほど）しか押せない。

## 選択肢
1. 案A：点線の下線のまま語を増やす
2. 案B：用語は普通の文字にし、後ろに ⓘ だけのボタン（`aria-label`「〈用語〉の説明」）を置く。捨てた理由：読み上げの名前が見える文字と別になる
3. 案C：用語の文字と小さな ⓘ を1つのボタンにし、下線はやめる。同じ画面の同じ語は最初の1か所だけ説明つきにする

## 決定
案C。

- ボタンは用語の文字と ⓘ。読み上げの名前は見える用語の文字（ⓘ は読まない）。説明は `aria-describedby` の先の `role="tooltip"`
- 下線は付けない。`pointer: coarse` では ⓘ のまわり 24px 角を押せる（WCAG 2.5.8）。44px は 390px で隣の操作に重なったのでとらない。印刷では ⓘ を出さない
- 同じ画面で同じ語が繰り返し出るときは、最初の1か所だけ説明つきにし、ほかは文字だけ（`Term` の `plain`）。開く欄（右の欄・吹き出し）は別の画面として数える

## 理由とトレードオフ
- 得るもの：語が増えても点線が並ばない。名前のボタン（点線）と用語（ⓘ）を見分けられる。見える文字と読み上げの名前がそろう
- 失うもの：ⓘ のぶん語が少し長くなる。表の2行目からは説明が無いので、上の1か所へ戻って読む

## 影響
- `components/Term.tsx`・`term.css`・`lib/glossary.ts`、各画面の `Term` の付け方。docs/design/pages-common.md
- 名前のボタン（`PersonButton`）の点線は変えない（別の部品）
- 見直す条件：ⓘ が名前の i（`PersonInfo`）や長い説明の `Hint` と紛れるという声が出たとき
