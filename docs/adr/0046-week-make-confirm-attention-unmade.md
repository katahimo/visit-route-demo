# ADR-0046：週の予定で見ながら確定でき、月をまたぐ週は1度に扱う

- 日付：2026-10-21
- 状態：採用（週で組むのは担当を組むの画面で ADR-0054・ADR-0063。要対応・「未作成」の数え方は ADR-0053）
- 関連：PRD D280・D281、ADR-0025（進み具合の帯・空の画面）・ADR-0031（まとめて確定）・ADR-0042（計算を画面の外で）

## 背景
週の予定で、見ていた週だけを作って確定する手段が無く、次の一手は月の予定へ飛ばして月全体（1〜2分）を作るものだった。週を見ながら作業を進めたい。
制約：契約・データの版は変えない。データを書き換えるのは store の `update(fn)` だけ。主ボタンは画面に1つ。

## 選択肢
1. 案A：週の見出しに主ボタンを状態で1つ出し、作り方・確定は月と同じ仕組み・決まりを週の日に当てる
2. 案B：週の空の画面のボタンを、月の「まとめて作る」の欄を対象の日を週に絞って開くだけにする。捨てた理由：月の画面へ飛ばされる問題が残り、月の欄に週の範囲という別の状態を持ち込む
3. 案C：週の予定に別の小さな計算を置く。捨てた理由：止める・二重に始めない・データの差し替えで止める・終わった知らせを二重に持つ

## 決定
案A。

- 週の見出しの主ボタンは状態で1つ（確定 → 済み。確定する日が無く残りが問題のある日だけなら「日の予定で」の理由を出す）。決まりは `lib/weekPrep` の `weekNext`
- 確定は月の「問題の無い日をまとめて確定」と同じ決まり（`bulkConfirmTargets`）・同じ確認ダイアログ・同じ書き方（`confirmDay`）を週の今日以降の日に当てる。問題のある日・前に確定した割当と違う日だけ残れば、ボタンを出さず日の予定で確定する理由を出す
- 担当を組むのは担当を組むの画面（範囲を週にする）。計算は `lib/monthBatch`（ADR-0042）で、月・週・日が同じ入れ物と決まりを使う。作っている間は主ボタンの確定を押せず、理由を見える文で出す
- 月をまたぐ週は1度に確定する（2つの月の日）

## 理由とトレードオフ
- 得るもの：週を見ながらその週だけを確定でき、月の画面へ飛ばない。確定は月と同じ仕組み・決まりなので数え方が食い違わない
- 失うもの：週の主ボタンは確定が中心で、組み直しは担当を組むの画面へ移る。週の予定でも今日以降の日を数える（7日ぶん。日ごとの状態は月・ホームと共有するので数え直しは増えない）
- 見直す条件：週のまま組みたい声が多ければ、週の主ボタンに組む入口を足す
