# ADR-0076：名簿を読み込んだあとに「位置の無い N人を地図に置く」を出し、1回の押しでまとめて置く

- 日付：2026-10-31
- 状態：採用
- 関連：PRD D89・D90・D121・D399、ADR-0016（押したときだけ外部の検索）・ADR-0068（名簿の欄）・ADR-0075（予約システムの CSV）

## 背景
予約システムの顧客の CSV（ADR-0075）を名簿として読むと、実データでは顧客515人のうち緯度・経度があるのは3人だけで、
ほとんどの人が位置の無いまま一覧に入る。位置の無い人をまとめて置く欄（`PlaceAllPanel`。D89）は一覧の下のほうにあり、
名簿の欄で読み込んだ人は、それに気づいて欄まで移り、もう一度「まとめて地図に置く」を押す必要があった。
外部への送信は利用者がボタンを押したときだけ（ADR-0016）なので、読み込みと同時に自動で探すことはできない。

決めること：導線をどこに・いつ出すか、押したあと何回押させるか、同意の扱い、〈スタッフ〉の自宅にもまとめて置くを作るか。

## 選択肢
1. 案A：読み込みが入ったら、名簿の欄の中（読み込みのすぐ下）に従のボタン「位置の無い N人を地図に置く」と送る先の注記を出す。押すと名簿の欄を閉じ、まとめて置く欄へ移って検索を始める（押すのは1回）
2. 案B：読み込みの確認のダイアログに「位置も探す」のチェックを足し、入れたらそのまま検索を始める
3. 案C：読み込みのあとのトーストに「地図に置く」のボタンを足す

## 決定
案A。
- 出す条件：〈利用者さん〉の名簿の読み込みが入った（`usePendingImport` が入ったと見届けた）あと、郵便番号・住所の検索（`geocode`）が入で、
  まとめて置く対象（`placeAllTargets` の targets：位置が無く、段階が「終了」でなく、住所か郵便番号のある人）が1人以上いて、まとめて置いている最中でないとき
- 出すかと文言は `lib/placeAll` の `placeAllLead`（N は `placeAllTargets` の targets の数で D89 の対象と同じ）。状態と押したときの処理は `components/useRosterPlaceLead`
- 押すと：導線を消し、名簿の欄を閉じ、まとめて置く欄へ移ってフォーカスを移し、まとめて置く（`usePlaceAllRun` の `run`）を始める。
  まとめて置く欄の「まとめて地図に置く」をもう一度押させない。この1回の押しを送る同意とし、ボタンの下に D90 の注記を出す
- 読み込みだけでは送らない（ADR-0016 のまま）。導線は名簿の欄の中の画面の状態で、保存しない
- `usePlaceAllRun` を `components/` に移して一覧の画面が持ち、`PlaceAllPanel` は結果を見せるだけにする（導線とカードの「まとめて地図に置く」が同じ処理を使う）
- 置けなかった人の出し方は D89 のまま。住所から位置が見つからなかった人がいれば、結果に1行「市区町村の名前が無い住所は見つからないことがあります…」を足す（新しい出し方は作らない）
- 〈スタッフ〉の自宅にはまとめて置くを作らない（下の理由）

## 理由とトレードオフ
- 得るもの：読み込んだ直後、目の前のボタン1回で位置が入り始める。導線は従のボタンで、一覧の主ボタン（〈利用者さん〉を追加）と並ばない。
  同意の形（押したときだけ・近くに送る先を書く）は ADR-0016 と同じ
- 失うもの：名簿の欄を閉じて読み込んだ（欄を閉じたまま入った）ときは導線が見えない（まとめて置く欄からは今までどおり押せる）
- 案B は確認のダイアログに外部送信の選択が混ざり、取り消しても送ったか分かりにくい。案C はトーストが消えると押せない
- 〈スタッフ〉の自宅にまとめて置くを作らない理由：〈スタッフ〉は〈利用者さん〉より一桁少なく、1人ずつの「地図に置く」（D121）で足りる。
  予約システムのスタッフの CSV（ADR-0075）は住所の列が無く緯度・経度を持つので、名簿から位置の無い人が大勢入る形にならない。
  〈スタッフ〉の自宅は郵便番号を保存しない（ADR-0016）ので、郵便番号だけの人を順に探すこともできない
