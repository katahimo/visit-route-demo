# ADR-0016：〈利用者さん〉の郵便番号→住所の補完と、住所→地図のピン（外部の検索サービスを押したときだけ使う）

- 日付：2026-10-17
- 状態：採用
- 関連：PRD D86〜D90・D118〜D121、ADR-0001（外部送信の方針）

## 背景
〈利用者さん〉の位置（緯度・経度）は移動時間の概算と地図の線に使う。位置は地図をクリックしてピンを置くしかなく、Excel で〈利用者さん〉をまとめて読み込むと位置が空の人が残り、1人ずつ地図で探す手間がかかる。郵便番号から住所を書き起こす手間もある。
PRD §7 は「外部送信は地図タイルの取得のみ」としていた（ADR-0001）。住所から位置を出すには、外部の検索サービスに住所を送るか、対応表を同梱するしかない。

決めること：方式、何をいつどこへ送るか、郵便番号検索の呼び方（CORS・JSONP）、失敗時の扱い、まとめて置くときの呼び方、郵便番号の持ち方。

## 選択肢
- 方式：A 外部の検索サービスを押したときだけ呼ぶ／B 郵便番号・住所と位置の対応表を同梱
- 呼び方：A fetch を先に試し、つながらなければ JSONP／B JSONP だけ／C fetch だけ
- まとめて置く：A 1人ずつ順に間をあけて呼ぶ／B 並べて一度に呼ぶ

## 決定
外部の検索サービスを、利用者がボタンを押したときだけ呼ぶ。

- 送る先：郵便番号検索（zipcloud）と国土地理院の住所検索だけ。キー不要・無料で、ビルドに秘密情報を入れない
- 送るもの：郵便番号（7桁）か住所の文字だけ。名前・メモ・特性などは送らない
- 送るとき：「住所を探す」「地図に置く」「まとめて地図に置く」を押したときだけ。ボタンの近くに送る先と中身を常に書く（押すこと自体が同意で、毎回の確認ダイアログは出さない）。開いただけ・入力しただけ・Excel 読み込みでは送らない
- 呼ぶ所：`lib/geocode.ts`・`lib/placeAll.ts`。画面から呼び、solver・matching・evaluate・seed・patterns・vacancy・reassign・excel・store からは呼ばない
- 郵便番号は fetch を先に試し、つながらない（CORS で読めない・通信できない）ときだけ JSONP で呼び直す。JSONP は終わったら script とグローバル関数を消し、遅れて届いた応答は捨てる
- 時間切れは1回の押下ごとに8秒（時間切れのときは JSONP へ切り替えない）。応答の形が想定と違うときも落とさず日本語の短い文で知らせ、失敗してもデータは変えない
- 候補が複数出たら先頭を入れ、ほかの候補（5件まで）から選び直せる
- 住所を入れるとき：いまの住所が見つけた住所で始まるなら番地を消さずそのまま。違う住所のときは「元に戻す」を出す
- ピン：見つけた位置に置く。ずれていれば消して地図をクリックで直す。ピンがある状態で郵便番号から住所を差し替えたときはピンを残し、「住所から置き直す」を促す
- まとめて置く：位置が無く段階が「終了」でない〈利用者さん〉のうち、住所か郵便番号のある人を1人ずつ順に、呼ぶたびに400msあける。「止める」で止まり、置けた人は1人ごとに `update(fn)` で書く（その間に利用者が直した人は上書きしない）。終わったら置けた人数と置けなかった人（名前・理由）を出す
- 郵便番号の持ち方：〈利用者さん〉の `place.postalCode`（空か7桁。ハイフン・全角・「〒」・空白は保存時に直す）。Excel の〈利用者さん〉に任意の列「郵便番号」。〈スタッフ〉の自宅・空き状況の場所には保存しない（探す手がかりだけの一時の入力）
- 同じ入力部品（`AddressField`）と決まりの純粋関数（`lib/addressLookup.ts`）を、〈利用者さん〉・空き状況の場所・〈スタッフ〉の自宅で共有する。探している途中に欄を書き換えたら呼び出しを止め、応答のあとも送った値と今の値が違えば捨てる
- CSP などの設定はリポジトリに無い（置くときは両ドメインを `connect-src`・`script-src` に足す）。外部の検索は e2e では偽の応答に差し替える

## 理由とトレードオフ
- 得るもの：Excel で読み込んだ〈利用者さん〉をボタン1つで地図に並べられ、郵便番号から住所の前半が入るので書き起こしの手間と誤記が減る。画面ごとに入力を作らないので文言・押せない理由・住所の当て方がずれない
- 失うもの：
  - 「外部送信は地図タイルの取得のみ」ではなくなる（PRD §7・design.md §2 に反映）。実在の住所を入れるとその住所が外部へ送られる（注記で知らせる。架空データの前提は変えない）
  - 外部サービスの停止・仕様変更・混雑で使えないことがある（地図のクリックで置ける）。JSONP は相手のスクリプトを動かす（CORS で読めないときだけ。送る先を固定）
  - 住所検索は文字の一致なので、番地の無い住所は町の代表の位置になることがある
  - 〈スタッフ〉の自宅の郵便番号は開き直すと空に戻る
- 捨てた案：方式B は約12万件で数十MBになり重く、毎月の更新も追う必要がある。呼び方B は常に相手のスクリプトを動かす、C は CORS で読めないと使えない。まとめて B は相手の負荷・制限に当たりうる
- 見直す条件：外部サービスが止まる・仕様が変わったら `lib/geocode` だけを差し替える。実データで使う声が出たら、送る前の確認ダイアログか同梱案を考え直す。自宅の郵便番号を保存したい声が出たら、自宅を〈利用者さん〉の場所と同じ形にする

## 影響
- 主なモジュール：`lib/geocode`・`lib/placeAll`・`lib/addressLookup`・`components/placeLookup`、〈利用者さん〉・〈スタッフ〉・空き状況の画面、excel（郵便番号の列）
- PRD §7 の外部送信は「地図タイルの取得と、利用者がボタンを押したときの郵便番号・住所の検索」
