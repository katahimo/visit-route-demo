# ADR-0016：郵便番号→住所の補完と、住所→地図のピン（外部の検索サービスを押したときだけ使う）

- 日付：2026-10-17
- 状態：採用
- 関連：ADR-0001

## 背景
位置は地図のクリックでしか置けず、Excel で読み込んだ〈利用者さん〉を1人ずつ探す手間があった。

## 決定
外部の検索サービスを、利用者がボタンを押したときだけ呼ぶ。
- 送る先：郵便番号検索（zipcloud）と国土地理院の住所検索だけ（キー不要）。送るのは郵便番号か住所の文字だけ
- 送るとき：「住所を探す」「地図に置く」「まとめて地図に置く」を押したときだけ。ボタンの近くに送る先と中身を書く（毎回の確認は出さない）
- 呼ぶ所：`lib/geocode.ts`・`lib/placeAll.ts`。画面から呼び、計算の層・store・excel からは呼ばない
- 郵便番号は fetch を先に試し、つながらないときだけ JSONP。時間切れは8秒。失敗してもデータは変えない
- 候補が複数なら先頭を入れ、5件まで選び直せる。住所が見つけた住所で始まれば番地を残す
- まとめて置く：位置の無い（終了でない）〈利用者さん〉を1人ずつ400msあけて呼ぶ。「止める」で止まり、置けた人は1人ごとに `update(fn)`
- 郵便番号は〈利用者さん〉の `place.postalCode`（空か7桁）。〈スタッフ〉の自宅・空き状況の場所には保存しない
- 入力部品 `AddressField` と `lib/addressLookup.ts` を各画面で共有。e2e では偽の応答に差し替える

## 捨てた案
対応表の同梱（数十MB・毎月の更新）・並べて一度に呼ぶ（相手の負荷）。

## トレードオフ
- 失うもの：外部送信が地図タイルだけではなくなる（PRD §7）。外部サービスが止まると使えない（地図のクリックで置ける）
- 見直す条件：サービスが変わったら `lib/geocode` だけを差し替える。実データで使うなら送る前の確認か同梱を考え直す
