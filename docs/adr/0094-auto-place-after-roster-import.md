# ADR-0094：名簿を読み込んだら住所から自動で地図に置き、位置の無い人を一覧で扱えるようにする

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0016・0068・0076・0093（ADR-0076 の「名簿のあとのボタン」を置き換える）

## 背景
名簿を読み込むと、〈利用者さん〉も〈スタッフ〉も位置の無いまま入る。〈利用者さん〉は読み込んだあとにもう一度ボタン（ADR-0076）を押す必要があり、〈スタッフ〉の自宅は1人ずつ画面を開いて［住所を探す］［地図に置く］を押すしかなかった。止めたあとや見つからなかった人を、どこで見て、どこから直せばよいかも分かりにくかった。外部へ送るのは押したときだけ（ADR-0016）にしたい。

## 選択肢
1. 案A：読み込みの確認に「読み込んだあと、住所から地図の位置を探します」の1文を足し、［名簿を読み込む］を押したら続けて自動でまとめて置く。〈スタッフ〉の自宅も同じ仕組みで置く
2. 案B：今のまま、読み込んだあとにボタンを出して押させる（ADR-0076）。〈スタッフ〉にも同じボタンを足す
3. 案C：読み込んだら確認なしで探す

## 決定
- 案A。郵便番号・住所の検索（ADR-0028 の geocode）が入で、読み込んだあとに位置の無い人（住所か郵便番号のある人）がいるときだけ、確認の本文に1文を足す。［名簿を読み込む］を押したことを送る同意とみて、入ったら名簿の欄を閉じ、まとめて置く欄へ移って始める。一覧の画面と登録の案内①②の両方
- まとめて置く処理（`lib/placeAll`）は〈利用者さん〉と〈スタッフ〉で同じものを使い、人の種類ごとの違い（数える人・書く先・文）は `placeAccess` の1か所に集める。〈スタッフ〉は休止の人を除き、郵便番号は持たないので住所だけで探す
- 〈スタッフ〉一覧にも〈利用者さん〉一覧と同じまとめて置く欄を出す
- 位置の無い人を一覧で扱う：
  - 一覧の上の欄の1行目に「位置が未登録の〈…〉：N人」と［位置の無い N人を地図に置く］（一度探したあとは［続きを探す（N人）］）・［位置なしだけ見る］。補足に「位置が無くても担当は組めます（移動は30分とみます）」（ADR-0093）。検索が切なら探すボタンは出さない
  - 絞り込みのチップ「位置なし N」（〈利用者さん〉は今の絞り込みの足すチップ、〈スタッフ〉は一覧の上に1つ）
  - 行に「位置なし」の印と［住所から探す］（その人だけ探して置く。結果は上の欄に出る）・［地図で置く］（その人の画面の場所・自宅の欄を開いた形で移る。`?edit=place`・`?edit=home`）

## 理由とトレードオフ
- 得るもの：名簿を読み込むだけで位置が入る。〈スタッフ〉の自宅も手で1人ずつ入れなくてよい。止めた・見つからなかった人を一覧で絞って、その場で直せる
- 失うもの：読み込みの確認が1行長くなる。読み込んだら送るので、送りたくなければ機能（geocode）を切るか、確認で取り消す必要がある
- 捨てた案：案B は押す回数が減らない。案C は押す前に送ることが分からず ADR-0016 に反する
