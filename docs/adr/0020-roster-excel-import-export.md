# ADR-0020：Excel の名簿（〈利用者さん〉・〈スタッフ〉のシート1枚）を、予定を消さずに足す・直す

- 日付：2026-10-18
- 状態：採用
- 関連：PRD D103〜D107、ADR-0006（Excel の入出力）

## 背景
Excel の書き出し・読み込み（PRD D23。ADR-0006）は全シートの全置き換えだけで、読み込むと訪問・伝えた内容などもブックの内容に置き換わる。人を指す列は名前で書き、同じブックの中だけで突き合わせている。

- よく増えるのは〈利用者さん〉で、1人足すたびに全体を読み込み直すと、組んだ予定がなくなる
- 名簿だけを別の表（事業所の台帳など）から写したいが、全体のブックには触りたくないシートも入っている
- 辞めた人・終わった人を消すと、その人を指す訪問などの扱いが難しくなる（今の画面も休止・段階「終了」で外している）

## 選択肢
1. 案A：名簿（シート1枚）の書き出し・読み込みを足す。読み込みは今のデータに当てて足す・直す（ID か名前で突き合わせ）。「総入れ替え」はブックに無い人を消さずに終了・休止にする。全体の読み込みは今のまま
2. 案B：全体の読み込みに「予定を残す」の選択を足す
3. 案C：名簿の読み込みも全置き換え（ブックに無い人は消す。その人を指す訪問は repair で外す）

## 決定
案A。データの画面の Excel で対象を「全体／〈利用者さん〉の名簿／〈スタッフ〉の名簿」から選ぶ。

- 名簿のブックはその人のシート1枚だけで、全体のブックの同じシートと同じ列・書式。全体のブックもそのシートだけを名簿として読める
- 読み込み方は「追加・更新」（既定）と「総入れ替え」。総入れ替えでもブックに無い人は消さず、〈利用者さん〉は段階「終了」、〈スタッフ〉は休止にする
- 同じ人：ID が入っていれば ID、空なら名前（全角半角・空白を同一視）。一致しなければ新しい人。ほかの人の参照は今のデータの〈スタッフ〉の名前で探す
- ブックに無い列は今の値のまま（新しい人は既定値）。知らない項目の列・いない人の名前・名前の重なりは、場所付きのエラーで止め、何も変えない
- excel は純粋な変換のまま（新しい DemoData と件数を返す）。画面が件数を見せて確かめてから store の `update` で入れ、最後は `migrate`（repair）で整える
- 確認には、〈スタッフ〉の休止で「担当できる人」から外れる〈利用者さん〉を出す。総入れ替えで今の人の半分を超えて外すときは、ファイルの取り違えの強い注意を先頭に出す。最終勤務日の入った〈スタッフ〉がいれば、読み込み後に振り直しを確かめる知らせを出す
- 新しい人の空の段階は利用中にする（名簿だけ）

## 理由とトレードオフ
- 得るもの：訪問・伝えた内容を残したまま人を足す・直せる。人を消さないので、その人を指す訪問が壊れない。全体の読み込みの決まり（ADR-0006）は変えない
- 失うもの：
  - ID を消して名前を変えた行は別の人として足される（ID を残せば防げる）
  - 総入れ替えでも人は減らない（消すのは画面から）
  - 名簿で変えた条件・段階で、今の担当が条件に合わなくなることがある（要対応で気づく。自動では直さない）
- 捨てた案：B は全シートを読んで突き合わせる処理が重い。C はその人を指す訪問の扱いが難しい

## 影響
- 主なモジュール：`src/excel/`（名簿の書き出し・読み込み・要約。全体の〈利用者さん〉・〈スタッフ〉シートの作り方を名簿と共通にした）、contracts（`RosterKind`・`RosterMode`・`RosterImportResult` だけ。データの形・版は変えない）、データの画面の Excel
- 見直す条件：訪問など、ほかのシートも部分的に入れたい要望が出たら、名簿と同じ「当てる」方式を広げる。名前の突き合わせで取り違えが起きたら、ID を必須にする
