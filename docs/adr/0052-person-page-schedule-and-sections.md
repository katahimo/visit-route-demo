# ADR-0052：〈利用者さん〉・〈スタッフ〉の画面を全画面にし、予定のカレンダーと節ごとの「直す → 保存」にする

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D308〜D313、ADR-0051（訪問の詳細の欄）・ADR-0012（定期パターン）・ADR-0013（休み）・ADR-0026（独自の確認ダイアログ）・ADR-0048（下書きのまま離れるときの確認）

## 背景
- 人を開くと右の欄で、一覧の鉛筆や `?id=` からいきなり編集の欄になると、見るだけのときも入力欄が並び誤って書き換えるおそれがある。そのため閲覧の欄を先に開き、「編集する」で編集に替える形にしていた。しかし閲覧の欄は住所・特性・担当の並びだけで、その人のこれからの訪問が見えなかった
- 編集の欄の中で、繰り返しと休みだけが押した時点で保存され、欄の「取り消し」で戻らなかった（保存の仕組みが2通り）
- 決定：〈利用者さん〉の画面は右の欄から全画面へ。データの形は変えない。スマホは見る・取り消す・担当替えまで

## 選択肢
1. 案A：右の欄のまま、閲覧の欄に「これからの訪問」の一覧を足す
2. 案B：`#/clients/:id`・`#/staff/:id` の全画面にし、タブ（先頭は予定）と、予定のカレンダー・節ごとの「直す → 保存」にする
3. 案C：案B に加えて、データの形（訪問に担当を持つ）も同時に作り直す（別 ADR で行った。ADR-0053）
- 閲覧と編集を別の欄の形に分ける案（入力欄を読み取り専用にする案・閲覧だけ別画面にする案）は、枠・select の読みにくさや即時に書く部品の個別停止、画面と経路の増加で採らない

## 決定
案B。
- ルート：`#/clients/:id`（`pages/ClientPage`）・`#/staff/:staffId`（`pages/StaffPersonPage`）。`new` は新しい人。一覧は一覧だけにし、行・「開く」・「追加」で全画面へ移る。古い `?id=` は一覧が受けてその人の画面へ `replace` で移る。吹き出し・パレット・名簿の知らせのリンクは直に `/:id` へ
- 画面の殻：名前と状態、一覧へ戻るリンク、タブ（`components/personPage` の `PersonTabs`。`?tab=`）。人が替わっても同じ画面として扱う
- 予定のタブ：`components/PersonCalendar`（週の時間軸・月のマス・狭い画面の日ごとのリスト）。回は `lib/personPage` で作り、押すと訪問の詳細の欄（ADR-0051）。〈利用者さん〉の広い画面だけ、空き枠を押す・縦にドラッグで新規、回のドラッグで日時を変えられる（範囲は欄で選ぶ）
- 繰り返し・休み：繰り返しは予定のタブの左に置き、「足す」「直す」「終わらせる」「消す」。休みは休みのタブ。どちらも保存を押すまで書かない
- 節：`components/personPage` の `EditSection`（読む ⇄ 直す → 保存・取り消し・Esc）。節ごとに保存する項目を決め、保存した中身にその項目だけ重ねる（`mergeFields`）。検査・正規化は節をまたいで同じ（郵便番号・メール・同じ名前・アイコン・担当できる人・段階・休止の確認・最終勤務日の振り直し）
- 変更の確認：変更があるまま 取り消す・Esc・別の節・タブ・メニューやリンクで移る（`useLeaveGuard`）・別の人の URL・再読込を確かめる。確認は独自のダイアログ（ADR-0026）。ブラウザの戻る・進むは、ページ側が止める手段が無く確認を出せないので、変更は黙って捨てる（確認は画面の中の操作・アプリ内のリンク・再読込・タブを閉じるときに限る）。`beforeunload`（再読込・タブを閉じる）の確認だけは、ブラウザの仕様でブラウザの確認のまま。変更があるときだけ受ける
- 月の予定で〈利用者さん〉を選んだときの右の欄は、その人の画面の予定（月）へのリンクにする

## 理由とトレードオフ
- 得るもの：その人の予定を見ながら、繰り返し・1回分・休みを同じ画面で直せる。どの節も「直す → 保存」で、保存の仕組みが1つ。見るだけのときに書き換える手段が画面に無い。カレンダーと欄は ADR-0051 の部品をそのまま使う
- 失うもの：
  - 一覧と人の画面を行き来する（隣の人を開くのは、戻る・一覧へ戻るリンクで1回多い）
  - 新しい人は基本の節だけで作り、住所・特性などは保存してから入れる
  - 〈スタッフ〉のカレンダーでは足す・動かすをしない（担当が替わると回がその人の予定から消え、分かりにくいため）。カレンダーの時刻は訪問の開始（早）と所要で、日の予定の時間軸（移動・待ちを入れた時刻）とずれることがある
- 見直す条件：週の予定の時間軸と `PersonCalendar` を寄せたくなったとき
