# ADR-0118：右下の浮かせた地図は勝手に開かず開け閉めを覚える・〈利用者さん〉あての訪問連絡と変更の連絡の住所を機能の入り切りにする

- 日付：2026-11-21
- 状態：採用
- 関連：ADR-0028（機能の入り切り）・ADR-0039・ADR-0103（日の予定の地図はいつも）・ADR-0017・ADR-0069（メール）

## 背景
顧客のご意見が3件あった。
- 右下に出る地図の表示が多く、閉じる手間がある。日の予定は地図のカード（`plan-map`）を本体の下に置き、画面の外にあるあいだ、右下に `MapDock` を浮かせる（ADR-0103）。〈スタッフ〉・区間・訪問を選ぶたびに、閉じていても開き直す作りで、列を押すたびに地図が開いていた。閉じた状態も覚えず、日や画面を替えると、また同じ状態から始まる
- 〈利用者さん〉への連絡（訪問連絡）はあまりしないので、なくてもよい。連絡の一覧には〈利用者さん〉あての連絡文・表（担当が変わる・時刻だけ変わる）が出るが、切る機能は無い
- 〈スタッフ〉への変更の連絡文は文字が多く、住所は要らない。「お願いします」の行に〈利用者さん〉の住所が入る（PRD D246）

## 選択肢
1. 案A：浮かせた地図は選んでも開かず、開け閉めを端末に覚える。連絡の2つは機能の入り切り（既定は入）にする
2. 案B：浮かせた地図を無くす（ボタンも）。連絡は文面を常に短くする
3. 案C：浮かせた地図にも機能の入り切りを足す。連絡は組織の設定欄を別に作る

## 決定
- 案A
- 浮かせた地図（`MapDock`）：選んだもの（`focusKey`）で開く動きをやめる。出すのは地図のカードが画面の外のあいだ、開くのは右下の「地図」のボタンを押したときだけ。開けた・閉じたは端末に覚える（`store/navOpen` の鍵 `map-dock`。日の予定と比べるの画面で1つ。無ければ閉じて始める）。読み直しても日を替えても同じ。開いているあいだは、選ぶと地図が強調される（今までどおり）。ボタンは小さく残す（ページの地図へ行くより近いため）
- 機能の入り切りを2つ足す（管理者設定の「現場との共有」。既定は入。`FEATURE_IDS` は22）：
  - `clientContact`「〈利用者さん〉への訪問連絡」：切ると、連絡の一覧と欠勤・キャンセルの欄から〈利用者さん〉あての連絡文を作らず、連絡の一覧の「担当が変わる〈利用者さん〉」「時刻だけ変わる〈利用者さん〉」の表も出さない。〈スタッフ〉あての連絡・件数（「連絡の一覧（訪問N件）」「変更あり N件」）・すべての連絡文のコピー（〈スタッフ〉あてだけになる）は残る
  - `contactAddress`「〈スタッフ〉あての変更の連絡に住所」：切ると、〈スタッフ〉あての連絡文・連絡の一覧の「お願いします」の行から〈利用者さん〉の住所を外す（所要の分・初めての訪問先の印と決まりごとは残る。日の予定のメール・チャット用の文は元から住所の扱いが別なので変えない）
- 文を作る関数（`lib/contacts`）は `ContactWords` の `clientContact`（既定は作る）と、住所を空にした `clientAddress`（`dayContactWords` の `staffAddress`）で出し分ける。画面は機能の値を `dayContactWords` に渡すだけ
- ひな形：どの機能もひな形ごとの差にはしない（今の動きは全ひな形で入）。ただしひな形を適用すると全 ID を明示して書く（ADR-0028）ので、新しい2つは基本のひな形の入れる機能に入れ、全ひな形で入にする。ひな形の「基本との差」には出ない
- 範囲外：日の予定のメール（D92）・チャット用の文（D419）は〈スタッフ〉あての別の文で、今回は変えない

## 理由とトレードオフ
- 得るもの：列や訪問を押しても地図が開かず、閉じる手間が減る。閉じた・開いたが続く。〈利用者さん〉あての連絡を使わない事業所は一覧が短くなる。住所なしの短い連絡文にできる。ほかの顧客の動きは変わらない（既定は入）
- 失うもの：地図を選んで見たい人は、ボタンを1回押す（以後は覚える）。選ぶだけで開く気軽さは無くなる。機能のスイッチが2つ増える
- 捨てた案：案B は地図を見たい人の動線をなくす。案C は設定の入口が増え、機能の入り切り（ADR-0028）の一覧に収まる2つにわざわざ別の欄を作る意味が無い
- 見直す条件：浮かせた地図のボタン自体が邪魔だという声が出たとき（ボタンを出す・出さないの設定を考える）

## 影響
- PRD D300 を直し、D466（浮かせた地図）・D467（〈利用者さん〉への訪問連絡）・D468（変更の連絡の住所）を足す。D211 の機能を22にする
- design：pages-plan.md・pages.md・pages-common.md・pages-plan-absence.md・contracts.md を直す
- データの版は上げない。機能の入り切りは省略可の表で、無い ID は入として読める。地図の開け閉めは DemoData に入れず端末に覚える（書き出し・初期化に入らない）
- e2e：`e2e-mobile.cjs`（浮かせた地図の段）・`e2e-absence.cjs`（`contact-features`）・`e2e-features.cjs`（スイッチの数）
