# ADR-0003：最適化はブラウザの Web Worker 上の焼きなまし（TypeScript）で解く

- 日付：2026-10-11
- 状態：採用

## 背景
静的サイトでは Python（OR-Tools）が動かない。割当費用と均等の費用を目的関数に入れ、同じ入力から同じ案を出したい。

## 決定
TypeScript の焼きなまし（貪欲な初期解・差分評価・指数冷却・最後に貪欲な仕上げ）。
- 近傍：別の担当へ移す・2訪問の担当を入れ替える・同じ担当の中で順番を入れ替える・落とした訪問を入れる
- 時間の約束・稼働時間帯・可否はハード（破る手は採らない）
- 乱数は seed 付き（mulberry32）。止めるのは反復回数（`defaultIterations`。問題の大きさから決める）。30秒で `stop` したら最良案を「途中の案」として採る

## 捨てた案
OR-Tools の WebAssembly 化・Pyodide：重く、任意の費用関数を入れにくい。

## OR-Tools との比較（2026-10-12 実測。移動だけの問題で比較）
- デモの規模（8人・1日約17件、10日分）：総移動が OR-Tools と一致（差 0.0%）
- 15〜50人・60〜250件：既定の反復回数では 2〜18% 負け、5倍（約7〜11秒）で OR-Tools 60秒との差 −1.7〜+5.6%（多くは3%以内）。OR-Tools 10秒は大規模で訪問を落とした

## トレードオフ
- 得るもの：依存なし・任意の費用関数・再現性
- 失うもの：最適性の保証。PoC本体の AI案とは結果が違う
- 見直す条件：30人・150件で30秒を超える、または移動だけの案が OR-Tools より 10% 以上悪いとき（ALNS に広げる）
