# ADR-0064：組み方の標準が無い間は、日の範囲を考え方ごとに組んで並べ、選んだ案を標準にする

- 日付：2026-10-25
- 状態：採用
- 関連：PRD D357・D356、ADR-0063（担当を組む・組み方の標準）・ADR-0062（組み方の標準）・ADR-0010（点数の基準のプリセット）・ADR-0053（AI は提案を出すだけ）

## 背景
- 提案の帯が変わる件数だけで、どう担当が変わるか分からず反映を判断できなかった
- 標準が登録されるまでは、最初から複数の考え方で組んで比べ、気に入った案を標準にしたい。以後はその標準で AI が組む
- 初期のプリセット名「標準」は「組み方の標準」と紛らわしい
- 利用者の指定：手順が少なく分かりやすい方。デモなので前のデータとの互換は要らない

## 選択肢
1. 案A：担当を組むの日の範囲で、標準が無ければ全プリセットで組んで案を並べる。案から［この案を標準にする］で、確認1回で、その日に反映し・その曜日の担当と時刻を標準にし・考え方を点数の基準にする（1手）
2. 案B：案を選んだら組み方の標準の画面へ移り、表で直して登録する。手順が増えるので取らない
3. 案C：標準の画面の「案をくらべる」へ誘導するだけ。同じく手順が増え、1日の案を見て決める流れにならない

## 決定
案A。

- 標準が無い間、範囲が週・月なら「AI で組む」は出さず、先に1日を考え方ごとに組んで標準を決める案内と［M/D を考え方ごとの案で組む］（範囲を日へ）だけを出す。標準を決める入口は1つ。ホームの「はじめに組み方の標準を決める」も同じ日へ
- 範囲が日で標準が無いとき：組む日・考え方の選択を出さず、その日（伝えていない日）をすべてのプリセット（最大6つ）で組む（`monthBatch` の `variants`）。標準が無いので標準のピンは使わず、手で付けたピンだけを守る（繰り返しの担当に縛られず考え方の違いが出る）
- 結果は考え方ごとの案の帯：タブ（今の担当・案ごとの点と変わる件数。最高点に王冠）で切り替え、選んだ案を日の予定と同じ時間軸（変わる訪問に印）と地図で見る。変わる訪問の一覧も出す。選んだ案に［この案を標準にする］［この日だけ反映］、全体に［捨てる］。件数と一覧だけでは違いを判断しにくかったため
- ［この案を標準にする］：確認 → その日に反映し、その曜日のマスだけ案の担当・開始を標準にする（`registerDayStandard`。動かした回・この回だけ変えた回・今の標準の担当がその日に働けない回は表に入れない。その日の回は残す。いつからは来週の月曜。違う予定は標準どおりに入れ替える）。考え方を点数の基準にする。違うマスが無くても標準を登録したことにする。すべて同じ update（元に戻すの1手）
- 標準の登録後は、日の範囲もふだんの「AI で組む」（点数の基準の考え方で組む）
- 提案の帯（ふだん・案とも）に、変わる訪問の一覧（「時刻 〈利用者さん〉：今の担当 → 提案の担当」、時刻だけなら「今の開始 → 提案の開始」）
- 組み方の標準の画面の「考え方」は、登録時でなく今の点数の基準を出す（AI は今の点数の基準で組むため）
- 初期データは今日からの日を AI で組まず、繰り返しの担当のままにする（PRD D322）。初めての人は考え方ごとの案から標準を決める
- メニューの並びは ホーム・予定を組む・予定・空き状況・人・設定（組む → 直す・確かめるの作業の順。ADR-0063 の並びを変える）
- 初期のプリセット名「標準」を「バランス」（id `balance`）に。データの版を3に上げ、前の版は読まず初期データで始める（ADR-0053 と同じ扱い）

## 理由とトレードオフ
- 得るもの：初めての人が、比べる → 選ぶ → 以後はその考え方、を1画面・1確認で済ませられる。件数でなく「誰の訪問が誰へ」を見て決められる
- 失うもの：
  - 1日分の案から作る標準はその曜日だけ。ほかの曜日は今の標準のまま（標準の画面の表で直す）
  - 1日分の案には手で付けたピンが効く（標準の画面の案はピンを効かせないひな形）
  - 計算はプリセットの数だけ（初期の3つで1日 約9〜15秒、6つで約20〜30秒）。月・週では案を並べない
  - 標準を決めるまで週・月をまとめて組めない
  - データの版3：前の版のデータ・JSON は読めない
