# ADR-0064：組み方の標準が無い間は、日の範囲を3つの考え方で組んで並べ、選んだ案を標準にする。プリセット「標準」は「バランス」に

- 日付：2026-10-25
- 状態：採用
- 関連：ADR-0063（担当を組む・組み方の標準）・ADR-0062（組み方の標準）・ADR-0010（点数の基準のプリセット）・ADR-0053（AI は提案を出すだけ）

## 背景
- 利用者の声（2026-10-25）：
  - 提案の帯が「担当が変わる 3件・時刻が変わる 0件」の数だけで、どう担当が変わるか分からず反映を判断できない
  - 標準が登録されるまでは、担当を組むの範囲が「日」のとき、最初から3つの考え方で組んで比べたい。気に入った案を標準として登録し、以後はその標準で AI が組む
  - 初期のプリセット名「標準」は「組み方の標準」と紛れるので「バランス」などに変える
- 利用者の指定：手順が少なく分かりやすい方。デモなので前のデータとの互換は要らない。きれいな作りに（2026-10-25）

## 選択肢
1. 案A：担当を組むの日の範囲で、標準が無ければ「3つの案を組む」。案のカードに［この案を標準にする］。確認1回で、その日に反映し・その曜日の担当と時刻を来週の月曜から標準にし・考え方を標準の考え方（点数の基準）にする（1手）
2. 案B：3つの案から選んだら組み方の標準の画面へ移り、表で直す・いつからを選んで登録する
3. 案C：標準の画面の「案をくらべる」へ誘導するだけ

## 決定
案A（利用者が決めた。2026-10-25。「手順が少なく分かりやすい方」）。

- 組み方の標準が無い間は、担当を組むの範囲が週・月なら「AI で組む」の欄を出さず、「組み方の標準がまだありません。週・月をまとめて組む前に、1日を3つの考え方で組んでくらべ、気に入った案を標準にしてください」と［M/D を3つの案で組む］（範囲を日へ。訪問のある伝えていない最初の日）だけを出す。標準を決める入口は1つ（日の3つの案）。ホームの「はじめに組み方の標準を決める」も担当を組むのその日へ
- 担当を組む（`#/arrange`）の範囲が日で、組み方の標準が無い（`data.standard` が無い）とき：組む日の選び方と考え方の欄を出さず、「組み方の標準がまだ無いので〜3つの考え方でこの日を組んで並べます」と書き、主ボタンは「3つの案を組む」。その日（伝えていない日）を先頭の3つのプリセットで組む（`monthBatch` の `variants`）
- 結果は考え方ごとの案の帯（カード3枚）：件数・移動の増減・変わる訪問の一覧、［この案を標準にする］［この日だけ反映］、全体の［捨てる］。担当なし・担当の変わる訪問がいちばん少ない案に王冠
- ［この案を標準にする］：確認（何が起きるかを箇条で）→ その日に反映し、`registerDayStandard`（その曜日のマスだけ案の担当・開始。いつからは来週の月曜。違う予定は標準どおりに入れ替える。考え方を点数の基準に。違うマスが無くても標準を登録したことにする）を同じ update で（元に戻すの1手）
- 標準を登録したあとは、日の範囲もふだんの「AI で組む」（点数の基準＝選んだ考え方で組む）
- 提案の帯（ふだん・案のカードとも）に、日ごとの変わる訪問の一覧（「時刻 〈利用者さん〉：今の担当 → 提案の担当」、時刻だけなら「今の開始 → 提案の開始（N分遅く）」）
- 初期のプリセットの名前「標準」を「バランス」に、id も `balance` に。データの版を3に上げ、前の版のデータは移さず初期データで始める（ADR-0053 と同じ扱い）

## 理由とトレードオフ
- 得るもの：初めての人が、比べる → 選ぶ → 以後はその考え方、を1画面・1確認で済ませられる。件数でなく「誰の訪問が誰へ」を見て決められる
- 失うもの：
  - 1日分の案から作る標準はその曜日だけ。ほかの曜日は今の標準のまま（組み方の標準の画面で表で直す）
  - 1日分の案には手で付けたピンが効く（組み方の標準の画面の案はピンを効かせないひな形。D352）
  - 計算は3倍（1日 約9〜15秒）。月・週の範囲では3案にしない
  - 標準を決めるまでは週・月をまとめて組めない（先に1日で標準を決める）
  - データの版3：前の版のデータ・JSON は読めず、初期データで始める
