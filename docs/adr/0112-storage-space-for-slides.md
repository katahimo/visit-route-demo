# ADR-0112：説明用スライドの iframe は、`?space=` の接頭辞で保存領域を分ける

- 日付：2026-11-09
- 状態：採用
- 関連：ADR-0001・0053

## 背景
操作説明の Web スライド（`public/slides/`）は、iframe で `../?space=slides#/plan` のようにアプリを開いて見せる。同じ画面を開くので、そのままでは普段のアプリと同じ localStorage・sessionStorage を読み書きし、スライドの操作（データの書き換え・初期状態に戻す・書き出し）が利用者の普段のデータを壊す。サーバーは持たない（ADR-0001）ので、分けるのはブラウザの保存の側。

## 選択肢
1. 案A：キーに接頭辞（`vrdemo:space:<space>:`）を付けて、同じ localStorage の中で分ける。
2. 案B：スライド用に別のオリジン（別のホスト名）で配る。
3. 案C：スライドの中ではデータを保存しない（メモリだけ）。

## 決定
案A。URL のクエリ `space=<英小文字・数字・ハイフン>` があれば、起動時に1度だけ読み、localStorage・sessionStorage のキーに接頭辞を付ける（`store/storageSpace`）。他の文字は無視して普段の領域で開く。書き出し・読み込み・初期状態に戻す・片づけ・別のタブの同期は、その領域のキーの中だけに効く。普段のアプリは接頭辞付きのキーを読まない。領域のときは上の帯に「説明用のデータ」を出す。

## 理由とトレードオフ
- 得るもの：配り方（同じ静的サイト・同じオリジン）を変えずに、普段のデータを守れる。スライドの中では普通に保存・読み直しができ、実際の画面と同じ動きを見せられる。
- 失うもの：同じオリジンなので、ブラウザの保存容量は普段と共有する。領域のデータは自動では消えない（ブラウザの保存を消すと一緒に消える）。

## 影響
- 要件 D447、`docs/design/pages-data.md`。
- localStorage・sessionStorage を直接触らず `appLocalStorage()`・`appSessionStorage()` を使う。lib は Storage を引数で受け、呼ぶ側（components・pages）が渡す。
- 見直す条件：スライド以外の領域が要るとき、または領域のデータを消す操作が要るとき。
