# ADR-0116：続く訪問は同じ人・夕方は自宅に近い人の条件と、開始時刻をずらさない機能のスイッチ

- 日付：2026-11-21
- 状態：採用
- 関連：ADR-0002・0011・0028・0035・0053・0101。PRD D453〜D456

## 背景
顧客のご意見3件（担当の振り分け）：
1. 「同じ利用者さんでサービスの内容が変わるため、時間を分けると、スタッフバラバラに振り分けられる」（全員向け）。
   身体介護と生活援助のように時間を分けた続く訪問は、繰り返しごとに別のいつもの担当・負担の均等・種類の条件で別々の人に入りやすい。
   今の費用では、同じ地点の続く訪問は移動0分で得をするだけで、それより重い条件があると分かれる
2. 「夕方の案件は自宅からなるべく近い人で振り分けたい」（全員向け）。今の費用は最後の訪問から自宅へ帰る移動も数えるが、
   移動1分＝1点で一律なので「夕方は特に帰りを近く」を重くできない
3. 「移動で80分はかかっていないのに10:20にずらされる。時間をずらした提案はしない設定にしてほしい（シフト作成時に見落とすと、
   サービス時間に遅刻したことになる）」（この顧客の好み）。スクショは 9:00 に終わる訪問のあと「移動 80分・33.1km」で 10:20 開始
   - 80分の出どころ：スクショのどの区間も 距離÷時間＝25km/h（13.7km・33分、18.5km・44分、33.1km・80分）。直線距離×道なり係数1.3÷車の速さ25km/h
     （ADR-0101 の既定）の見積もりどおりで、計算の誤りではない（33.1km は直線 約25.5km。25.5×1.3÷25×60＝79.4分）。
     既定の25km/h は遅刻を避ける安全側で、長い区間（郊外の幹線）ほど実際より長く出る。道路の所要（OSRM）を取っても、
     補正（＋5分・×1.5）で平均すると約23km/h 相当なので、遠い組を直線から見積もる今の扱い（ADR-0101）を変えても大きくは変わらない

## 選択肢
続く訪問（1）：
1. 案A：条件の型 `sameClient` を足し、「同じ人が続けて回らない組」に 重み×10点。列ごとに足せるよう組の点を半分ずつ両方の訪問に持たせる
   （列にいる訪問は続けて回らない組ごとに半分、担当なしの訪問は組ごとに半分）
2. 案B：続けて回る組に −重み×10点（加点）。式は簡単だが、点数の下限（100点）が組の数だけ下がり、ふだんの点数が変わる
3. 案C：いつもの担当（continuity）に混ぜる。型の意味が変わり、必須にすると続く訪問まで必須になる
4. 案D：続く訪問を1件にまとめて組む。訪問の ID・種類・担当・確定の扱いが変わる大きな改修

既定で効かせるか（1）：
1. 案E：組み込みの条件にし、初期データに入れ、無い古いデータにも読み込みで足す（重み2）
2. 案F：条件の型だけ足し、使う事業所が［条件を追加］で足す

夕方（2）：
1. 案G：条件の型 `homeNear`：開始（早）が 17:00 以降の訪問の割当費用に、訪問から自宅までの移動1分＝重み×0.2点
2. 案H：「その人のその日の最後の訪問」の帰りの移動に重みを掛ける（列の費用）。朝だけの人の昼の最後の訪問にも効き、「夕方」と言えない
3. 案I：時刻の境を条件ごと・事業所ごとに決められるようにする（欄と画面が増える）

ずらさない（3）：
1. 案J：機能の入り切り（ADR-0028）のスイッチ `shiftStart`「開始時刻をずらして組む」。入が今までの動き。切ると時間に幅のある訪問も
   開始（早）だけ（latest＝earliest）で組み・検査し、欠勤の振り直しの「N分遅らせれば入る」を探さない
2. 案K：事業所の設定（`org`）に欄を足し、管理者設定に新しいカードを置く
3. 案L：見積もりの速さを上げる（全員の移動が短くなり、遅刻の側に倒れる）

## 決定
- 続く訪問は 案A＋案E。組は「同じ〈利用者さん〉の同じ日の訪問で、前の終わり（開始（早）＋所要）から次の開始（早）まで 0〜30分（`SAME_CLIENT_GAP_MAX`）で、
  いちばん早く始まるもの」。重なる訪問（2人で入る）は組にしない。続く先は1つの訪問につき1組だけ（先の添字の訪問が取り、ほかはまだ取られていない先から選ぶ）。
  同じ時刻の印の無い2件 A・B のあとに C があると、A→C・B→C の2組では1人の列にどちらかしか続けられず、どの案でも減点が残るため（捨てた案：
  同じ時刻の2件を組から外す。2人のどちらかが続けて回る好みも消える）。必須にはできない。費用は `Problem.chain`（`matching/chain`）で持ち、
  solver は `routeCost`（列の点）と `dropPointsOf`（担当なしの半分）、evaluate は `chainScore` で同じ値を数え、`totalPoints` の `chain` に入れる。
  採点（`PlanScore.chainPoints`・`perRule[ID]`）・達成（組の数のうち続けて回る組）・減点の内訳（「続く訪問が別の人」）・点を下げているいちばんの理由に出す。
  点数の下限には入れない（どの案も0以上）。perRule・達成のキーは `Problem.chain.ruleId`（sameClient の型の条件の ID）。repair が ID の衝突で
  'sameClient2' などにしても、型で引くのでほかの条件（ID 'sameClient'）の集計を上書きしない（捨てた案：キーを型の名前に固定）
- 組み込みの条件：初期の条件に `{ id: 'sameClient', label: '続く訪問は同じ人', weight: 2 }`。無いデータ・ブックは store の repair が最後に足す。
  消すボタンを出さず、足す種類にも出さない（切るのは重み0）。プリセットの重みは バランス2・移動を短く2・人の組み合わせ重視3、無い古いプリセット（調整した重みを含む）は2
- 夕方は 案G。初期データには入れず（今までと同じ）、［条件を追加］で足す。点は移動0分以外いつも正なので、条件ごとの達成は
  「自宅までの移動が `HOME_NEAR_MET_MINUTES`（15分）以内」の夕方の訪問を数える（理由の `Reason.met`。点が0以下で数える決まりでは、いつも0件になる。
  捨てた案：達成の対象外にする。条件を足した事業所が効き目を見られない）。重みの無い古いプリセットは2（足してすぐ効く。条件が無ければ効かないので、ほかの事業所は変わらない）
- ずらさないは 案J。グループは「担当の決め方」で、どのひな形でも入。空き状況の問い合わせの仮の訪問（`INQUIRY_VISIT_ID`）は時刻を探すので幅のまま。
  切ると `Problem.fixedStart` を立て、`reassign.candidatesFor` は「ずらせば入る」を探さない
- 80分の見積もりは直さない（式・既定どおり）。顧客には管理者設定の「移動時間の見積もり方」で車の速さを地域に合わせる（例 30〜35km/h）か、
  車道にそった道のりを取ることを案内する

## 理由とトレードオフ
- 得るもの：続く訪問を分ける原因（いつもの担当・均等）と同じ物差し（重み×10点）で比べられ、事業所が重みで強さを決められる。
  半分ずつ持たせる形なら、列ごとの差分評価（焼きなまし・振り直し・素朴な案・挿入）をそのまま使え、solver と evaluate の合計点が一致する。
  夕方は割当費用だけなので solver・evaluate を変えない。ずらさないは既存の管理者設定のスイッチの並びに1行足すだけで、画面の部品が増えない
- 失うもの：組み込みの条件は「消せない条件」という例外が1つ増える。古いデータは読み込むと条件が1つ増え、続く訪問のある日の点数がその分下がる。
  夕方の境（17:00）は決め打ち。ずらさないを切ると、時間に幅のある訪問の幅は AI と検査で使われない（開始（早）が約束の時刻になる）
- 害の見込み（案E にした理由）：組になるのは同じ〈利用者さん〉の間30分以内の続く訪問だけで、同じ地点なので同じ人なら移動も減る。
  分けたい事情（資格・担当を限る）は必須の条件・種類が先に効き、重み2（移動20分ぶん）は負担の均等や移動が大きく違えば負ける強さ。
  重なる訪問（2人で入る）は対象外
- 捨てた案：案B は点数の物差しが変わる。案C は型の意味と必須が混ざる。案D は改修が大きい。案F では今使っている事業所（ご意見の顧客を含む。
  エキスパート機能が切だと条件の重みの画面が出ない）に届かない。案H は「夕方」と言えない。案I は欄と画面が増えるので、声を聞いてから。
  案K は画面の部品が増える。案L は全員の移動が短くなり遅刻の側に倒れる
