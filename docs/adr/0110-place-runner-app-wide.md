# ADR-0110：住所からの位置の検索はアプリで1つの入れ物で続け、探し終えてから組む

- 日付：2026-11-07
- 状態：採用（PRD D445。ADR-0094 の「画面が持つ」を置き換え）

## 背景
名簿を読み込んだあとの位置の検索（PRD D427。ADR-0094）は、一覧の画面・登録の案内が持っていた。〈利用者さん〉400人などでは数分かかり、そのあいだに
最初の設定を終えて予定の画面へ移ると、検索が止まる。残りの人は位置なし（移動30分の見込み）のまま、予約の読み込みのあとの自動の組み（D442）で担当が決まり、
あとで位置が入っても、担当のある訪問は組み直さない（担当なし・要対応だけを組む）。近さを見ない組みで固まる。

## 選択肢
1. 案A：今のまま（画面を移ると止まる。［続きを探す］で続ける）
2. 案B：検索中は「予定の画面へ」を押せなくする
3. 案C：検索をアプリで1つの入れ物（lib/placeRunner）に移し、画面を移っても続ける。検索中は読み込みのあとの自動の組みを待たせ、探し終えてから1回組む

## 決定
案C。自動の組み（lib/autoArrangeBatch。ADR-0072）と同じ作りで、App の直下の PlaceRunHost が store につなぎ、上の帯に進み具合と［止める］を出す。
〈利用者さん〉と〈スタッフ〉はアプリで1本の列に並べる（外部の検索は同時に1本。ADR-0016）。データを丸ごと差し替えたら止め、書かず・組まない。
組むのは、まとめて探して位置を入れた人がいたとき・探すあいだに読み込みの自動の組みを待たせたとき（1人だけ探す行の［住所から探す］では組まない）。

## 理由とトレードオフ
- 得るもの：待たずに予定の画面へ進める。担当は位置のそろったデータで決まる
- 失うもの：探し終えるまで、読み込んだ予約は担当なしのまま（上の帯で探していると分かる）。案B は待たせるだけで、400人では使いにくい

## 影響
- 一覧の画面・登録の案内の欄（PlaceAllPanel）は入れ物の進み具合を読むだけ。画面を離れても止めない（止めるのは［止める］と差し替え）
- 一覧の画面どうしも同じ列に並ぶ（〈利用者さん〉と〈スタッフ〉を同時に探さない）
