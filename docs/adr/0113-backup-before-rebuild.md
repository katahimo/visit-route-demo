# ADR-0113：今のデータがあるときは、控えを書き出すまで作り直せない

- 日付：2026-11-12
- 状態：採用
- 関連：ADR-0032・0092・0102

## 背景
事業所が自分のデータを入れて実際に使い始めた。データはブラウザの中にしか無い。作り直す入口は3つ（デモの更新の知らせで「デモで試す」「自分のデータで始める」を選ぶ／「最初の設定をやり直す」・ブラウザの「戻る」で出る2問に答える／例外の画面の「データを初期状態に戻す」）。どれも注意の文と1世代の控え（ADR-0032）だけで、押し間違えると次の置き換えで控えも消える。控えの書き出しは案内の文だけだった。

## 選択肢
1. 案A：今のデータがあるのに作り直すときは、その画面で控え（JSON）を書き出すまで実行のボタンを押せなくする
2. 案B：作り直すときに自動で控えのファイルを保存させる
3. 案C：1世代の控えを複数世代にする

## 決定
- 案A
- 最初の2問の画面：今のデータがあり（やり直し・更新の知らせ）、「今のデータを使い続ける」以外を選んでいるあいだ、注意の下に案内と［控えを書き出す］を出す。押すと控え（データの画面の「ファイルに書き出す」と同じ JSON）を保存し、ファイル名と戻し方を出す。書き出すまで主ボタン「はじめる」は押せない。初めて開いたとき（データが無い）は出さない
- 更新の知らせの初めの選択は「今のデータを使い続ける」のまま（ADR-0102）。やり直しの2問は「閉じる」で今のデータのまま戻る
- 例外の画面：「データを初期状態に戻す」は「控え（バックアップ）を書き出す」を押すまで押せない（書き出せるデータが無いときも、書き出しを試したあとは押せる）
- 判定は `lib/firstRun` の `firstRunGuard`、書き出しは `components/useBackupDownload`（データの画面と共用）。1世代の控え（ADR-0032）はそのまま残す
- 読み込みで置き換える操作（控え・Excel 全体・名簿）は今までどおり確認と1世代の控え（ファイルを選ぶ手順があり、押し間違いで起きにくい）

## 理由とトレードオフ
- 得るもの：押し間違い・読み違いで実データを失わない。控えのファイルが手元に残り、別の端末でも戻せる
- 失うもの：デモを試し直すだけの人にも1手増える。書き出したファイルを本当に持っているかまでは確かめない
- 捨てた案：案B は押していないのにファイルが保存され、スマホでは保存の確認が出て何が起きたか分かりにくい。案C は容量が倍々（ADR-0032 で捨てた）
