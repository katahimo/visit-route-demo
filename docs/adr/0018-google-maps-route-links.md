# ADR-0018：道順は Google マップの公開のリンク（Maps URLs）を作るだけ（API・キー・サーバーは使わない）

- 日付：2026-10-18
- 状態：採用（日のメールの長さの段階は ADR-0059）
- 関連：PRD D97〜D101、ADR-0016・0017

## 背景
スタッフは訪問先までの道を、住所を地図アプリに打ち直して探している。前に使っていた社内の仕組みでは区間ごとに「道順を見る」「今いる場所から」の Google マップのリンクがあり、便利だった。
PRD §4 は「Google Maps Platform は使わない（移動時間は直線距離の概算）」、§7 は外部送信を地図タイルと押したときの検索だけとしており、道順の出し方によってはぶつかる。

決めること：どう道順を出すか、どこに置くか、経由地の上限と分け方、場所の書き方。

## 選択肢
- 出し方：A Maps URLs のリンクを作るだけ／B Directions API で経路・時間を取って中に出す／C 出さない
- 経由地：A 3件で複数本に分ける／B 上限を気にせず1本

## 決定
Google マップの公開の「Maps URLs」（`https://www.google.com/maps/dir/?api=1&origin=…&destination=…&waypoints=…&travelmode=…`）のリンクを作るだけにする。区間の分数・キロ数は Google から取らず、直線距離の概算のまま（時間・距離は開いた Google マップで見る）。

- 外部送信の決まりとの関係：アプリはリンクを画面・メールに置くだけで通信しない。押した人の端末が Google マップを開き、そのとき URL の場所が Google に渡る（人が選んで開く）。PRD §7 は変えない。PRD §4 の「使わない」はキーの要る API のことで、公開 URL のリンクは別物
- URL に入れるもの：場所と移動手段だけ。場所は座標（小数6桁まで）があればそれ、無ければ住所の文字。名前・鍵・入り方などは入れない。場所が無い区間はリンクを出さない。移動手段は〈スタッフ〉の `travelMode` を `travelmode` に対応づける
- 経由地は1本に3件まで（Google の公開文書の「スマホのブラウザで3件まで」に合わせ、4件目以降が黙って抜けるのを避ける。`MAPS_MOBILE_WAYPOINTS`）。超えれば前の1本の行き先を次の出発地にして複数本に分ける。URL は 2,048字を超えるとき経由地を減らして分ける
- 公共交通は経由地付きの経路を Google マップが出さないので、全行程は出さず区間ごとのリンクだけにする
- 場所の無い地点は全行程では飛ばし、近くに「全行程に入っていません」と書く。自転車は日本で経路が出ないことがあるので bicycling のまま、近くに徒歩へ切り替える案内を添える
- 置く場所（主ボタンにしない。小さな枠のリンク、`target="_blank" rel="noopener noreferrer"`）：日の予定のメール（全行程と区間ごと。ADR-0017）、スタッフ画面（1日の全行程・各訪問の「前の場所から」と「ここへ道案内」）、日の画面の訪問の詳細（担当の並び順での「前の場所から」）
- 組み立ては純粋関数 `lib/mapsLink.ts` と `lib/mail.ts`、部品は `components/mapsLinks.tsx`。データは変えない

## 理由とトレードオフ
- 得るもの：住所を打ち直さずに道順・1日の回り方を Google マップで開ける。キー・費用・サーバーが要らず静的サイトのまま。時間・距離・渋滞は Google が出すので、概算とのずれを人が確かめられる。外部送信の決まりを変えない
- 失うもの：
  - アプリ内の分数・キロ数は概算のまま（画面に「Google マップで確かめてください」）
  - 経由地3件なので訪問の多い日は全行程が2〜3本。公共交通は区間ごと。自転車は徒歩に切り替える手間
  - メールに URL が入るぶん長くなる
  - 押した人の端末から Google に場所が渡る（メールを転送すると自宅の位置も渡る）
- 捨てた案：出し方B はキーを公開リポジトリ・静的サイトに置けず、費用と利用者のデータを Google へ送る点で PRD §4・§7 を大きく変える。C は住所を打ち直す手間が残る（要望の中心）。経由地B は4件目以降が抜ける・開かない
- 見直す条件：実機（iPhone・Android の Google マップのアプリとブラウザ、PC のブラウザ）で経由地の上限・公共交通の扱いを確かめ、`MAPS_MOBILE_WAYPOINTS`・`MAPS_URL_LIMIT` を見直す。全行程の本数が多くて使いにくい声が出たら PC で開く場面だけ上限を9にする。アプリ内で Google の時間・距離が要るなら別の ADR で API とキーの置き場（サーバー）を考える

## 影響
- 主なモジュール：`lib/mapsLink`・`lib/mail`・`components/mapsLinks`、スタッフ画面・日の画面
- PRD §4 に Google Maps Platform とは別物である旨、§7 に道順のリンクは外部送信に当たらない旨
