# ADR-0009：日の予定の編集と割当の手直しを1画面（日の予定）にまとめる

- 日付：2026-10-13
- 状態：採用（AI で組む操作は ADR-0063 で「予定を組む」の画面へ移った）
- 関連：PRD D4

## 背景
「予定」と「AI案」の2つの画面があり、どちらもその日の訪問を担当ごとの列に並べて、ドラッグで担当を移せた。

- 同じ日の割当を2か所で触れ、どちらが正なのか分かりにくかった
- 予定の画面には、地図の担当の絞り込み・区間の強調・点の理由・浮かせた地図が無かった
- 比較の画面の地図は押したときの挙動が予定の画面と違った

## 選択肢
1. 案A：1画面に統合する（AI案の画面を土台に、訪問の一覧を足す）
2. 案B：1つの画面の中でタブ（訪問の一覧／割当）を切り替える
3. 案C：統合しない（文言・リンクだけ直す）

## 決定
案A。画面の名前は「予定」（`#/plan`）。古いリンクの `#/schedule` はそこへ移す。

- 訪問の編集・取り消しと、担当の手直し（ドラッグ）、確定、地図・理由を同じ画面で扱う
- 訪問を押したときは理由だけを出す。担当を変えるのはドラッグ（か担当を変えるメニュー）
- 担当ごとの列の見出しの下に、その日の稼働時間帯と「この日だけ変更」を出す。列の最後に「自宅まで N分」（帰りの区間。押すと地図で強調）を出す
- 「入らなかった訪問」を未割当の列とし、ドラッグ中は（0件でも）出してドロップ先にする。落とすと担当と固定が外れる
- 担当ごとの順番と地図の部品（`lib/routeView.ts`・`components/routeView.tsx`）は予定と比較で共通にし、地図の押したときの挙動を同じにする

## 理由とトレードオフ
- 得るもの：割当を触る場所が1つになる。訪問の編集と、地図・理由を見ながらの手直しを同じ画面でできる。比較と予定で地図の操作が同じになり、コードの重複も減る
- 失うもの：
  - 画面が縦に長くなる
  - 休み・休止中の人の列は出さないので、休みの人へはドラッグで移せない
  - ドラッグ中の予告は必須の条件に合わないことだけ。時間の約束・稼働時間帯に収まらないは、移したあとに必須の違反として赤い枠と印で出る

## 影響
- 画面の詳細は design/pages-plan.md
- 見直す条件：AI を使わずに担当を決めたいという声が多いとき
