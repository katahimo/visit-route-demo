# ADR-0059：日のメールを作ったら確定にし、区間ごとの道順を残す。週のメールは見通しで確定にしない

- 日付：2026-10-23
- 状態：採用
- 関連：PRD D346、ADR-0017（メール連携）・ADR-0018（道順のリンク）・ADR-0053（提案→反映→確定）

## 背景
- 「確定（伝えた）」は〈スタッフ〉に伝えた内容を残す操作で、AI で組み直さない守りと「未連絡の変更」（伝え直す一覧）の元になる（ADR-0053）
- 「組む → メールで送る → 確定を押す」の3手では、送ったあとに確定を押し忘れやすい
- 日のメールの区間ごとの道順は、URL の長さの目安（Windows・不明な端末 2000字。D96）を超えると最初に外していた。初期データでは訪問3件の日でも外れた
- 週のメールは確定していない日ごとに「（まだ確定していません）」と書き、読みにくかった

## 選択肢
1. 案A：確定は手で押す
2. 案B：日のメールを全員分作ったら、その日を確定にする（週のメールは見通しで確定にしない）。手の「確定」は残す
3. 案C：週のメールを送ったら、その週を全部確定にする

## 決定
案B。
- 日のメールの欄：送れる人（アドレスがあり `tooLong` でない）の「メールを作る」を全員分押したら、1回だけ確定する（`PlanPage` の `confirmByMail`。確認は出さず、知らせに「元に戻す」）。アプリは送信を知れないので、メールアプリを開いたことで数える。アドレスの無い人に電話で伝えたときなどのため、欄の下に「確定（伝えた）にする」も残す
- 週のメールは見通し。送っても確定にしない。確定していない日があれば冒頭に1回だけ書く
- 日のメールの本文は、区間ごとの道順を残す段を先に試す（要点・全行程・区間の短い行の順に削り、最後に区間を外した段）。短い段は冒頭と省略の知らせも短くする
- 日・週のメールのボタンは見出しの下のナビの行の右（ADR-0060）。週はどの表示でも出す

## 理由とトレードオフ
- 得るもの：送ったことがそのまま確定になり押し忘れが減る。伝える手順が「週で見通し → 前日に日のメールで確定」の2段になり、現場の運用に近い。Windows の PC でも区間ごとの道順が届く
- 失うもの：メールアプリを開いただけで送らなかったときも確定になる（知らせの「元に戻す」で戻す）。区間を残す段では住所・決まりごとが本文から外れる（「本文をコピー」には全部入る）
- 案C は週の途中の欠勤・キャンセルでほとんどの日が「未連絡の変更」になり、伝え直しの一覧が増えるので取らない

## 影響

- 見直す条件：メールの送信をアプリが知れるようになったら（サーバーから送るなど）、作ったでなく送ったで数える
