# ADR-0015：退職・担当替えの一括振り直し、稼働の見込み（拘束・交通費）、〈利用者さん〉の段階、当日キャンセルの印

- 日付：2026-10-17
- 状態：採用
- 関連：ADR-0011・0014・0053

## 背景
退職者の担当の組み直し、拘束時間と交通費の計算、案件の段階の管理、当日キャンセルの記録が別のツールや手作業だった。

## 決定
- 最終勤務日：`staffSchema.lastDay`。`availabilityOf` は翌日から（上書きがあっても）空。compile は `AFTER_LAST_DAY` で外す。先の予定は勝手に作り直さず「担当が休み」の要対応にする
- 振り直し（`lib/offboard`）：
  - 範囲：`from`（最終勤務日の翌日、今日より前なら今日）以降のその人の訪問と、その人を繰り返しの担当・担当できる人にしている〈利用者さん〉。どちらでもないが `from` 以降の訪問の担当がその人の〈利用者さん〉も「訪問の担当」として入れる（範囲の訪問はどれも、その〈利用者さん〉で代わりを選べば適用で替わる）
  - 候補：`from` から28日の訪問ごとに、その人が担当できる人に入っている〈利用者さん〉だけ担当を限る決まりを外して（入っていなければ決まりのまま。担当できる人で持っていなければ、その人が担当の回だけ数える）他の人を変えず入れられる人（`fitsOf`）を数え、入る回の多い順 → 受け持ちの少ない順 → 名前
  - 適用（`applyOffboard`）：`from` より前から続く繰り返しは `splitPattern` で分け、担当できる人に代わりを足す。`from` より前の担当は変えない。分けた回は ID を付け替えて記録を引き継ぐ
- 稼働の見込み（`lib/workload`・`#/workload`）：拘束＝最後の終わり−最初の開始。自宅との行き帰りは拘束に入れず、距離（直線の概算）と交通費（距離×単価、日ごとに四捨五入）には入れる。「予定からの見込みで実績ではない」と書く
- 拘束の上限：`orgSchema.spanLimitHours`（0〜24・既定10・0＝注意しない）。超える日は「拘束超」の注意だけ。AI の条件にはしない
- 段階：`clientSchema.stage`（相談受付・顔合わせ・契約・利用中・終了）。`stageFlags` が active・tentative を決める。古いデータは `stageOfLegacy`
- 紹介元：`clientSchema.referrer`（名前・連絡先・メモ）
- 当日キャンセル：`visitSchema.cancelKind: 'sameDay' | null`。取り消すとき選び、件数を月間・〈利用者さん〉に出す

## 捨てた案
最終勤務日に休止にする予約（予定全体の対象外になる）・適用と同時に先の案を作り直す（意図しない変更）・拘束を条件の型にする。

## トレードオフ
- 失うもの：最終勤務日の後の担当は人が振り直すまで要対応に残る。拘束の上限は AI の案で超えうる。実働の上限は見ない
- 見直す条件：拘束の長い案が続いて困る声。返答待ちを段階で数えたい声
