# ADR-0015：退職・担当替えの一括振り直し、稼働の見込み（拘束・交通費）、〈利用者さん〉の段階、当日キャンセルの印

- 日付：2026-10-17
- 状態：採用
- 関連：PRD D71〜D74・D170、ADR-0011・0013・0014、ADR-0025（当日キャンセルの入口）、ADR-0053（担当は訪問に持つ）

## 背景
訪問介護・移動支援の事業所（正社員8名・利用者約20名・直行直帰）のヒアリングで、ADR-0013・0014 のあとに残った困りごと。
1. 退職者が出ると、その人がいつもの担当・定期パターンの担当になっている利用者の組み直しに時間がかかる
2. 拘束10時間の日もあるが実働は8時間以内（休憩は移動に含める運用）。拘束・実働の記録が無く、交通費（距離×10円/km）は自作の表計算で出している
3. 案件は紹介元の相談員を通して「相談受付→返答待ち→顔合わせ/契約→利用中」を別のツールで管理している。〈利用者さん〉は「利用中／休止」と「仮押さえ」しか持たない
4. 当日キャンセルもふつうにあるが、取り消しの種類を残していない

決めること：最終勤務日の持ち方、振り直しの候補と適用の範囲、稼働の見込みの数え方、拘束の上限の扱い、段階と active・tentative の関係、当日キャンセルの持ち方。

## 選択肢
- 最終勤務日：A `lastDay` ＋ `availabilityOf` が翌日から空／B その日に休止にする予約／C 後の日ごとに稼働の上書き（空）
- 振り直し：A 候補を出し選んで適用（先の予定は勝手に作り直さない）／B 適用と同時に先の案を作り直す／C いつもの担当をその場で書き換える
- 拘束：A 最初の開始〜最後の終わり（直行直帰）／B 自宅を出てから帰るまで
- 上限：A 設定値で注意だけ／B 条件の型「拘束」で AI に効かせる
- 段階：A `stage` を足し active・tentative を合わせる／B stage だけにする
- キャンセル：A `cancelKind`／B メモの文で見分ける

## 決定
最終勤務日は〈スタッフ〉に持ち稼働時間の1か所で効かせる。振り直しは候補を出して選ばせる。拘束の上限は注意だけ。段階を正にして active を合わせる。当日キャンセルは訪問に種類を持つ。

- 最終勤務日：`staffSchema.lastDay`（null＝なし）。`availabilityOf` は最終勤務日の後なら（上書きがあっても）空。compile は理由 `AFTER_LAST_DAY`（ruleId 'slot'）で外す。稼働時間を読む所はすべて `availabilityOf` を通るので1か所で効く。先の予定は勝手に作り直さず、後のその人の担当の訪問は「担当が休み」の要対応になる。担当できる人（ADR-0014）はその人だけに限った利用者さんを黙って「限らない」にせず、入らなくなるので振り直しを促す
- 振り直し（`lib/offboard`）：
  - 範囲：数え始める日 `from`（最終勤務日の翌日。今日より前なら今日）以降にその人が担当する訪問と、その人を繰り返しの担当・担当できる人にしている利用者さん（終了の人は除く）
  - 候補：`from` から28日の訪問ごとに、担当を限る決まりを外した問題で、その日の担当の並びに他の人を変えず入れられる人（`fitsOf`）を数え、入れる回の多い順 → 受け持ちの少ない順 → 名前
  - 適用（`applyOffboard`）：`from` から受け持ちを移す。`from` より前から続く繰り返しは `splitPattern` で分け（前はその人、後ろは代わり）、〈利用者さん〉の担当できる人には代わりを足す。`from` より前の日の担当は変えない。分けた繰り返しの回は ID を付け替えて、伝えた内容などの記録を引き継ぐ
  - 確認の文に、付け替える回の数と、「だれにもしない」で担当を限らなくなる利用者さんを出す
- 稼働の見込み（`lib/workload`・`#/workload`）：拘束＝最後の終わり−最初の開始（訪問＋移動＋待ち）。直行直帰なので自宅との行き帰りは拘束に入れず、距離（直線距離の概算）と交通費（距離×単価を日ごとに四捨五入）には入れる。拘束は分に丸めてから上限と比べる。「予定からの見込みで、実績ではない」と書く。Excel の「稼働の見込み」シートは書き出すだけ
- 拘束の上限：`orgSchema.spanLimitHours`（0〜24・0.5刻み・既定10。0＝注意しない）。超える日は月間に「拘束超」・要対応に名前、日の画面に帯。手当てが必要（赤）には数えない。AI の条件にはしない
- 段階：`clientSchema.stage`（相談受付・顔合わせ・契約・利用中・終了）。`stageFlags` が active・tentative を決め、`repair` と画面が合わせる。予定・AI で組むの対象を読む所は従来どおり active だけを見る。古いデータは `stageOfLegacy`
- 紹介元：`clientSchema.referrer`（名前・連絡先・メモ）。「返答待ち」は段階にせず紹介元のメモに書く
- 当日キャンセル：`visitSchema.cancelKind: 'sameDay' | null`。取り消すとき欄（ふつう／当日キャンセル）で選ぶ。取り消していない訪問は `repair` が null にする。月間に件数、〈利用者さん〉に「うち当日キャンセル」。取り消し方・数え方は変えず、空いた時間へ入れ直す計算は足さない。入口は訪問の取り消しと「欠勤・キャンセル」の「〈利用者さん〉がキャンセル」（PRD D170）
- Excel の新しい列・行はどれも任意

## 理由とトレードオフ
- 得るもの：最終勤務日の後は1か所で勤務なしになり、画面ごとに辞めた人を数え分けなくてよい。退職者のぶんを利用者さんごとに1つの表で選んでまとめて置き換えられ、先の予定は知らないうちに変わらない。拘束・移動・待ち・交通費が予定から自動で出る。`stage` は読む所を変えずに古いデータも読める
- 失うもの：
  - 最終勤務日の後の担当は、人が振り直すまで要対応として残る
  - 担当できる人に代わりを足すと `from` より前の日にも担当できるようになる
  - 同じ人を何人もの代わりに選ぶと入りきらないことがある。見本の期間は28日で、それより先は見ない
  - 拘束の上限は注意だけで、AI の案が超えることがある。実働の上限は見ない。移動の時間・距離は直線距離の概算
  - 段階ごとの期日・やることは持たない（二重に持つ）。当日キャンセルは回数のみ（請求・集金・連絡はしない）
- 捨てた案：最終勤務日B は休止が予定全体の対象外になる。C は日数分のデータ・期間の延長に弱い。振り直しB は意図しない変更、C は最終勤務日より前の日の担当も変わる。拘束B は直行直帰の運用に合わない。キャンセルB は数えられない
- 見直す条件：拘束の長い案が続いて困る声（上限B）。実働の上限を見たい声。返答待ちを段階として数えたい声（段階を足す。版は変えない）
