# ADR-0054：予定の日・週・月を共通の部品に寄せ、人の画面をタブにまとめ、範囲の AI を提案にし、元に戻すを全体で1本にする

- 日付：2026-10-22
- 状態：採用（メニューの並びと AI を使う入口は ADR-0063・ADR-0064）
- 関連：PRD D326〜D332、ADR-0053（担当は訪問に持つ）・ADR-0030（担当を変える ▾）・ADR-0042（月まとめを画面の外で）・ADR-0047（人の画面の並び）・ADR-0063（予定を組む）

## 背景
- 日・週・月は同じ `visitsOn` と `DayStatus`（`useDayStatuses`）を読むのに、画面が別々に育っていた：操作の行の並び、AI で組む操作の形（日は提案、週・月は組みながら訪問に書く）、元に戻す（画面ごとに別の控え）、進み具合の帯が日・週・月に出て主ボタンと重なる
- メニューが9項目あり、人の4画面（〈利用者さん〉・〈スタッフ〉・相性・勤務時間）が別々だった
- 複数の訪問をまとめて動かす・替える手段が無かった

## 選択肢

### 「人」のまとめ方
1. 案A：人の入口の画面（カードから選ぶ）を新しく作る
2. 案B：4画面の見出しの下に共通のタブ（設定のタブと同じ形）を置き、メニューは「人」1項目で最後に開いたタブを開く

### 日・週・月のまとめ方
1. 案A：1つのコンポーネント（拡大率を props）に作り直す
2. 案B：共通の部品（操作の行・提案の帯・複数選択の帯・元に戻す）を取り出して3画面で使い、本体（時間軸・表・カレンダー）は今の画面に残す

### 範囲の AI
1. 案A：週・月は組みながら訪問に書く
2. 案B：範囲の提案を出し、同じ形の提案の帯で［反映する］（画面の外の計算 `lib/monthBatch` のまま、書かずに日ごとの差を持つ）

### 元に戻す
1. 案A：画面ごとの控え
2. 案B：store の `update` を1回ごとに履歴に積み、どこからでも同じ「元に戻す・やり直す」

## 決定
すべて案B。

### 人のタブ
- 「人」は〈利用者さん〉・〈スタッフ〉・相性・勤務時間（シフト）の画面を受け持ち、押すと最後に開いた人のタブ（既定は〈利用者さん〉）。タブは `PeopleTabs`（設定のタブと同じ `TabNav`）。一覧の見出しの「相性の表」の文字ボタンは消した（タブと重なる）

### 予定の共通の部品（`components/scheduleParts.tsx`）
- `ScheduleToolbar`：欠勤・キャンセルを登録／元に戻す・やり直す（`UndoButtons`）／表示の切り替え／その他 ▾。日・週・月とも同じ並び
- `ProposalBand`：「提案：担当が変わる N件・時刻が変わる M件・点 a→b」と［反映する］［捨てる］、差の一覧（畳む）。範囲の提案（`RangeProposalBand`：`monthBatch.proposal`）を日・週・月の予定と担当を組むに同じ形で出す
- `SelectionBar`・`useVisitSelection`：日の予定・週の時間軸の帯で、Shift・Ctrl（mac は ⌘）＋クリック、帯で Shift／Ctrl＋Enter で選ぶ・外す。下に貼り付く帯で「担当を替える ▾」「時刻をずらす」「取り消す」「選択を外す」。どれも「この回だけ」（`lib/multiEdit`）で1回の update。できなかった訪問は知らせに理由
- 進み具合の帯（`ProgressBand`）は月の予定だけ。週は確定の状況の1行、日は見出しの状態の印と「今の担当」の1行

### 範囲の提案（`lib/monthBatch`）
- 1日ずつ組み、日ごとに組み始めたときの訪問・提案の担当の並び・差を持つ。訪問には書かない。終わると提案と知らせ
- 「反映する」は、今のデータで組み始めたときのままの日（訪問が同じ・その日の問題の入力が同じ・伝えていない。`proposalDayFresh`）だけを1回の update で書く。変わった日は当てずに件数を知らせる。新しく組み始める・データを丸ごと差し替えると提案は消える。反映していない提案があるまま新しく組み始めるときだけ確認する
- 画面を移っても組みの計算と提案は残る（モジュールの入れ物）。保存はせず、読み直すと消える

### 全体の元に戻す（`lib/history`・`store/react.tsx`・`components/undo.tsx`）
- store の `update(fn, label?, opts?)` の1回を1手として積む（StrictMode・描き直しで2回呼ばれても1手）。`opts.group` が同じ続けての update は1手、`opts.history: false` は戻せない操作で積まずに履歴を捨てる。手には名前を付ける。最大50手。画面の状態だけ（保存しない）。読み込み・初期化・直前の状態に戻す・別のタブの変更（丸ごと差し替え）で捨てる
- 戻す・やり直す：トーストの「元に戻す」、予定の操作の行、Ctrl+Z（⌘Z）・Ctrl+Shift+Z（Ctrl+Y）。入力欄の中と、確認・引き出し・パレットが開いている間はキーを奪わない（`historyKeysOn`）
- 欠勤の「振り直す前に戻す」：欠勤の登録と振り直しを別の手にし、直前の手がこの日の振り直しでそのあと変わっていなければ全体の「元に戻す」で1手戻す（欠勤は残る）。それ以外は確認して振り直す前の担当・ピンに戻す手を積む（`revertReassign`）
- 複数選択の帯は、書くときに store の最新のデータへ当て直す（確認の間の別のタブの変更を消さない）
- データの画面の「直前の状態に戻す」（読み込み・初期化の前の1世代の控え。ADR-0032）は別のまま

## 理由とトレードオフ
- 得るもの：
  - 日・週・月のどれでも同じ操作の行・同じ提案の帯・同じ元に戻すで、手が同じ。範囲の AI も反映する前に差を見られる
  - 元に戻すが1か所（50手）になり、画面ごとの控えと「戻せない」の理由の多くが消えた。手の名前が出るので何が戻るかが分かる
  - 人の4画面をタブで行き来できる。複数の訪問をまとめて替える・ずらす・取り消すが1手でできる
- 失うもの：
  - 範囲の AI は［反映する］まで訪問に書かない（1手増える）。組んでいる途中で止めても、反映するまでは変わらない
  - 日・週の進み具合の帯（月の予定とホームだけで見る）
  - 全体を1つのコンポーネントにはしていない（本体は3画面のまま）。複数選択は月・表・一覧の表示では使えない
  - 元に戻すの履歴は保存しない（読み直すと消える）。50手を超えると戻せない
