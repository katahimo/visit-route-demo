# ADR-0054：予定の日・週・月を共通の部品に寄せ、範囲の AI を提案にし、元に戻すを全体で1本にする

- 日付：2026-10-22
- 状態：採用（人のタブとメニューは ADR-0067・0074、進み具合の帯は ADR-0074 で「詳しく ▾」へ）
- 関連：ADR-0030・0042・0053

## 背景
日・週・月が別々に育ち、操作の行・AI で組む形・元に戻すが画面ごとに違った。複数の訪問をまとめて動かす手段も無かった。

## 決定
### 予定の共通の部品（`components/scheduleParts.tsx`）
- `ProposalBand`：「担当が変わる N件・時刻が変わる M件・点 a→b」と［反映する］［捨てる］、差の一覧（畳む）。範囲の提案（`RangeProposalBand`）も同じ形
- `SelectionBar`・`useVisitSelection`：Shift・Ctrl（⌘）＋クリック、Shift／Ctrl＋Enter で選ぶ。帯で「担当を替える ▾」「時刻をずらす」「取り消す」「選択を外す」。どれも「この回だけ」（`lib/multiEdit`）で1回の update。書くときに store の最新のデータへ当て直す
- 本体（時間軸・表・カレンダー）は画面ごとに残す

### 範囲の提案（`lib/monthBatch`）
- 1日ずつ組み、日ごとに組み始めたときの訪問・提案・差を持つ。訪問には書かない
- 「反映する」は組み始めたときのままの日（`proposalDayFresh`）だけを1回の update で書き、変わった日は件数を知らせる。反映していない提案があるまま組み始めるときだけ確認
- 画面を移っても残り、保存はしない

### 全体の元に戻す（`lib/history`・`store/react.tsx`・`components/undo.tsx`）
- store の `update(fn, label?, opts?)` の1回を1手として積む（StrictMode で2回呼ばれても1手）。`opts.group` が同じなら1手、`opts.history: false` は積まずに履歴を捨てる。手に名前を付ける。最大50手。保存しない。丸ごとの差し替えで捨てる
- トーストの「元に戻す」・操作の行・Ctrl+Z（⌘Z）・Ctrl+Shift+Z（Ctrl+Y）。入力欄の中と、確認・引き出し・パレットが開いている間はキーを奪わない（`historyKeysOn`）
- 欠勤の「振り直す前に戻す」：登録と振り直しを別の手にし、直前の手がこの日の振り直しなら全体の元に戻すで1手。それ以外は確認して前の担当に戻す手を積む（`revertReassign`）
- データの画面の「直前の状態に戻す」（ADR-0032）は別のまま

## 捨てた案
1つのコンポーネントに作り直す（画面ごとの違いで分岐だらけ）・週・月は組みながら訪問に書く（差を見られない）・画面ごとの控え。

## トレードオフ
- 失うもの：範囲の AI は反映まで書かない（1手増える）。複数選択は月・表では使えない（ADR-0056 で広げた）。履歴は読み直すと消える
- 見直す条件：50手で足りない・保存したい声
