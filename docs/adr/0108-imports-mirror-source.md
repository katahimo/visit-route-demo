# ADR-0108：ファイルの読み込みは総入れ替え（予約システム・カレンダーを写す）

- 日付：2026-11-07
- 状態：採用
- 関連：ADR-0020・0068・0075・0090・0107

## 背景
予約は予約システム（Reserva）が持ち、このアプリはその書き出し（CSV）を読む。今の予約の CSV の読み込みは「足す・直す」だけで、ファイルに無い訪問は消さず、キャンセルの予約は取り消しの訪問として残る。予約システムで消した・キャンセルした予約をアプリから消せない。休みのカレンダー（ADR-0107）も、手で入れた欠勤を残すので写しにならない。利用者の要望は「各種 CSV は基本総入れ替え、予約システムをミラーリングしたい」。

## 選択肢
1. 案A：予約の CSV は、ファイルの最初の日〜最後の日の単発の訪問をファイルに合わせる（範囲の外は変えない）
2. 案B：予約の CSV は、単発の訪問すべてをファイルに合わせる
3. 案C：今のまま足す・直すだけにし、消すのは手で

## 決定
案A。
- 予約の CSV（予約システムの形・このアプリの予定の CSV・ほかの形すべて）：ファイルの最初の日〜最後の日（取り消しの行も含めた日付）の単発の訪問のうち、ファイルに無いものと、状況がキャンセルの予約の訪問を消す。繰り返しの回は消さない。入れなかった行（名前が無い・同じ名前が2人など）が指す訪問は残す（読めないだけで消さない）。確認と知らせに「削除 N件」。結果の型 `BookingImportResult` に `removed` を足す
- 名簿：読み込み方の既定を「総入れ替え」にする（ファイルに無い人は消さず休止・終了。今の総入れ替えのまま）。「追加・更新」は残す
- 休みのカレンダー：当たった〈スタッフ〉の今日から93日の欠勤を、手で入れたものも含めてカレンダーの内容に入れ替える。チェックで選ばず全部入れ替える。勤務の無い日の休みは入れない

## 理由とトレードオフ
- 得るもの：予約システム・カレンダーで消した・キャンセルした予約や休みがアプリからも消え、二重に直す手間が無くなる
- 失うもの：アプリで足した単発の訪問・手で入れた欠勤は、読み込むと範囲の中では消える（予約システム・カレンダーに入れる）。キャンセルの訪問を残さないので、当日キャンセルの月の件数（D74）は予約システムで見る。間違ったファイルを読むと多く消える（確認の件数と、元に戻す・1世代の控えで戻す）
- 案B を捨てた理由：期間を区切って書き出したファイルで、期間の外の予約まで消える
- 案C を捨てた理由：要望に合わない

## 影響
- PRD D441（D104・D408・D440 を直した）
- 見直す条件：範囲の端の日（ファイルの最初・最後の日の外）に消し残りが出て困るとき（書き出しの期間を指定して読む）
