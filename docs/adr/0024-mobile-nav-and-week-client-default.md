# ADR-0024：スマホは上の帯・引き出し・下のタブでメニューを出し、週の時間軸の〈利用者さん〉は先頭8人を初期値にする

- 日付：2026-10-18
- 状態：採用（下のタブの項目・メニューの並びは ADR-0045・0054・0063）
- 関連：PRD D132〜D140、ADR-0021（表の絞り込み）、ADR-0033（狭い画面の表）

## 1. スマホのメニュー

### 背景
狭い画面（幅860px以下）では左のメニューが上に横一列で並び、項目が多くて巻かないと見えず、グループの見出しを隠すので同名の項目も見分けられなかった。右下の地図・左下の帯・トーストは画面の下端からの位置を CSS の変数で避け合っている。端末の前提は「管理者役は PC、スマホは表示の確認」（PRD §7）。

### 選択肢
1. 案A：上の帯に今の画面の名前と「メニュー」、左から出る引き出しに全メニュー、下によく使う画面のタブ
2. 案B：横一列のまま見出しだけ出す（巻くのが残る）
3. 案C：下のタブだけにして残りは「その他」（「その他」がもう1枚の画面になり、見出しの問題が残る）

### 決定
案A。上の帯に今の画面の名前（グループの見出し＋項目名）、引き出し（dialog。全メニューを縦に並べる）、下のタブ（よく使う画面・探す・メニューのボタン）を置く。広い画面は変えない。

- 今の画面をどの項目と見るか・上の帯の名前・下のタブの選び方は `lib/nav.ts` の1か所で決める（左のメニュー・引き出し・パレットも同じ元から引く）。引き出しは `app/NavDrawer.tsx`
- 今の画面の項目・タブを押し直しても移り直さない（URL のクエリ＝画面の状態を消さない）
- 引き出しは `SidePanel` と同じ閉じ込め・フォーカスの戻し方で、裏のロックは数を数える `lib/scrollLock` にまとめる（右の欄と重なっても最後の1つまで戻さない）
- 下のタブの高さは `--bottom-tabs-h` にし、浮いている部品・本文の下の余白・トーストはこの変数で避ける。safe-area（`viewport-fit=cover`）も避ける
- 印刷では下のタブ・引き出し・上の帯（用紙が860px以下のとき）を出さない
- データ・契約・URL は変えない

### 理由とトレードオフ
- 得るもの：巻かずに全メニューへ（2手）、よく使う画面は1手。広い画面は変わらない
- 失うもの：上の帯が2段になることがあり、下のタブのぶん本文が狭くなる。項目が2か所に描かれる（同じ部品 `NavGroups`）
- 見直す条件：下のタブの項目はデモの反応で入れ替える。スマホで予定を直す使い方が増えたら、画面の中身のスマホ向けの作りを別に決める

## 2. 週の時間軸「〈利用者さん〉で見る」の初期値

### 背景
時間軸の「〈利用者さん〉で見る」は、検索欄で人を選ぶ（8人まで・`?client=`。PRD D61・D62）。選んでいないと空で、開くたびに選び直す手間がかかった。〈スタッフ〉で見るときは全員が出るので、見る人によって操作が違った。

### 決定
この週に訪問がある人をチップで並べ（表の既定と同じ人・同じ順）、`?client=` が無ければ先頭8人を初期値にする（URL に書かない。週を送るとその週の人になる）。検索欄は「ほかの人を探す」に畳んで残す。表から移るときは、`?client=` があればそれ、無ければ表で絞り込んだ先頭8人、絞り込んでいなければこの週の先頭8人。

- 決まりは `lib/timelineClients.ts` の1か所。チップは〈スタッフ〉と同じ `PickChips`
- 選んでいる人と上から2行ぶんだけ出し、残りは「あと N人」で畳む（PRD D140。`lib/fold`）。選んでいる人は動かさない

### 理由とトレードオフ
- 得るもの：開いたらすぐ帯が見え、〈スタッフ〉と同じ操作。引き継ぎと初期値が1つの決まりになる
- 捨てた案：初期値を URL に書く（週を送ると前の週の人が残る）／検索欄のまま初期値だけ先頭8人（〈スタッフ〉と操作がそろわない）
- 失うもの：「全部外す」のあとは週を送っても空のまま。訪問のある人が多いとチップが長くなる
- 見直す条件：訪問のある人が数十人の事業所でチップが長すぎれば、チップも絞り込みか「もっと見る」で畳む

## 影響
`lib/nav.ts`・`app/NavDrawer.tsx`・`lib/scrollLock`・`lib/timelineClients.ts`・`lib/fold`・週の画面。データ・契約は変えない。
