# ADR-0122：更新のときに前のデータを自動で控え、設定のひな形のリンクを3ステップの手順にする

- 日付：2026-11-22
- 状態：採用
- 関連：ADR-0026・0032・0102・0113・0121。PRD D480・D483〜D488

## 背景
顧客はデータをブラウザの localStorage に持つ。公開版を更新すると、次に開いたとき「デモを更新しました」（ADR-0102）が出るが、
更新の前に控えを取ってもらう術は無かった。設定のひな形のリンク（ADR-0121）を、更新のあとに顧客に最初にしてもらう手順にしたい。
それには、リンクを開いたときに更新の画面と確認のダイアログが続けて出るのではなく、控え → 変わる設定 → 適用が1枚で分かる形が要る。

## 選択肢
更新前の控えの置き場所：
1. 案A：1世代の控え（ADR-0032 の `vrdemo:data:prev`・`…:prev:info`）に置き、情報に更新の id を足す（`release`。省略可）
2. 案B：別のキー（`vrdemo:data:release-prev`）にもう1つ控えを持つ
3. 案C：DemoData の中に持つ

手順の画面：
1. 案D：独自の確認ダイアログの殻（ADR-0026）に、①控え ②変わる設定 ③［適用］を1枚で出す
2. 案E：確認ダイアログを3回続けて出す
3. 案F：最初の2問の画面（ADR-0102）の部品で全画面にする

## 決定
- 置き場所は 案B（最初は 案A で作ったが、レビューで直した。下の「直したこと」）。開いたとき（`store/persist` の `loadWithStatus`）、保存データが読め、
  まだ見ていない更新がある（`vrdemo:release:seen` と比べて知らせる更新がある）なら、画面を出す前に**読んだ元の文字のまま**（migrate・repair の前）を
  `vrdemo:data:release-prev` に、`{ at, release }`（時刻・今の更新の id）を `vrdemo:data:release-prev:info` に書く（`store/releaseBackup` の `keepBeforeRelease`）。
  1世代の控え（`vrdemo:data:prev`）には触らない。同じ更新の控えがもうあれば残し直さない（読み直し・2つ目のタブで時刻を変えない）。
  前の更新の控えは次の更新の控えで置き換える（更新前の控えも1つだけ）。リンクで開いても普通に開いても同じ
- 容量：書けなければ古い更新前の控えを捨てて1回だけ試し直し、それでも書けなければ古い控えを書き戻して、控えなしで理由を返す。
  今のデータ（`vrdemo:data`）と1世代の控えには触らない。結果（残した時刻か理由）は store の `releaseBackup` で画面に渡し、
  「デモを更新しました」の画面と手順の画面の①に出す（①は今のキーに控えがまだあるときだけ時刻を出す）。
  本体の保存が容量超過のときは、1世代の控え → 更新前の控えの順に捨てて今のデータを書く（今のデータが先。ADR-0032。捨てたら知らせる）
- 1世代の控えの `keepPrevious` も、書けなかったときは前の世代を書き戻す（`cancel` を呼ばなくても前の控えを失わない。`swapPrevious` と同じ）
- 更新の画面で「デモで試す」「自分のデータで始める」を選んだとき：今のデータが更新前の控えと同じ（`releaseBackupHolds`。控えを migrate・repair して比べる）なら
  1世代の控えには残さない（前からある控えを上書きしない）。違えば（別のタブで直した・更新前の控えを残せなかった）今のデータを1世代の控えに残してから作り直す
- データの画面：2つの控えを別のカードで出す。「直前の状態に戻す」（1世代の控え。今のまま）と、更新前の控えがあれば
  「更新前の控え（11月21日の更新の前・14時03分）」・［この控えに戻す］・［この控えを書き出す］（元の文字のまま `staff-assign-demo-<控えの日>-release.json`。
  直前の状態の控えは `…-previous.json`）。［この控えに戻す］（確認つき）は、元の文字を今の読み込みと同じく migrate・repair に通し、
  いまのデータを1世代の控え（操作の名前「更新前の控えに戻す」）に残してから戻す。残せなければ戻さない。**更新前の控えは戻したあとも残す**
  （入れ替えない）。確認の本文に、今ある直前の状態の控えが置き換わることを書く
- 手順の画面は 案D（`components/SettingSetSteps`。殻は `components/DialogShell` に分け、確認ダイアログと共用）。
  見出し「設定のひな形「…」を適用します」、① データの控え（「更新前の控えを自動で残しました（◯時◯分）。適用の前に、今のデータの控えを
  ファイルに書き出してください。」と［控えをファイルに書き出す］＝データの画面の「ファイルに書き出す」と同じファイル）、② 変わる設定
  （今 → 適用後。ADR-0121 の一覧のまま）、③［取り消す］［適用］。書き出すまで［適用］は押せず「① で控えをファイルに書き出すと［適用］を
  押せます」を添える。文と判定は `lib/settingSets` の `settingSetBackupStep`
- リンク（`#/settings?apply=…`）で開き、手順の画面を出すとき（知っている ID で変わる項目がある。`lib/settingSets` の `settingSetLinkPlan`。
  手順の画面の判定と同じ関数）は「デモを更新しました」を出さず見たことにし（`FirstRunGate`）、手順の画面に
  「デモを更新しました。」と畳んだ［変わったことを見る］（開いたときにまだ見ていなかった更新の一覧）だけを出す
- 保存データが無い人がリンクを開いたときは、最初の2問のあと最初の画面ではなく同じリンクへ進み、手順の画面を出す。
  作ったばかりのデータ（このタブで2問に答えて作った）なので①は「控えは要りません」とし、書き出しを求めない
- すでに同じ設定なら「すでにこの設定です」で手順の画面を出さない（書き出しも求めない）。知らない ID と、適用のあとの［元に戻す］は今のまま。
  どちらも手順の画面を出さないので、更新を見たことにせず、いつもの「デモを更新しました」を出す（答えたあとにリンクの知らせ）
- データの版（DATA_VERSION）は上げない。データ（DemoData）に欄は足さない（控えはブラウザの別のキー）

## 直したこと（レビュー。2026-11-23）
- 案A では、開いただけで前からある1世代の控え（初期状態に戻す・読み込み・最初の設定をやり直すの前）を今のデータで上書きした。
  うっかり初期状態に戻した人の本物のデータが控えにしか無いとき、それが消える。→ 案B に変えた
- 容量不足のとき、1世代の控えを2回消し、取り消しも呼ばないので、前の控えを消したうえで「データはそのままです」と出ていた。
  → 更新前の控えは別のキーなので、書けなければそのキーだけ諦める。`keepPrevious` も書けなければ前の世代を書き戻す
- 更新の知らせを出したまま別のタブで直したあと、このタブで作り直すと、控えが開いたときの古い中身のままで、別のタブで直した分が残らなかった。
  → 今のデータが更新前の控えと違えば1世代の控えに残す
- 更新前の控えが migrate・repair を通したあとのデータだった。→ 読んだ元の文字のまま残す（戻すときに通す）
- 知らない ID・すでに同じ設定のリンクでも更新を見たことにし、「デモを更新しました」も控えの知らせも出なかった。→ 手順の画面を出すときだけ見たことにする

## 理由とトレードオフ
- 得るもの：更新のたびに、顧客が何もしなくても更新の前のデータが端末に1つ残り、データの画面から戻せる。前からある1世代の控えも消えない。
  リンクを開いた顧客は、控えのファイルを手元に残してから設定を変える流れを1枚で見られる
- 失うもの：控えが2つになり、容量を最大で今のデータ1つ分多く使う（足りなければ更新前の控えを諦め、本体の保存では控えを先に捨てる）。
  更新前の控えに戻すと、今ある直前の状態の控えは置き換わる（確認の本文に書く）。
  リンクを開いた人は更新の中身を畳んだ一覧でしか見ない。作ったばかりのデータの判定はタブ単位（同じタブで長く使ってからリンクを開くと書き出しを求めない）
- 捨てた案：案A は前からある1世代の控えを開いただけで上書きし、顧客のデータを失うことがある（レビューで再現）。容量は案B の欠点だが、
  データを失わないほうを先にする。案C はデータの版・書き出しに入り、控えが控えを含んで膨らむ。
  更新前の控えに戻したとき、いまのデータを更新前の控えと入れ替える案は、更新の前ではないデータが「更新前の控え」の名で残り、
  もう一度押すと更新の前のデータに戻れなくなるので捨てた（いまのデータは1世代の控えに回す）。
  案E は3回続けて押すと読まずに進みやすく、どこまで済んだかが見えない。案F は2問の画面の流れ（問1・問2）と混ざり、設定の画面の上で済む操作に全画面は大きい
