# ADR-0048：条件の重みの表を下書きにし、「変更を確定」と確認のあとで保存する

- 日付：2026-10-21
- 状態：採用
- 関連：PRD D233・D286、ADR-0023・ADR-0026・ADR-0035・ADR-0036

## 背景
条件の重みの画面（`#/rules`）の表は点数の基準のプリセットの重みを直す（ADR-0035）。スライダー・必須の切り替えを動かすとすぐ保存していたが、基準の重みは月・日の組み方と点数のすべてに効く。「動かしたら即確定？ 今の設定と違えば分かるようにし、確定ボタンで確定し、確定したらどうなるかを出してほしい」と声が出た。
決めること：表の重み・必須をいつ保存するか。今の設定との違いの見せ方。確定の前に何を見せるか。確定していない変更を持ったまま画面を離れるとき。

## 選択肢
1. 案A：表の重み・必須は画面の中の下書きにし、「変更を確定（N件）」で独自の確認を出してからまとめて保存する。違う行は色と文字の印。離れるときは確認
2. 案B：即時に保存し、保存したあとにトーストで知らせて［元に戻す］を付ける。捨てた理由：誤って動かすと、元に戻すまでの間に作る・確かめる操作が混乱する
3. 案C：画面全体（名前・条件の追加と削除・プリセットの節・乱数の種も）を下書きにして1つの保存ボタンで書く。捨てた理由：名前の変更などの小さな操作まで確定が要り手間が増える

## 決定
案A。

- 下書きは画面の state（型ごとの重み・必須。`lib/weightDraft`）。`DemoData` の形は変えない。確定で `update(d => applyDraft(d, 下書き))`（型ごとに `setBasisWeight`）。保存済みと同じ値に戻した欄は下書きから外れる
- 違う行は左に注意の色の帯・淡い地・「変更あり 3→2.5」の文字（色だけに頼らない）。同じ型の条件はどの行にも出る（基準は型ごとの重み）
- 確定の帯は下書きがある間だけ、画面の下に貼り付く。主ボタン「変更を確定（N件）」と文字のボタン「取り消す」。その間「条件を足す」は枠にして主ボタンは1つ（ADR-0036）
- 確認（ADR-0026）：変わる条件と重み（前→後）、点数の基準のプリセットの重みになり組み方と点数に使うこと、影響する日（確定後のデータで重みが変わる今日以降の日。確定済みの日は作り直さない）を出す。取り消すは確認なしで下書きを捨てる
- 離れるとき：HashRouter なので `useBlocker` は使えない。下書きがある間、アプリの中の別の画面へのリンクの押下を捕捉して確認し、確定なら同じリンクを押し直す。コマンドパレットは移る前に `confirmLeave()`。再読込・タブを閉じるは beforeunload（`components/useLeaveGuard`・`lib/leaveGuard`）
- 整合：点数の基準を替える・基準のプリセットを消す・初期値に戻すと下書きを捨てる（確認の本文に書く）。条件の名前・追加・削除・プリセットの節・基準のラジオ・乱数の種はすぐ保存

## 理由とトレードオフ
- 得るもの：動かしただけでは何も変わらず、試しに動かしても組み方や点数を誤って変えない。今の設定との違いが行ごとに見える。確定の前に影響する日が分かる
- 失うもの：重みを変えるのに確定と確認の1手が増える。プリセットの節は即時のままで、基準のプリセットの重みを2か所で直せる（片方だけ下書き）。ブラウザの戻る・進むでは確認を出せず、下書きは黙って捨てる（ADR-0023 の〈スタッフ〉の編集の欄と同じ限り）
- 見直す条件：プリセットの節も下書きにしたい声が出たとき。データのルーターに移したとき（戻るでも確かめる）
