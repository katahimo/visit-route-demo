# ADR-0087：相性の表は残し、マスをボタンにせず押すと出る選ぶ欄1つにして、凡例・絞り込みを畳む

- 日付：2026-11-02
- 状態：採用
- 関連：ADR-0022・0047・0073・0074

## 背景
UX レビューで、相性の画面（`#/compat`）は 1366px・390px とも画面のボタンが約225個（初期データ 20人×8人で、マス 160・列の見出し 8・行の名前 20・絞り込みの欄の2つ・凡例の4つの札と「点のしくみ」・タブなど）あり、文字と操作が多いと指摘された。マスはどれも枠つきのボタンで、Tab で 190 回以上止まる。上の説明の文（「セルを押すと ◎ → ○ → 空 → △ → × と変わります」）と凡例の札で記号の意味が2か所に出て、表の下に「休止中の…は出していません」の注記もあった。

利用者の判断：**表とデータ（5段階。D8）は残し、見た目の量と操作の数だけ減らす**。相性の意味（◎○未入力△×、× は担当にしない）と計算への効き方は変えない。

## 選択肢
1. 案A：今のまま、マスの枠を薄くするだけ（ボタンの数・Tab の回数は変わらない）
2. 案B：表を〈利用者さん〉ごとの一覧（記号の入った人だけ）にする（表を残す判断に反する。全体を見渡せない）
3. 案C：表は残し、マス・見出し・名前をボタンにしない grid（Tab の止まり所1つ・矢印で動く）にする。マスを押すと**選ぶ欄1つ**（5段）が出る。凡例は1行、絞り込みは1つの「絞り込み」に畳む

## 決定
案C。

- **表は grid**（`role="grid"`。`<table>` のまま）：マス・列の見出し・行の名前はボタンにせず、表全体で Tab の止まり所は1つ（roving tabindex）。矢印・Home・End（行の先頭・最後）・Ctrl＋Home／End（最初・最後のマス）・PageUp／PageDown（10行）で動く。左上の角には止まらない。位置の計算は `lib/gridFocus` の純粋関数
- **マスを押す（Enter・Space）と相性を選ぶ欄**（`compatChoice`。`DetailPopover` で出す）：見出し「〈利用者さん〉 × 〈スタッフ〉」、◎ 選ばれやすい・○ やや選ばれやすい・－ 未入力（ふつう）・△ 選ばれにくい・× 担当にしない の5段、今の相性に印（`aria-pressed`）とフォーカス。↑↓・Home・End で動き、選ぶと入れて閉じ、フォーカスはマスへ戻る。Esc・外を押す・もう一度押す・Tab で外へ出ると閉じる。押して回す（◎→○→空→△→×）のはやめる（× まで4回押していたのが、どの相性も2回になる）
- **マスの見た目**：枠つきのボタンをやめ、細い線の格子に記号だけ。入れた相性だけ薄い地の色（◎○ 緑・△ 黄・× 赤）
- **列の見出し・行の名前**を押す（Enter・Space）と今までどおり詳細の吹き出し（D114・D115）。見出しの欄そのものが入口（ボタンを中に置かない）
- **凡例は1か所・1行**（「◎ 選ばれやすい ○ やや選ばれやすい △ 選ばれにくい × 担当にしない」。札にしない）。上の説明は「マスを押して相性を選びます」の1行で、記号を並べない
- **絞り込みは1つの「絞り込み」に畳む**（中に〈スタッフ〉（列）と〈利用者さん〉（行）。要約は絞っていなければ「絞り込みなし」、絞れば絞った側の人数と中身。URL に絞り込みがあるときだけ開く。D116 の中身は同じ）
- **休止中の人の注記を出さない**（休止中の人を出さないのは今までどおり。D117）
- **エキスパート機能の入切の差は1つ**：入だけ凡例の横に「点のしくみ」（点・条件の重みの話）。切は出さない。判定は `lib/peopleView` の `compatHintLabel` の1か所（相性の画面のほかの入切の判定は持たない）

## 理由とトレードオフ
- 得るもの：初期データで画面のボタン（`button`・`summary`・リンク・入力。メニューを含む）が 248 → 59（エキスパート入）・241 → 51（切）。メニューを除いた中身の見えている操作は 193 → 4（入）・3（切）、Tab の止まり所は 193 → 5・4。390px では表の上端が 474px → 333px に上がる。300人×60人で相性を1回変えて描き終わるまでの中央値は、前（押して回す）の 95〜112ms に対し 68〜95ms（同じ機械の測り。マスを押して選ぶ欄が開くまでは約 40ms）
- 失うもの：◎ を入れるのが1回押すから2回押す（押して欄を開き、選ぶ）になる。マスのボタンの見た目が無くなり、押せると分かりにくい（上の1行の説明・指のカーソル・地の色で補う）。読み上げは表のモードではなく grid のモードで読む
- 見直す条件：続けて同じ記号を入れる作業が多く2回押しが重いという声（選ぶ欄を開かずに数字のキーで入れる、などを足す）。マスが押せると分からないという声

## 影響
- PRD：D116（絞り込みは1つの畳んだ欄）・D253（速さの関門は「相性を1回選んで描き終わるまで」）を直し、D420 を足す
- 設計書：`docs/design/pages-compat.md`。e2e：`scripts/e2e-compat.cjs`（操作の数・grid・選ぶ欄・速さの測り方）・`scripts/e2e-words.cjs`（マスの読み上げ）
- 部品：`DetailPopover` に開いたときのフォーカスの先（`focusSelector`）を足した。`lib/compatLevel` の `cycleCompat`・`nextCompatLevel` を消し `setCompatLevel`・`COMPAT_CHOICES`・`COMPAT_WORD` に。`lib/compatView` の欄ごとの要約を `compatFilterSummary` 1つに
