# ADR-0027：メニューをやりたいことの順に並べ、コマンドパレット（Ctrl+K）で画面・操作・人へ飛べるようにする

- 日付：2026-10-18
- 状態：採用（メニューの並びは ADR-0045・0054・0063。パレットの候補に担当・訪問が増えたのは ADR-0055）
- 関連：PRD D178〜D183、ADR-0024（スマホのメニュー）、ADR-0025（導線）、ADR-0034（画面名）

## 背景
画面の監査（ADR-0025）で、メニューについて次が分かった。
- メニューが「データの種類」で並び、やりたいこと（月を組む・欠勤に対応する・問い合わせに答える）と合わない
- 「一覧・編集」が2つ同名で並び、見出しや上の帯の名前で見分けるしかない
- 画面が増え、名前を知っている画面・人にもメニューか一覧をたどる必要がある（〈利用者さん〉を名前で開くのに2〜3手）

制約：URL・データ・契約・store は変えない。新しい依存（パレットのライブラリ）を足さない。〈スタッフ〉はよみを持たない。

## 選択肢
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 並びA：やりたいことの順（組む → 当日 → 問い合わせ → 人 → 条件）に並べる | 仕事の流れで探せる。欠勤がメニューから1手。同名項目が無くなる | メニューの位置が変わる（URL は同じ） | 採用 |
| 並びB：データの種類のまま名前の重複だけ直す | 変更が小さい | 「やりたいことから入る」問題が残る | 不採用 |
| 道具A：自前のコマンドパレット | 名前を知っている画面・操作・人に2〜3打で着く。既存の入口を使い二重に作らない | 全員の名前をそろえ直す（300人×60人で数ms）。漢字の〈スタッフ〉はひらがなで引けない | 採用 |
| 道具B：上の帯の常設の検索欄 | 常に見える | 狭い画面で帯が2段になり、Tab の順が増える | 不採用 |
| 道具C：作らない | 実装不要 | 画面・人が増えるほど遠くなる | 不採用 |

## 決定
- メニューは用途の並びにし、「〈利用者さん〉一覧」「〈スタッフ〉一覧」のように名前で見分けられるようにする（呼び方から引く。画面の見出しもそろえる）。「欠勤・キャンセルを登録」は画面でなく操作（`?do=absence`）で、今の画面の印を付けない。並びは `lib/nav.ts` の `menuSections` の1か所で、左のメニュー・引き出し・下のタブ・上の帯の名前・パレットの画面がここから引く
- 上の帯の名前は「見出し・項目名」で、390px で入りきらなければ2行にして名前を切らない
- コマンドパレット：上の帯の「探す」（狭い画面は下のタブ）と Ctrl+K（mac は ⌘K）で開く、画面・操作・人の名前を打って絞り込むモーダル。確認ダイアログの inert・フォーカスの戻しを使う。中身と絞り込みは `lib/commandPalette.ts`（純粋関数）、見た目は `components/CommandPalette.tsx`。行き先は今ある URL だけ（画面・`?do=`・`?id=`）
- 〈利用者さん〉はよみ（カタカナ）でも引け、〈スタッフ〉は名前だけ。画面の候補には呼び方のよみを別名で足す（`TERM_READINGS`。既定の漢字の呼び方のみ）。前の画面名も別名で引ける
- キー操作：入力欄の中の Ctrl+K も開き（Windows・Linux では文字編集に使わず、ブラウザでは検索欄へ移ってしまうため）、閉じたらその入力欄へ戻す。mac は ⌘K だけで開き、Ctrl+K（行末まで消す）は横取りしない。右の欄・確認・引き出しが開いている間は開かない（未保存の編集の上から別の画面へ移れてしまうため）。開かないときもブラウザの検索欄へ移る既定の動きは止める

## 理由とトレードオフ
- 得るもの：仕事の流れで探せ、名前を知っているものへ2〜3打で着く。新しい保存データ・依存・契約は無い
- 失うもの：慣れたメニューの位置が変わる。上の帯にボタンが増える。〈スタッフ〉のよみは持たない（足すとデータの版・Excel が変わる）
- 見直す条件：パレットを使う人が多ければ最近使ったものを先に出す（保存が要る）。〈スタッフ〉をよみで引きたい声があればよみを足す

## 影響
`lib/nav.ts`・`lib/commandPalette.ts`・`components/CommandPalette.tsx`・`app/App.tsx`。画面の細部は design/pages.md。
