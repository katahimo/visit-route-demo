# ADR-0025：やりたいことから入る導線（ホーム・進み具合の帯・欠勤の欄・言葉の案内・行き先）

- 日付：2026-10-18
- 状態：採用（メニューは ADR-0045・0054・0063、ホームのカードの順・欠勤の主ボタンは ADR-0044、欠勤の欄の連絡の段は ADR-0038、案の作り方は ADR-0053・0063）
- 関連：PRD D141〜D145・D151〜D155・D167〜D177・D184〜D204、ADR-0026（独自の確認）、ADR-0027（メニュー・パレット）

## 背景
利用者の依頼「直感的にやりたいことが操作できるように」で画面を監査したところ、やりたいことに届くまでの迷いが見つかった。
- 起動すると案内なしで日の画面になり、今月の準備の進み具合や次の一手は月の画面を開かないと分からない
- 同じ操作の入口が複数あり、逆に急な欠勤は見つけにくい
- 用語の説明がその場に無い、空き状況・スマホの月・ファイル選択（英語）・右の欄の確定ボタン（内容から離れる）・要対応の行き先（行き止まり）などの問題

制約：新しい保存データを増やさない。データを書き換えるのは store だけ。既存の URL を壊さない。スマホは表示の確認が主（PRD §7）。判定は純粋関数に置き、月の画面と同じ数え方にそろえる。

## 決定
既存の画面・操作へ移るだけの導線を足す。共通の考え方は「数え方・文の決まりを `lib/` の純粋関数1か所に置く」「新しい保存データ・契約を足さない」。

1. ホーム「今日やること」（D141〜D145）：起動（`#/`）と知らない URL の行き先をホームにし、カードは既存の画面・操作へ移るだけにする（`lib/home.ts`）。日の状態の計算は `lib/useDayStatuses.ts` に切り出して月・帯と共有する（数が食い違わない）。月の操作は `?do=` で開き、1回行ったら URL から消す
2. 進み具合の帯（D151〜D155）：見ている月の今日以降の訪問・確定・要対応と、次の一手のボタン1つを細い帯にまとめる（`lib/progressBand.ts`・`components/progressBand.tsx`）。同じ数字を2か所に並べない。読み上げは aria-label と空で置く aria-live。Ctrl・⌘・Shift・中ボタンは横取りしない
3. 急な欠勤・当日キャンセルの入口（D167〜D172）：日の画面の操作の行の先頭に「欠勤・キャンセルを登録」を置き、段階のある右の欄（`pages/SuddenPanel.tsx`、決まりは `lib/sudden.ts`）を開く。何が起きたか → 人 → 影響と振り直し → 確定と進む。列の見出し・ホームのカード・パレットも同じ欄を開く。下のタブには入れない（ADR-0045 で後に入れた）
4. 言葉と案内（D173〜D177）：日の点数の理由は減点の内訳から1つ選ぶ純粋関数（`lib/scoreReason`）。用語は辞書（`lib/glossary`）と部品 `Term`（その場で出る tooltip。同時に1つ）。空の画面は「なぜ空か＋行き先」（`lib/emptyGuide`）。月のマスの読み方は、マスに文だけを置き表に1つの見張りの吹き出し（`MonthCellTip`）で出す（マスごとの部品は描き直しを重くするため）
5. 空き状況の段階化（D184〜D188）：1画面のまま いつ・何を → 場所（任意・畳む）→ 受けられる曜日・時間帯 → 次の一手（`lib/vacancyView`）。案内文は開いているときだけ計算する。週は4つの表示の1つの切り替えで、URL は `?view=`・`?by=`（`lib/weekView`）
6. スマホ・ファイル選択・ツアー（D189〜D193）：390px の月は日ごとの一覧（`?layout=`。`lib/monthList`）。ファイル選択は日本語の1部品 `FilePick`。初回のツアーは中央のカード（`lib/tour`・`components/Tour.tsx`）で、「見た」は DemoData と別の localStorage キー `vrdemo:tour:seen`（書き出し・初期化に混ぜない）。`?id=`・`?do=` のリンクでは自動で出ない
7. 右の欄の確定ボタンの帯（D194〜D197）：内容のすぐ後ろに `position: sticky; bottom: 0` で置く（`usePanelFoot`）。帯の高さを `--drawer-foot-h` にして `scroll-padding-bottom` に使う。600px 以下は主ボタンを全幅。safe-area を避ける。部品1か所で全部の欄に効かせる
8. 行き止まりから次の画面へ（D201〜D204）：行き先は `lib/links.ts`。日の画面の `?do=unassigned`（その日の担当なしの訪問へ巻く）と `?do=absence&staff=…`（その人の2段目）を足し、読んだら URL から消す。要対応の行は種類ごとの行き先を決め、行全体を1つのボタンのままにする（入れ子にしない）

## 選択肢と捨てた案
| 区切り | 採った案 | 捨てた案とその理由 |
|---|---|---|
| 1 ホーム | 起動時のホームにカード | 日の画面の上の帯（日の画面が長くなる）／メニューの並べ替えだけ（今の状態が分からない） |
| 2 進み具合 | 共通の帯にまとめる | 帯＋従来の手順の欄を残す（同じ数字が2か所） |
| 3 欠勤 | 段階のある右の欄 | 中央のダイアログ（縦に長く確認と重なる）／専用画面（日の画面の案と離れる） |
| 4 言葉 | 辞書＋tooltip 部品 | 押して開く `Hint` に寄せる（その場で読めない）／用語集の画面（行き来が要る）／マスごとの `title`（キーボード・タッチで読めない） |
| 5 空き状況 | 段階に並べ替え（1画面） | ウィザード（条件を変えて見比べるたび段を戻る） |
| 6 ツアー | 中央のカード・見たことは別キー | 要素を指す吹き出し（幅ごとに指す先が変わる）／見たことを DemoData に入れる（書き出し・初期化で混ざる） |
| 7 右の欄の帯 | sticky の帯 | 各欄の内容の最後に置く（長い欄で巻かないと届かない） |
| 8 行き先 | 既存の `?do=` の形 | 別名の値（ツアー判定・消し方を再利用できない）／行の中に別リンク（ボタンの入れ子） |

## 理由とトレードオフ
- 得るもの：開いた人が1画面で次の一手に着き、同じ数字が同じ数え方でホーム・月・日に出る。入口が目的別にそろう。新しい保存データ・契約は無い。部品1か所で効かせたので全部の欄で同じ動き
- 失うもの：月・日・ホームで今日以降の訪問を計算・採点する負荷（日ごとの覚えと `useDeferredValue` で抑える）。ツアーが要素を指さないこと（場所は文で読むので、メニュー名を変えたら `lib/tour.ts` も直す）。「見た」はブラウザごと。スマホは帯・タブぶん本文が狭い
- 見直す条件：カードが多すぎるならホームを月ごと1枚に。起動・帯が重い事業所（数十人・日に数十件）では今日から2週間だけ数える。用語の下線が多ければ最初の1か所だけに。端末をまたいで「見た」を持ちたい声があってもサーバーには保存しない（PRD §4）
