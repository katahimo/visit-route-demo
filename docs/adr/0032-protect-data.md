# ADR-0032：データを守る仕組み（1世代の控え・書き出しの知らせ・古い訪問の片づけ・壊れたデータと別のタブの知らせ）

- 日付：2026-10-19
- 状態：採用（片づける対象は ADR-0053 の保存のしかたに合わせた）
- 関連：PRD D2・D3・D227、ADR-0001（ブラウザ完結・localStorage）、ADR-0026（独自の確認）、ADR-0053

## 背景
データは利用者のブラウザの localStorage（`vrdemo:data:v1` の1つの JSON）にしか無い（ADR-0001）。
- 「初期状態に戻す」「Excel 全体の読み込み」「控えの読み込み」「名簿の総入れ替え」は確認を出すだけで、置き換える前のデータはどこにも残らない
- 容量超過の文は「古いものを消してください」だが、それをする画面が無い
- 保存していたデータが読めないと退避して初期データで開くが、何も知らせない（利用者は消えたと思う）
- 別のタブで変わると黙って読み直し、編集中の欄は保存で別のタブの変更を上書きする
- 書き出し（控え）を促すものが無く、いつ書き出したかも分からない

制約：サーバー・ログインは作らない（PRD §4）。外部送信を増やさない。DemoData の契約に項目を足さない。データの書き換えは store の `update(fn)` だけ。localStorage の容量（5MB 前後）を倍にしない。

## 選択肢
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 控えA：置き換える前に1世代だけ別のキー | 誤操作から1手で戻れる。容量は最大で倍まで | 2つ前には戻れない。大きいデータでは控えが残せない | 採用 |
| 控えB：複数世代 | 何回か前にも戻れる | 容量が世代数倍。上限で本体の保存を圧迫する | 不採用 |
| 控えC：確認の文を強くするだけ | 容量を使わない | 押し間違いは戻せない | 不採用 |
| 控えD：IndexedDB | 容量が大きい | 非同期の API で store が二重になる | 不採用 |
| 知らせA：最後に書き出した日を覚え、2週間で1日1回トースト | 押し付けず思い出せる | 別の端末の書き出しは分からない | 採用 |
| 知らせB：毎回の起動で確認ダイアログ | 確実に目に入る | 毎回止められて煩わしい | 不採用 |
| 知らせC：書き出した日を DemoData に持つ | 控えで他の端末へ渡る | 控えを読み込むと日付が戻り、契約に項目が増える | 不採用 |
| 片づけA：月を選び、それより前の訪問の記録だけ消す | 手で範囲を選べ、人・条件は残る | 消したものは戻せない | 採用 |
| 片づけB：容量超過のとき自動で消す | 手間が無い | 黙って消え、何が消えたか分からない | 不採用 |
| 別のタブA：読み直して知らせる（編集中は上書きの注意） | 今の動きを変えず、黙って変わらない | 入力中の欄と別のタブの変更は統合しない | 採用 |
| 別のタブB：編集中は読み直さない | 入力は守れる | 画面と保存のデータが食い違う | 不採用 |

## 決定
置き換える前に**1世代だけ**別のキーに控え、データの画面から戻せるようにする。書き出した日をブラウザごとに覚えて2週間で知らせ、容量超過には古い訪問の片づけを用意する。読めなかったデータと別のタブの変更は知らせる。

- 1世代の控え：store の `keepPrevious(reason)` が `vrdemo:data:prev`（置き換える前の JSON）と `vrdemo:data:prev:info`（時刻と操作の名前）に書く。次に残すと上書き。対象は初期状態に戻す・控えの読み込み・Excel 全体の読み込み・名簿の読み込み。確認の本文に見込みで「戻せます」と書き、確認で OK になってから残す。「直前の状態に戻す」（確認つき）はいまのデータと控えを入れ替える。いまのデータを控えに残せなければ戻さない（戻すといまのデータを失うため）
- 容量：控えが書けなければ前の世代を消して1回だけ試し直し、それでもだめなら残さず、完了の知らせに「控えを残せません」を添える（操作は止めない）。本体の保存が容量超過なら控えを先に捨てて書き直す（いまのデータが控えより大事）
- 最後に書き出した日：`vrdemo:backup:last`（控えの JSON と Excel 全体の書き出しで更新。名簿だけは数えない）。起動したとき、確定した日があり14日以上書き出していなければトースト。知らせた日を `vrdemo:backup:reminded` に覚え1日1回まで
- 古い訪問の片づけ：データの画面で月を選び（既定は3か月前）、その月より前の保存した訪問・伝えた内容・振り直しの情報を `update(fn)` で消す（`lib/tidy`）。繰り返しの回は繰り返しのとおりに戻り、人・条件は消さない。件数と空く見込みを出して確認する。容量超過の文はこの欄を指す
- 壊れたデータ：`loadWithStatus()` が `broken` を返し、本文の先頭に閉じられる注意の知らせと「読めなかったデータを書き出す」（`vrdemo:data:broken` の元の文字をそのままファイルに）。退避も容量超過で失敗したら「今すぐ書き出してください」に変える
- 別のタブ：読み直したら「別のタブで変わったので読み直しました」。〈スタッフ〉・〈利用者さん〉の編集に変更があれば「保存すると上書きします」（入力は残す。統合はしない）
- 控え・書き出した日・知らせた日はブラウザごとの記録で、ツアーの `vrdemo:tour:seen` と同じく DemoData の外（書き出し・読み込み・初期状態に戻すの対象外）。localStorage を触るのは store の中だけ

## 理由とトレードオフ
- 得るもの：初期化・読み込みを押し間違えても1手で戻れる。容量超過の文が画面の操作を指す。データが読めなかった・別のタブで変わったことが分かる。控えの書き出しが促される
- 失うもの：控えの分だけ localStorage を使う（最大で本体と同じ大きさ）。戻せるのは1つ前だけで、片づけで消したものは戻せない。書き出した日はブラウザごと（別の端末で書き出しても知らせは出る）。別のタブの変更と入力中の欄は統合せず、保存すれば上書きする
- 見直す条件：控えが残せないことが多ければ、控えを圧縮するか IndexedDB を検討する。2つ前に戻したい声が多ければ世代を増やす。知らせが煩わしければ日数（14日）を延ばす
