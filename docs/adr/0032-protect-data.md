# ADR-0032：データを守る仕組み（1世代の控え・書き出しの知らせ・古い訪問の片づけ・壊れたデータと別のタブの知らせ）

- 日付：2026-10-19
- 状態：採用（片づける対象は ADR-0053 の保存のしかた）
- 関連：ADR-0001・0026・0053

## 背景
データは localStorage（`vrdemo:data:v1`）にしか無く、置き換える操作の前のデータが残らず、壊れたデータや別のタブの変更も黙って扱っていた。サーバーは作らず、契約に項目を足さない。

## 決定
- 1世代の控え：store の `keepPrevious(reason)` が `vrdemo:data:prev` と `vrdemo:data:prev:info` に書く。対象は初期化・控えの読み込み・Excel 全体の読み込み・名簿の読み込み。確認で OK になってから残す。「直前の状態に戻す」はいまのデータと控えを入れ替える（いまのデータを控えに残せなければ戻さない）
- 容量：控えが書けなければ前の世代を消して1回試し直し、だめなら残さず知らせる。本体の保存が容量超過なら控えを先に捨てる
- 最後に書き出した日：`vrdemo:backup:last`（JSON と Excel 全体で更新）。確定した日があり14日以上書き出していなければトースト（`vrdemo:backup:reminded` で1日1回）
- 古い訪問の片づけ（`lib/tidy`）：月を選び（既定3か月前）、それより前の保存した訪問・伝えた内容・振り直しの情報を消す。人・条件は消さない。容量超過の文はこの欄を指す
- 壊れたデータ：`loadWithStatus()` が `broken` を返し、注意の知らせと「読めなかったデータを書き出す」（`vrdemo:data:broken`）
- 別のタブ：読み直したら知らせる。編集中の欄は「保存すると上書きします」（統合しない）
- 控え・日付の記録はブラウザごとで DemoData の外。localStorage を触るのは store の中だけ

## 捨てた案
複数世代（容量が倍々）・IndexedDB（store が二重）・毎回の起動で確認（煩わしい）・容量超過で自動で消す（何が消えたか分からない）。

## トレードオフ
- 失うもの：控えの分だけ容量を使う。戻せるのは1つ前だけ。片づけは戻せない
- 見直す条件：控えが残せないことが多ければ圧縮か IndexedDB。知らせが煩わしければ14日を延ばす
