# ADR-0102：デモの更新を最初の2問の画面で知らせ、「今のデータを使い続ける」を上に置く。案内ツアーをなくす

- 日付：2026-11-04
- 状態：採用
- 関連：ADR-0025・0045・0053・0073・0092

## 背景
デモは毎日のように更新するが、開いた人には何が変わったかが見えない。前に使った人は保存データのまま開き、デモの初期状態（新しい初期データ・ひな形）で試し直すには、データの画面の「始め方を選び直す」か「デモの初期状態に戻す」を探す必要があった。
データの版（DATA_VERSION）が変わったときだけは、読めないので初期データで始めて知らせている（ADR-0053）。版が同じ更新では何も出ない。
また案内ツアー（データの画面の「案内をもう一度見る」から開く2枚。ADR-0025・0045）は、最初の2問（ADR-0073）と要対応の帯・登録の案内が入口になってから自動では出ず、中身も画面の変更に追いつかなくなっていた。

## 選択肢
1. 案A：更新の一覧（id と箇条書き）をコードに持ち、見た更新の印を端末に残す。まだ見ていない更新があれば、最初の2問の画面を「デモを更新しました」として出し、問1のいちばん上に「今のデータを使い続ける」を置く
2. 案B：ビルドごと（コミットごと）に版を変え、開くたびに知らせる
3. 案C：知らせはトーストだけにし、データは今までどおり黙って使う

## 決定
- 案A
- 更新の一覧は `src/lib/releaseNotes.ts` の `RELEASE_NOTES`（新しい順。id は出す日 `YYYY-MM-DD`、同じ日の2回目から `-2` など）。利用者の目に見える変更を出すときに先頭へ1件足す。足さない更新では知らせない
- 見た更新は DemoData と別のキー `vrdemo:release:seen` に id だけ持つ（store/start）。データの版・書き出し・初期状態に戻すに入れない
- 知らせるのは、保存データが読め、まだ見ていない更新があるとき。印が無い人（この仕組みの前から使っている人）には最新の1件を出す。初めて開いた人（最初の2問）・印 `all`（e2e）・読めなかったデータ（ADR-0053 の知らせ）は知らせず、見たことにする
- 画面は最初の2問の画面を使う：見出し「デモを更新しました」、変わったところ、問1「どのデータで続けますか」＝今のデータを使い続ける（初めに選んでおく。問2を出さず、主ボタン「開く」で今の画面のまま開く）／デモで試す／自分のデータで始める（選ぶと問2と「いまのデータは消えます」の注意。答えると今のデータを1世代の控えに残して作り直す）
- 案内ツアー（`components/Tour`・`lib/tour`・データの画面の「使い方の案内」）をなくす（PRD D192・D193・D277 を廃止）

## 理由とトレードオフ
- 得るもの：前に使った人が、変わったところを読み、今のデータのまま続けるか、新しいデモで試し直すかをその場で選べる。既定は今のデータなので、何も考えずに「開く」を押しても消えない。画面は2問の画面を使い回し、新しい画面を増やさない。ツアーの直しが要らなくなる
- 失うもの：更新のたびに一覧へ1件足す手間。足し忘れると知らせない。案内ツアーで流れを読むことはできなくなる（取扱説明書と画面の説明で代える）
- 捨てた案：案B はデプロイのたびに知らせが出て、内部の直しでも選ばせることになる。案C は選び直す入口が見つからないまま

## 影響
- `src/lib/releaseNotes.ts`（新規）、`src/store/start.ts`（`SEEN_RELEASE_KEY`・`seenRelease`・`rememberRelease`）、`src/store/persist.ts`（`loadWithStatus` の `releaseNotes`・`keepAfterRelease`・`startWithAnswer`）、`src/store/react.tsx`（`releaseNotice`・`cancelFirstRun`）、`src/components/FirstRunPage.tsx`
- 消したもの：`src/components/Tour.tsx`・`tour.css`・`useTourModal.ts`、`src/lib/tour.ts`、データの画面の `TourCard`、e2e-tour のツアーの節
- PRD D437（新規）。D192・D193・D277 を廃止
- 見直す条件：知らせが多すぎる・少なすぎるという声が出たとき。更新の一覧が長くなったとき（古いものを消す）
