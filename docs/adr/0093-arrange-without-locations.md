# ADR-0093：位置（緯度・経度）が未登録でも担当を組む

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0016・0068・0075・0092

## 背景
台帳・予約システムの CSV には住所はあっても地図の位置が無い。読み込んだあと［地図に置く］を押すまで〈利用者さん〉の位置と〈スタッフ〉の自宅の位置が未登録で、計算（matching/compile）は未登録の組を可否で外していた（`noPlace`・点は無限）。CSV を読んで毎週の予定を入れ、AI で組むと「組める〈スタッフ〉がいない」で1件も組めず、理由が分かりにくかった。住所から位置を探すのは外部へ送るので、押したときだけ（ADR-0016）にしたい。

## 選択肢
1. 案A：位置が未登録でも組む。未登録の側への移動はどこからでも決まった分数とみて、位置のある組を先に選ぶよう点を足す
2. 案B：読み込んだあと自動で住所から位置を探す
3. 案C：今のまま外し、知らせで［地図に置く］へ案内する

## 決定
- 案A。未登録の訪問先・自宅への移動は 30分（`UNPLACED_TRAVEL_MIN`）、距離は 0 m（交通費に入らない）とみる。組の理由に「〈利用者さん〉の位置が未登録（移動は30分とみる）」（`noPlace`・30点 `UNPLACED_POINTS`）を出し、可否にはしない
- 自宅の位置が未登録の〈スタッフ〉も、その日に働く人に数える（均等・いつもの担当の判定）

## 理由とトレードオフ
- 得るもの：CSV を読んだだけで担当を組んで動きを見られる。外部へ勝手に送らない
- 失うもの：位置が無い間は移動・道順・交通費の見込みが実際と違う（理由に出し、地図に置けば直る）
- 捨てた案：案B は押したときだけ送る決まり（ADR-0016）に反する（のちに ADR-0094 で、読み込みの確認に送ることを書いたうえで採用）。案C は最初に試す人がつまずく

## 影響
- `src/matching/compile.ts`（`travelMatrices`・`pairReasons`・`working`）、`src/contracts/problem.ts` のコメント、PRD D426
- 見直す条件：30分の見込みが現場と合わないという声が出たとき（事業所の設定にするか決める）
