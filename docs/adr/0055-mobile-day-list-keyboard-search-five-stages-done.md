# ADR-0055：スマホは日ごとのリストと下から出る欄、広い画面は帯をキーで動かし、パレットで担当と要対応を引く

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D333〜D338、ADR-0051（訪問の詳細の欄）・ADR-0052（人の画面）・ADR-0054（共通の部品・元に戻す）・ADR-0024（スマホの下のタブ）・ADR-0045（下のタブの並び）

## 背景
- スマホは見る・取り消す・担当替えまで（追加・移動はしない。ADR-0051）
- 390px の日の予定は見出し・今の担当の1行・担当ごとの1日・操作の行が積まれ、最初の画面に訪問がほとんど見えなかった。訪問の詳細の欄は右の欄の形（画面いっぱい）で、押すボタンが小さかった
- 週の表・月では複数選択できず、スマホの既定は表なので選ぶ所が無かった
- 訪問をキーボードで動かす手段が無く（ドラッグか欄）、パレットの訪問は〈利用者さん〉の名前と日付でしか引けなかった

## 選択肢

### スマホの予定
1. 案A：今の画面（順番のカード）を詰めるだけ
2. 案B：日の予定に日ごとのリスト（1行1訪問）を足してスマホの既定にし、順番・一覧は「その他 ▾」の「表示」に残す。週・月はスマホでも今の表示を「まとめて見る」として残す
3. 案C：週・月もスマホでは日ごとのリストにする

### 訪問の詳細の欄（スマホ）
1. 案A：今の右の欄のまま
2. 案B：下から出る欄（ボトムシート）にし、大きな4つのボタンで中身を開く

### キーボードの繰り返しの回
1. 案A：動かすたびに範囲の確認（モーダル）
2. 案B：「この回だけ」で動かし、画面の下に小さな帯「これ以降も／すべての回も／このまま」

## 決定
すべて案B。

### スマホの日ごとのリスト（`components/dayList.tsx`）
- 600px 以下の日の予定の既定。行は時刻・〈利用者さん〉・担当の印と名前・印（要対応・未連絡の変更・ピン）。取り消し・休みの回も薄く出す
- 日の送りは上の帯の日付の切り替えと、リストの左右のスワイプ（横 60px 以上・縦 40px 以内。タッチ・ペンだけ）
- 行を押すと訪問の詳細の欄。行を長押し（500ms）するか見出しの「選ぶ」で複数選択
- 操作の行は1段（ボタンの名前は読み上げだけに残してアイコンだけ）。日の予定の表示の切り替え（日ごとのリスト・順番・一覧）は「その他 ▾」の「表示」。見出しの説明・担当ごとの1日は出さない
- 週・月は「まとめて見る」として今の表示のまま。下のタブの「予定」は最後に開いた表示で、既定は日。人の画面の予定のスマホの日ごとのリストは ADR-0052 のまま

### 下から出る欄（`SidePanel` の `sheet`）
- 600px 以下で `VisitPanel` を下に寄せ、高さは内容に合わせる（上は 88% まで）。欄の外を押すと閉じる。中身は要約と大きな4つのボタン：担当を替える・取り消す・道順（Google マップ。担当なしは今いる場所から）・日の予定で見る
- 日時の変更・範囲・新規は出さない。複数選択の帯（`SelectionBar`）も同じ置き場所（下のタブのすぐ上・全幅）で、スマホでは時刻をずらすを出さない

### 下のタブ
- ［ホーム｜予定｜欠勤｜探す｜メニュー］。「探す」はコマンドパレットを開く。860px 以下では上の帯の「探す」を出さない。空き状況はメニューとパレットの画面から

### キーボード（`lib/visitKeys.ts`・`components/visitKeys.tsx`）
- 日の予定・週の予定の時間軸の帯で：↑↓ 15分・←→ 1日・Shift+←→ 隣の担当（訪問の詳細の欄と同じ候補で担当できる最初の人。`nextStaffFor`）・Enter で欄・Delete で取り消し（独自の確認）。Shift+Enter（複数選択）と Space（帯の詳細）はそのまま
- 書き込みは `lib/visitOps` の `applyVisitEdit`・`cancelVisitOp`。時刻・日付は「この回だけ」、担当はそのまま。update は1回で手の名前つき（全体の元に戻す。ADR-0054）
- 動いた先を `output`（aria-live）で読み上げ、動かした先で要対応なら添える。できない理由は知らせ
- 繰り返しの回は小さな帯（`KeyMoveBand`）で「これ以降も／すべての回も」を選べる。選ぶと直前の手を戻し、範囲つきで当て直す（1手のまま）。伝えた日の訪問も変わるなら欄と同じ文で確かめる。あとから別の変更が入っていれば選び直さない

### パレットの訪問の検索（`lib/commandPalette`）
- 語を日付・「担当なし」「要対応」・名前に分ける。名前は〈利用者さん〉か担当の〈スタッフ〉に当てる（部分一致だけ）。索引は〈利用者さん〉ごと・〈スタッフ〉ごと・全部を持つ（`VisitIndex`）
- 「要対応」は日の予定と同じ訪問ごとの検査（`visitIssues`）を、1日ずつ間を空けて計算し、終わった日から候補に出す（描画を止めない）。日付の語が無ければ今日から31日先まで

## 理由とトレードオフ
- 得るもの：
  - 390×844 で日の予定を開くと、最初の画面に訪問が5件ほど見える（前は0〜1件）。訪問を押すと指で押しやすい4つのボタンが出る
  - スマホでも複数の訪問をまとめて担当替え・取り消しできる。広い画面ではマウスを使わずに訪問を動かせ、1手ずつ戻せる
  - パレットで「担当なし」「要対応」「担当の名前」から欄を直接開ける
- 失うもの：
  - スマホの下のタブから空き状況へ1回で行けない（メニューか探すから）
  - スマホの日の予定で、表示の切り替え・担当ごとの1日・移動・理由・次の一手がすぐには見えない（「その他 ▾」と「詳しく」で見る）
  - スマホの欄は決まりごとの無い訪問の「前の場所から／ここへ道案内」の2つの代わりに「道順」1つ
  - 週・月の表（〈スタッフ〉×曜日・〈利用者さん〉×曜日・カレンダー）では複数選択・キーボード移動ができない。週の時間軸の帯の Shift+←→ は利用中の〈スタッフ〉の並びの隣の人
  - 下から出る欄はなぞって閉じる・高さを変える・スマホの戻るで閉じることができない（外を押す・×で閉じる）。スワイプはマウスでは効かない
  - パレットの「要対応」は31日先まで
- 手を入れた数値：長押し 500ms、スワイプは横 60px・縦 40px 以内
