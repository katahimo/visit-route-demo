# ADR-0010：点数の物差しを「点数の基準のプリセット」で固定する

- 日付：2026-10-13
- 状態：採用（基準の重みを直す画面と、試す重みの扱いは ADR-0035・0053）
- 関連：PRD D233、ADR-0005・0007・0008

## 背景
点数（ADR-0007）は「その日の条件」から作った `Problem` と物差しで付けていた。プリセットを押すとその日の条件が変わるため、押すたびに同じ案の点が全部変わった。「どれが良いか」を比べる点が、押したボタンで動くので比べられない。
決めること：物差しをどの条件で作るか、必須の違反・条件ごとの達成をどちらで数えるか。

## 選択肢
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 物差し1-A：基準のプリセットで固定 | プリセットどうし・案どうしを同じ物差しで比べられる | 基準と違う条件で作った案は点が低く見えうる | 採用 |
| 1-B：各案を作った条件で採点 | 作った考え方に忠実 | 案どうしの点が比べられない | 不採用 |
| 1-C：その日の条件のまま | 変更なし | 押すたびに点が動く | 不採用 |
| 必須・達成2-A：点と同じ基準の物差し | 「参考」の印と点が食い違わない | 作り方と一致しないことがある | 採用 |
| 2-B：その日の条件 | 作り方と一致 | 「参考」の印と点がずれる | 不採用 |

## 決定
1-A、2-A。

- 点数の基準は `DemoData.scorePresetId`。初期は先頭のプリセット（バランス）。無い・存在しない id は store の `repair` が先頭のプリセットにする。プリセット0件なら条件そのものが物差し
- 物差しの条件＝`applyPreset(data.rules, 基準のプリセット)`。条件の追加・削除・名前・項目は反映し、重み・必須だけ基準のプリセットにする
- 基準の物差しで出すもの：点・内訳・必須の違反・条件ごとの達成・提案の比較・計算中の「いまの最良 N点」
- その日の条件のままのもの：solver が最小にする費用と探索、訪問ごとの理由・入らなかった訪問の理由（AI がどう組んだかの説明）、ドラッグ時の「必須の条件に合わない」警告
- 計算中の点：Worker の進み具合に、いまの最良の案（`bestRoutes`）を足し、画面が基準の物差しで採点し直す。`bestScore` が変わらないときは送らない
- 基準は条件の重みの画面の「点数の基準」で選ぶ。基準のプリセットを消すと残りの先頭に移り、「初期値に戻す」で初期の基準に戻る。物差しの名前は見出しに小さく出す
- Excel の「プリセット」シートに「点数の基準」列（○ は1行だけ。無印なら先頭、○ が2行以上なら止める）

## 理由とトレードオフ
- 得るもの：どの案・プリセットを見ても点が動かない。点の意味が「事業所が基準に選んだ考え方で、理想より1件あたり何分余計か」に固定される。プリセットは「どう組むか」だけを変える、と言い切れる
- 失うもの：
  - 基準が「バランス」のとき「人の組み合わせ重視」の案は、相性・希望の加点を基準の重みでしか数えず点が低く見える（物差しの名前を出し、基準を選べることを説明に書く）
  - 基準と違う必須で作った案は基準では違反にならない（初期の3種は必須が同じなのでふだんは食い違わない）
  - 訪問ごとの理由（その日の条件）と点（基準）の物差しが違うことがある。理由は説明として割り切る
- 見直す条件：基準と違う必須のプリセットを使う事業所から違反の数え方が分かりにくいと言われたとき。案ごとに「作った条件での点」も見たいと言われたとき

## 影響
- evaluate・useDayModel が基準の物差し（`scoreProblem`・`scoreScale`）を使い、matching・solver は変えない
- 細部は design.md の「点数」
