# ADR-0100：組み方の標準を廃止し、条件の重みをメニューから直接直す

- 日付：2026-11-04
- 状態：採用
- 関連：ADR-0035・0048・0062〜0067・0072・0074・0088（置き換える部分は各 ADR の状態の行）

## 背景
エキスパート機能が入のとき、AI の重みを直す画面（条件の重み）への道が分かりにくかった。メニューの「組む」の子は 基本情報・組み方の標準・担当を組む で、条件の重みは組み方の標準の「案をくらべる」の寄り道だった。標準を決める手順（基本情報 → 案をくらべる → 標準にする → 担当を組む の4段、基本情報が変わったときの組み直しの知らせ）も重い。一方、AI で担当を組む重み（予定を入れたときの自動の組み・担当を組む）を単純に調整したい声があった。標準の中身である「毎週同じ人が行く」は、繰り返しのいつもの担当（`usualStaffId`）と、自動の組みが繰り返しを入れて組んだとき `usualStaffId` を書く動き（D376）ですでに持てる。

## 選択肢
1. 案A：組み方の標準を廃止し、条件の重みをメニューの子にして、重みの保存を単純にする
2. 案B：標準を任意にして奥へ下げる
3. 案C：重みを1本のスライダー（移動を短く ⇔ 同じ人）にする
4. 案D：入口（メニュー・リンク）だけ直し、標準は残す
5. 案E：重みを保存したとき、今ある担当も組み直す

## 決定
案Aを採る。
- 組み方の標準（`#/standard`・案をくらべる・標準にする・案の日で見る）、予定を組むの段（`ArrangeSteps`）、`data.standard`、要対応の帯の「組み方の標準が無い」「基本情報が変わった（組み直す）」、メニューの「変更」の印、担当を組むの組み直しの知らせ、`lib/arrangeBasis`・`store/arrangeBasis` を無くす。担当を組むはエキスパート入でも標準なしで、今の条件の重みで AI で組む
- 繰り返しのいつもの担当がその日に担当できる回は、ピンと同じに扱う（`standardPinsOf` は残す）。自動の組みが `usualStaffId` を書く動きも同じ
- メニュー「組む」（エキスパート入）の子は 条件の重み（`/rules`）・担当を組む の2つ。件数の印は担当なしの日の数だけ
- 予定と相性（`#/basics`）は入切とも〈利用者さん〉の小さいタブ（一覧・予定と相性・相性。`lib/peopleTabs`）。「組む」の子「基本情報」と基本情報のタブ（`BASICS_TABS`）は無くす
- 条件の重み：見出しの［組み方の標準へ戻る］を無くす。表の上に［値を入れる：〈プリセット名〉］（今の基準以外のプリセット。押すとその重み・必須を下書きに入れるだけ）。保存は「保存（N件）」→ 確認「重みを保存しますか？（N件）」（名前の欄は無い）→「調整した重み」（id `tuned`。1つだけ。無ければ足し、あれば重みだけ上書き）に書いて点数の基準にする（`lib/presets` の `saveTunedWeights`）。ほかのプリセットは変えない。プリセットの管理（基準の丸・名前・消す）は表の下の畳んだ節に置く。`saveDraftAsPreset`・名前の欄を無くす
- 重みを保存しても今ある担当は変えない（次に組むときから使う）

## 理由とトレードオフ
- 得るもの：メニューの子が2つになり、重みへ1手で行ける。段・標準の表・組み直しの知らせ・標準の登録の分岐とコード・テストが無くなる。重みの保存が「保存」1つで、増え続けるプリセットも「調整した重み」1つにまとまる
- 失うもの：標準の週を表で一括して決める道、案をくらべて標準にする道、基本情報が変わったときの組み直しの知らせ。比べるのは提案を比べる（`#/compare`）に残る。同じ人に寄せるのはいつもの担当の重みと、自動の組みが書く `usualStaffId` で足りるとみる（利用者の判断。単純さを優先）
- 捨てた案の理由：B は手順と分岐が残る。C は条件ごとの調整（必須・条件の種類）ができない。D は標準の複雑さが残る。E は保存のたびに確定前の担当が動き、手で直した所の扱いが増える
- 見直す条件：同じ手直しが何週も続く・組み直しの知らせが欲しいという声が出たとき
