# ADR-0096：遠方の〈利用者さん〉に手で決める移動時間（片道・分）と遠方（出張）の印

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0016・0093・0028

## 背景
移動時間は直線距離×1.3÷手段の平均速度（車 25km/h など。`domain/geo` の `estimateLeg`）で見積もる。東京の〈利用者さん〉（仙台から新幹線で行く）や名取→福島のような遠方の人は、移動が十数時間と見積もられ、どの担当の列にも入らない（`matching/timing` の時刻の判定で外れる）。可否（`allowed`）は満たすので `compile` の `infeasible` に載らず、担当なしの理由は「時間が合わない」としか出なかった。距離の見積もりでは新幹線・飛行機の速さが表せない。

## 選択肢
1. 案1：〈利用者さん〉ごとに「移動時間（片道・分）」を手で決める。入っていれば、その〈利用者さん〉への・からの移動は距離の計算でなくこの分数
2. 案2：〈利用者さん〉に「遠方（出張）」の印。印のある訪問の日は、その担当はその訪問だけを回る（前後にほかの訪問をつながない）
3. 案3：遠い距離だけ速さを上げる（例 50km を超えたら新幹線の速さ）
4. 案4：経路検索の API（地図サービス）で実際の所要を取る

## 決定
案1と案2を合わせて採る。
- 契約：`clientPlaceSchema` に任意の `travelMinutes`（1〜720の整数）と `farTrip`（boolean）。無い古いデータはどちらも無し（保存データの版は変えない。項目ごと省く）
- 移動の行列（`matching/travel` の `travelMatrices`）：地点のどちらかに移動時間があればその分数（両側にあれば長いほう）、距離は 0 m。位置が未登録でも移動時間があれば「位置が未登録」の点（ADR-0093）を足さない（〈利用者さん〉の側も、〈スタッフ〉の自宅の側も。その組の移動は自宅の位置を使わないため）
- 遠方（出張）：問題の訪問に `solo: true`。`matching/timing` の strict（`scheduleRoute`・`routeCost`）は、遠方の訪問とほかの〈利用者さん〉の訪問が同じ列にあれば不可（`soloBroken`。同じ〈利用者さん〉の2回はよい）。列の最初の遠方の訪問は、家を出る時刻を勤務の開始に縛らない（訪問そのものは勤務の時間に収める）。solver・自動の組み・振り直し・空き状況はこの2関数を通るので、可否の表（`allowed`）は変えない
- 手で同じ列に入れたときは evaluate の採点で守れない条件（`notAllowed`、文「遠方（出張）の日はほかの訪問を入れません」）
- 担当なしの理由（evaluate の explain）：候補の担当ごとに、遠方の日なら「遠方（出張）の日はほかの訪問を入れません」（ruleId `farTrip`）、その訪問だけでも家からの移動で間に合わなければ「移動が間に合わない（片道 約N分）」（ruleId `travelTooFar`）。キー・文の頭は `matching/travel`、見分けと直し方の案内は `lib/travelReasons` の `travelReasonOf`（理由の案内を出す画面が使う）
- 交通費：移動時間を決めた区間の距離は 0 m（交通費に入れない）。新幹線・飛行機の代金は距離×単価で表せないため。決まった額の交通費の欄は持たない（要るという声が出たら別に決める）
- 表示：〈利用者さん〉の画面の場所の節に入力と読むだけの「移動」、訪問の詳細・日の予定の訪問の詳細に「遠方（出張）・移動 片道N分・家を出る目安 H:MM」（目安＝開始−移動。遠方で移動時間のある人だけ）

## 理由とトレードオフ
- 得るもの：遠方の人も組める。ほかの訪問とつないで実際には回れない案を出さない。担当なしの理由が「移動」と分かる
- 失うもの：移動時間は〈利用者さん〉ごとに1つで、出発地（自宅・前の訪問先）による違いを表せない。遠方の日はその担当の残りの時間を使わない（出張の日に近くの訪問を足す使い方はできない）。距離 0 m のため交通費の見込みは少なく出る
- 捨てた案：案3 は速さの境目と新幹線の駅までの時間を決められず、遠くても車で行く人と区別できない（〈利用者さん〉ごとの事情を表せない）。案4 は外部へ毎回送ることになり、送るのは押したときの住所の検索だけという決まり（ADR-0016）に反し、キーと費用が要る
