# ADR-0060：予定の日・週・月の上に同じナビの行を置き、上の帯に貼り付ける

- 日付：2026-10-24
- 状態：採用
- 関連：PRD D347、ADR-0054（予定の共通の部品）・ADR-0058（操作の行の位置）・ADR-0044（上の帯の日付の選択）

## 背景
- 日付の送りが2か所にあった（上の帯の日付の選択と、月・週のカードの左上の月送り・週送り）。［月｜週｜日］のタブの位置も画面ごとに違い、確定・メールで送るのボタンの位置もばらばらだった
- 一般的なカレンダーアプリ（［今日］［‹ ›］期間［月｜週｜日］の1行）と比べ、どこで送るか・切り替えるかを探させていた

## 選択肢
1. 案A：見出しの下に「［今日］［‹ 期間 ▾ ›］［月｜週｜日］……確定」の1行を3画面で同じ位置に置き、予定の3画面では上の帯の日付の選択を出さない
2. 案B：上の帯の日付の選択を表示している単位で送るように変え、カードの中の送りをやめる。［月｜週｜日］は見出しのすぐ下に固定
3. 案C：案A の1行を広い画面では上の帯の下に貼り付ける（sticky）

## 決定
案C。
- 共通の部品 `components/ScheduleNav.tsx` を見出しのすぐ下に置く。左から「今日」・期間の select（‹ ›）・［月｜週｜日］、右に操作（日：状態の印・メールで送る・確定。週：メールで送る・まとめて確定。月：無し）
- 送る単位は表示している単位（月は1か月、週は1週、日は1日）
- 上の帯の日付の選択（`DateSwitcher`）は `/plan`・`/week`・`/month` では出さない（`DATE_PAGES` から外す）。月・週のカードの中の送りはやめる
- 861px 以上で上の帯の下に貼り付ける。高さ（`--sched-nav-h`）は `ResizeObserver` で測り、巻いて止める位置の計算（`scroll-padding-top`）が使う（決め打ちにしない）。860px 以下は貼り付けず折り返す。印刷では期間の文だけ出す
- キーボードの送り（←→ など）は札のキー（ADR-0056）とぶつかるので入れない

## 理由とトレードオフ
- 得るもの：送り・切り替え・確定が3画面で同じ位置。表示している単位で送るので、月で「次の日」を押して迷うことが無い。巻いても送り・確定が押せる
- 失うもの：広い画面では1行（約 64px）を上に使い続ける。案を比べる・勤務の見込みなどでは上の帯の日付の選択が残るので、予定の3画面とほかの画面で日付の場所が違う
- 案B は変更が少ないが、［月｜週｜日］と送りが離れたままなので取らない

## 影響
- `components/ScheduleNav.tsx`・`ViewSwitch.tsx`・`pages/MonthPage.tsx`・`WeekPage.tsx`・`PlanPage.tsx`・`lib/nav.ts`（`DATE_PAGES`）
- 見直す条件：ほかの日付の画面（案を比べる・勤務の見込み）でも同じ行が欲しくなったら、上の帯の日付の選択をやめてこの部品に寄せる
