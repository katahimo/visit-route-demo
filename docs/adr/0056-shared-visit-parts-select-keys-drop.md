# ADR-0056：訪問の帯の印・選ぶ・キー・ドラッグの落とし先の判定を共通の部品にする

- 日付：2026-10-22
- 状態：採用（週の表・月のマスの訪問の見せ方は ADR-0057）
- 関連：PRD D339〜D341・D333、ADR-0054（予定の共通の部品）・ADR-0051（スマホは見る・取り消す・担当替えまで）

## 背景
- 日・週・月・人の予定表の本体はそれぞれ別に育ち、共通なのは見出し・操作の行・訪問の詳細の欄・提案の帯・全体の元に戻すだけだった
- 困っていたこと：
  - 複数選択とキーで動かすのが日と週の時間軸だけで、ほかの画面ではできない
  - 帯の印（要対応・ピン・未連絡の変更・資格✗／限✗）の判定が画面ごとに別で、「この画面だけ判定が古い」がレビューで何度も出た
  - ドラッグの落とし先の判定（今日より前・時間の幅・同じ行の決まり）も画面ごとに別

## 選択肢
1. 案A：日・週・月・人の予定表を1つの本体に作り直す
2. 案B：本体は画面ごとに残し、印・選ぶ・キー・落とし先の判定を共通の部品（純粋関数＋小さなフックと部品）にする
3. 案C：今のまま、画面ごとに足りない所だけ足す

## 決定
案B。

- **印**（PRD D339。`lib/visitLook`・`VisitMarks`・`useVisitLooks`）：要対応・資格✗／限✗・未連絡の変更・ピン・この回だけ変更・仮押さえの判定の元を1つにする。資格✗・限✗があれば同じことを言う要対応は重ねない。取り消し・休みの回は未連絡の変更だけ。今日より前の日は要対応・資格✗／限✗を出さない（月のマス・ホームと同じ）
- **選ぶ**（PRD D340。`lib/visitSelect`・`useVisitSelection`）：Shift／Ctrl＋クリック・Enter で1件ずつ、Esc で外す。スマホは長押しか「選ぶ」。今日より前・取り消し・休みは選ばない。選んだ訪問は複数選択の帯（`SelectionBar`。`lib/multiEdit`）。期間を変えたら外す
- **キーで動かす**（PRD D333・D340。`lib/visitKeys`・`useVisitKeys`）：↑↓ 15分・←→ 1日・Shift+←→ 隣の担当・Enter 欄・Delete 取り消し。休み・取り消し・今日より前の回は動かさない。日時を動かさない所（〈スタッフ〉の画面）は ↑↓←→ を読まない。スマホではキーを読まない
- **ドラッグの落とし先の判定**（PRD D341。`lib/visitDrop`・`useVisitDrag`）：置けない（取り消し・休み・今日より前・ほかの人の行・7:00〜20:00 の外）は灰の影と理由で落とせない。置けるが入らない（入れる人が0人・担当できない人の行）は赤い影と理由で、落とせるが要対応になる。確定した日・繰り返しの回は影に添える。落とすと落とした日時（・担当）を入れた訪問の詳細の欄が開く
- **1行1訪問の行**（`VisitRow`）：選ぶ印・時刻・名前と担当・印。スマホの日ごとのリスト・人の予定表の2段目・月のその日のリストで同じ
- 画面ごとに残すもの：日の時間軸と地図・欠勤の振り直し・差の欄、週の時間軸と表の並べ方、月のマス、人の予定表の足す・空き枠
- データを書くのは store の update だけ（キーは `lib/visitOps`、選んだ訪問は `lib/multiEdit`、ドラッグは欄の保存）。どの操作も全体の元に戻すの1手

## 理由とトレードオフ
- 得るもの：どの画面でもマウスなしで訪問を選ぶ・動かす・担当を替える・取り消せる。印の判定の元が1つで、種類を足すときは `visitLook` だけを直せばよい。ドラッグで「なぜ置けないか」が影の文で分かり、どの画面でも同じ
- 失うもの：
  - 今日より前の日に要対応の印を出さない（日の予定の時間軸も）
  - 〈スタッフ〉の画面の複数選択の帯に「時刻をずらす」は出さない
  - 人の予定表の回の aria-pressed は繰り返しの強調でなく選択を表す
  - 日・週・月・人の予定表の本体は4つのまま（共通は部品だけ）
- 案A は画面ごとの違い（日の地図・欠勤の振り直し・月のマス）が大きく、1本に畳むと条件分岐だらけになるので取らない。案C は判定の食い違いが続く
- 置けない影は drop を受けず、入らない影は落とせる（落として要対応にするかは人が決める）

## 影響
- `lib/visitLook`・`visitSelect`・`visitDrop`・`visitKeys`、`components/visitParts.tsx`、各画面（`PlanPage`・`WeekPage`・`MonthPage`・`PersonCalendar`）
- 設計書：design/pages-common.md（共通の部品）ほか各画面
- 見直す条件：日の予定の帯の詳細と訪問の詳細の欄の2か所の重なりが保守の負担になれば、本体の統合（案A）を見直す
