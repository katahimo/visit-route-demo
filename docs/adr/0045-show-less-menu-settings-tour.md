# ADR-0045：見せる量を減らす：初回は「基本」、設定を1つのタブ群に、ツアー3枚、操作の行の「その他 ▾」

- 日付：2026-10-21
- 状態：採用（メニューの項目は ADR-0054・ADR-0063 で組み替え。今は 予定を組む・予定・空き状況・人・設定などの6項目）
- 関連：PRD D273〜D279、ADR-0024（下のタブ）・ADR-0025（ツアー）・ADR-0028（機能の入り切り・ひな形）・ADR-0034・ADR-0036

## 背景
個々の文言・手順より量が問題だった。初めて開くと機能のひな形が「すべて」で、メニューの項目が多く、初回の案内が6枚、月と日の操作の行にボタンが7〜8個並んだ。「訪問の種類」「特性の項目」「条件の重み」「管理者設定」「データ」はふだんの作業ではたまにしか開かない設定で、メニューに独立して置く理由が薄い。
制約：契約・URL（古いブックマーク）は変えない。保存データがある人の機能の入り切りは変えない（全部入りだった人は全部入りのまま）。e2e のためだけの分かれ道をアプリに置かない。主ボタンは画面に1つ。

## 選択肢
- 初回のひな形：A 保存データが無いときだけ「基本」で作り、案内の1枚目で「基本／すべて」を1問だけ聞く／B 契約の既定値（`orgSchema.features`）を「基本」にする／C 今のまま
- 設定のメニュー：A メニューは「設定」1項目にし、切り替えは画面の上のタブ／B 設定を1画面にまとめる／C メニューのグループを畳めるようにする
- 操作の行：A 毎日使う操作だけ出し、ほかは「その他 ▾」（`MenuButton`）へ／B 2段に分けて出したまま／C 今のまま

## 決定
いずれも A。

- 初回の判定は store（`loadWithStatus` の `fresh`。保存データが無い）。入り切りは案を作る前に入れ（`createInitialData(today, features)`）、計算に効く機能が食い違わないようにする。1枚目の選択は初めて自動で開いたときだけ出し、1枚目を離れるときに当てる。ほかの変更が入っていれば入り切りだけ書き換える。「初期状態に戻す」は今の入り切りを残す（事業所の設定なので）
- e2e・デモの前準備用に、別のキー `vrdemo:features:start` が `all` なら初回もすべて入で始める（画面からは書けない）
- 設定は「設定」1項目と、上のタブ［訪問の種類｜特性の項目｜条件の重み｜管理者設定｜データ］（相性は ADR-0047 で「人」へ）。項目は最後に開いたタブを開く。URL は変えず、パレットは1画面ずつ引ける
- ツアーは3枚：ホーム（＋初回の1問）／予定で組んで確定／欠勤・キャンセル
- 月・日の操作の行は主ボタンと毎日使う操作だけにし、表示の選択・印刷・訪問を追加・メールで送る・使い方などは「その他 ▾」へ。月の凡例はマスの色を読む唯一の手がかりなので「その他 ▾」に入れない。表示の選択は、〈スタッフ〉・〈利用者さん〉・混み具合を選んでいる間・休みの入力中はたたまない

## 理由とトレードオフ
- 得るもの：初めての人の画面が「基本」の機能だけになり、1問で「すべて」にも戻れる。設定がメニューで1項目になる。ツアーは初見で読み切れる。操作の行が主ボタンと毎日使う操作だけになる。URL・契約・保存データのある人の入り切りは変わらない
- 失うもの：設定の各画面へは1手増える（パレットでは1手）。月・日の「その他 ▾」の中の操作は1手増える。「基本」を選んだ人は、条件の重みなど入れていない機能があることを管理者設定を開くまで知らない（1問の説明と注記で補う）。「どこまで使いますか」は初めて自動で開いたときだけで、答えずに読み直すと2度目は出ない（管理者設定のひな形で選び直す）
- 捨てた案：初回の B は features の無い古いデータ・控えまで「基本」になり、全部入りだった人の画面が変わる。C は量が減らない。設定の B は今の URL・部品を作り直すことになる。C は畳んだ中身が見えず探す手間が変わらない。操作の行の B は量が減らない
- 見直す条件：初回の「基本」でほぼ全員が「すべて」を選ぶなら、初回の既定を「すべて」に戻す
