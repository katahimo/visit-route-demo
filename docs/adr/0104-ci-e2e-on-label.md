# ADR-0104：CI の e2e は PR に「e2e」のラベルを付けたときだけ走らせ、perf は手動と夜間、記録は失敗のときだけ3日残す

- 日付：2026-11-06
- 状態：採用
- 関連：ADR-0029・ADR-0041

## 背景
PR への push のたびに、速い検査・e2e（4つに分けたジョブ）・perf の6ジョブが走っていた（1回あたり待ちを含めて30分ほど）。手直しで何度も push すると、そのたびに e2e が最初から走り、途中の push の分は取り消される。
報告（playwright-report）を成功のときも14日残していたため、Actions の保存の容量の上限に当たり、テストが通ってもジョブが落ちた。非公開のリポジトリでは実行の分数の無料枠（月2000分）にも当たり、ジョブが始まらなくなった（2026-11-06。公開に切り替えて戻した）。

## 選択肢
1. 案A：速い検査は push ごと。e2e は PR に「e2e」のラベルを付けたとき（と付いた PR への push）・手動・夜間。perf は手動・夜間。記録は失敗のときだけ3日
2. 案B：e2e は main に入ったあと（push）に走らせる
3. 案C：今のまま（push ごとに全部）

## 決定
- 案A
- `pull_request` の `types` に `labeled` を足す。速い検査はラベルを付けただけの実行では走らせない。e2e は PR では「e2e」のラベルがあるときだけ。perf は `pull_request` では走らせない
- ラベルを付けたときの実行と push の実行は `concurrency` の組を分け、互いに取り消さない
- playwright-report・test-results は失敗のときだけ残し、`retention-days` は 3
- 手動（workflow_dispatch）はブランチを選んで e2e と perf を全部走らせられる。夜間（週1回）は今までどおり全部

## 理由とトレードオフ
- 得るもの：手直しの push では数分の速い検査だけで済む。e2e は仕上がった時に1回。保存の容量を使い切らない
- 失うもの：ラベルを付け忘れると e2e を通さずにマージできる。マージの前に「e2e」のラベル（か手動の実行）で通すことを手順にする。perf の後退は夜間まで気づかない
- 捨てた案：案B は壊れたものが main と公開に入ってから気づく。案C は分数と保存の容量を使い切る

## 影響
- AGENTS.md・design.md の CI の説明を直す
- e2e を見たい PR には「e2e」のラベルを付ける（エージェントは GitHub のラベルの付与か、手動の実行で）
