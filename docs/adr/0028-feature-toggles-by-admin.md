# ADR-0028：管理者設定で機能を入り切りし、事業所に要る機能だけの画面にする

- 日付：2026-10-19
- 状態：採用（初回の既定・設定の置き場所は ADR-0045）
- 関連：PRD D210〜D216、ADR-0025・0027（メニュー・パレット）

## 背景
事業所によって要る機能が違う。訪問介護・移動支援（直行直帰・毎週固定）は当日キャンセル・欠勤の振り直し、拘束・交通費、担当替えが要り、訪問看護（〈利用者さん〉が多い）は第N曜日・曜日ごとの時刻、休み、鍵・駐車場の決まりごと、空き状況の案内文、担当を限る、月の印刷が要る。相手の業務に無い機能がメニュー・欄・ボタンに並ぶと画面が重く、ほかの法人に提案するときも同じことが起きる。利用者の依頼は「管理者設定で ON/OFF して、必要な機能だけのすっきりした画面に」「ひな形は法人名を出さず機能的な名称に」。

制約：ログインは作らない（PRD §4。1ブラウザ＝1事業所）。データの版は変えない（欠けた項目は zod の既定値）。外部送信は増やさない。機能を切ってもデータは消さない（入り直せば戻る）。

## 選択肢
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 単位A：画面の単位 | 単純 | 欠勤・メール・道順・月の印刷のような画面の中の欄・ボタンが切れない | 不採用 |
| 単位B：機能の単位（約20） | 画面の中の入口まで1つの名前で切れる | 組み合わせが増え、URL の直書きを表に寄せる作り直しが要る | 採用 |
| 単位C：業種のひな形だけ | 最も簡単 | 事業所ごとの細かい違いを表せない | 不採用 |
| 持ち方A：`org.features`（DemoData） | JSON の控えで設定ごと渡せる | 初期状態に戻すと消える（のち ADR-0045 で戻しても残す） | 採用 |
| 持ち方B：別の localStorage キー | 控え・初期化に入らない | 他の端末・人へ渡せず、事業所の設定と人の状態が混ざる | 不採用 |
| 効き方A：画面から隠すだけ（データは AI案に効く） | 実装が軽い | 隠れた設定が案に効き、「なぜこの担当か」で説明できない（PRD §5 の納得感） | 不採用 |
| 効き方B：好み・決まりは計算からも外す（事実は残す） | 見えない条件が出ない。入り直せば効く | 切り替えると案が変わる | 採用 |
| ひな形A：「適用」で一度だけ書き込む | 個別の直しが素直。業種と連動しない | 適用後の変更は自分で管理 | 採用 |
| ひな形B：業種で自動決定し差分で持つ | 業種を変えれば追従 | 状態が二重になり説明しにくい | 不採用 |

## 決定
機能の単位（20）で入り切りし、設定は `org.features` に持つ。ひな形は「適用」ボタン。切った好み・決まりは計算からも外し、事実は効かせ続ける。

- 持ち方：`src/contracts/features.ts` の機能 ID の一覧と `featuresSchema`（ID → boolean の部分表。知らない ID は捨てる）。無い ID は「入」なので、昔のデータ・控えは全部入りのまま
- 機能の一覧の正は `lib/features.ts`（名前・説明・グループ・依存・URL（ルート・`?do=`）・ひな形の表。依存先が切なら依存元も使えない）。画面へは `useFeature(id)` と `<Feature id>`。データを書き換えるのは store の `update(fn)` だけ
- 常に出す土台（切れない）：ホーム・予定（月・週・日）・〈利用者さん〉一覧・〈スタッフ〉一覧・勤務時間（シフト）・訪問の種類・管理者設定・データ
- 切れる機能：毎月の第N曜日・曜日ごとの時刻、〈利用者さん〉の休み、希望休のまとめ入力、月の印刷、案を比べる、欠勤・キャンセル（入口と欄だけ切り、すでに振り直した結果は残す）、空き状況、空き枠の案内文、相性、担当を限る、段階・紹介元、訪問先の決まりごと、退職・担当替え、勤務の見込み、交通費、条件の重みとプリセット、メール、道順のリンク、郵便番号・住所の検索、Excel の入出力（控えの JSON は残る）
- 出し分け：メニュー・下のタブ・上の帯・パレットはメニューの決まり（`menuSections`）から自動で消える。ルートは、切った機能の URL（`?do=` 含む）を開くとホームへ移し（replace）「この機能は設定で切っています」の知らせを出す。パレットの操作・ホームのカード・ツアーの枚・行き先のリンクは表から引く。画面の中の欄・ボタンは `<Feature id>` で囲む
- 計算への効き方：切った好み・社内の決まり（相性・担当を限る）は matching の compile も読まない（隠れた設定が案に効くのを避ける）。事実（〈利用者さん〉の休み・欠勤と希望休・最終勤務日・繰り返しの展開）は切っても効かせ続ける（外すと休みの人に訪問が入るため）。solver・evaluate は変えない
- ひな形（法人名・出典は画面に出さない。適用は一度だけ書き込む出発点で、あとから個別に直せる。適用前に独自の確認で差を出す）：基本（予定・欠勤・空き状況・相性・道順・住所の検索）／労務・契約管理（基本＋勤務の見込み・交通費・退職・段階）／月次予定・現場共有（基本＋第N曜日・休み・希望休・月の印刷・案内文・担当を限る・決まりごと・Excel）／すべて。条件の重みとプリセット・案を比べる・メールは「すべて」だけが入
- 設定の画面は管理者設定（ひな形4つ＋グループごとのスイッチ。依存先が切なら押せず理由を出す。押すとすぐ保存）。鍵・ログインなしでだれでも開ける（デモなので受け入れる）。設定の画面と土台の画面は切れないので戻れなくなることはない

## 理由とトレードオフ
- 得るもの：事業所に要る機能だけのメニュー・画面になる。ひな形で最初の設定が1手。データを消さないので試しに切っても戻せる。デモで「どの機能を切ったか」が要件の材料になる（PRD §1）
- 失うもの：入り切りの組み合わせが増え確かめる範囲が広がる。切った機能の条件が案から外れるので、切り替えると案が変わる。ログインが無いので、だれでも管理者設定を開いて戻せる
- 見直す条件：デモでほぼ全員が同じ機能を切るならその機能の既定を「切」に。1つの機能の中で一部だけ要る声が多ければ機能を分ける

## 影響
`contracts/features.ts`・`lib/features.ts`・`lib/nav.ts`・`lib/links.ts`・`lib/commandPalette.ts`・`lib/tour.ts`・matching の compile・`pages/SettingsPage.tsx`・各画面の `<Feature>`。PRD §4 に「ログイン・権限で設定を守る・機能ごとの料金」はやらないを記す。
