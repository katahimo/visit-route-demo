# ADR-0028：管理者設定で機能を入り切りし、事業所に要る機能だけの画面にする

- 日付：2026-10-19
- 状態：採用（初回の既定・設定の置き場所は ADR-0045、エキスパート機能と単発のみのひな形は ADR-0072）
- 関連：ADR-0025・0027

## 背景
事業所によって要る機能が違い、業務に無い機能が並ぶと画面が重い。ログインは作らない。機能を切ってもデータは消さない。

## 決定
機能の単位で入り切りし、設定は `org.features` に持つ。ひな形は「適用」で一度だけ書き込む。
- `src/contracts/features.ts` の機能 ID と `featuresSchema`（ID → boolean。知らない ID は捨て、無い ID は「入」）
- 機能の一覧の正は `lib/features.ts`（名前・説明・グループ・依存・URL・ひな形）。依存先が切なら依存元も使えない。画面は `useFeature(id)`
- 切れない土台：予定（月・週・日）・〈利用者さん〉一覧・〈スタッフ〉一覧・勤務時間・訪問の種類・管理者設定・データ
- 出し分け：メニュー類は `menuSections` から自動で消える。切った機能の URL はトップへ移し「この機能は設定で切っています」。画面の中は部品で `useFeature` を見る
- 計算：切った好み・決まり（相性・担当を限る）は compile も読まない。事実（休み・欠勤・希望休・最終勤務日・繰り返しの回）は切っても効かせる
- ひな形（法人名は出さない。適用前に差を確認）：単発のみ／基本／労務・契約管理／月次予定・現場共有／すべて
- 設定はだれでも開ける（デモなので受け入れる）

## 捨てた案
画面の単位（画面の中の欄が切れない）・業種のひな形だけ（細かい違いを表せない）・別の localStorage キー（他の端末へ渡せない）・隠すだけで計算に効かせる（説明できない条件が案に効く）。

## トレードオフ
- 失うもの：組み合わせが増え確かめる範囲が広い。切り替えると案が変わる
- 見直す条件：ほぼ全員が同じ機能を切るならその既定を「切」に
