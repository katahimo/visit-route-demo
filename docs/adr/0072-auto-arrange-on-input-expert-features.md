# ADR-0072：希望日時を入れたら入れた分だけ自動で組み、標準・案比べ・条件の重みはエキスパート機能にする

- 日付：2026-10-29
- 状態：採用（実装は第1段＝入口の整理、第2段＝自動の組みの順）
- 関連：PRD D372〜D378、ADR-0062（組み方の標準）・ADR-0063・ADR-0065〜ADR-0067（予定を組む）・ADR-0053（AI は提案を出すだけ）・ADR-0028（機能の入り切り）・ADR-0042（月まとめて）・ADR-0054（元に戻す）

## 背景
- 利用者の声：Web アプリが複雑になった。〈利用者さん〉・〈スタッフ〉の情報と希望日時を入れたら、入れた分を自動で組めば足りる
  - 案を比べる・組み方の標準・条件の重み・予定を組む4段（基本情報 → 案 → 標準 → 担当）は、組み方を作り込みたい人の道で、ふだんの人には手順が多い
  - 訪問看護・介護は曜日・時刻の繰り返しが大半で、自動に入る日付は翌月まで。それ以外はカレンダーで日ごとに登録する
  - ベビーシッター型は日々の単発の予約だけが入り、新しい訪問が毎日増える。毎回「予定を組む」へ行く作りは合わない
- 制約：ログイン・サーバーは無い（ADR-0001）。`Math.random`・`Date.now` は solver に入れない。今の標準の担当・ピン・伝えた日の予定は壊さない

## 選択肢
1. 自動で組んだ結果の扱い
   - A：即反映して「元に戻す」1手（ADR-0054 の履歴）。結果は知らせの1行で見る
   - B：入力のたびに提案の帯を出し、［反映する］を押す（ADR-0053 のまま）
2. 組む範囲
   - A：入れた分（新しい訪問・日時を変えた訪問）のうち、担当が無くピンも無く伝えていない日のものだけ。ほかの担当は固定
   - B：その日・月を丸ごと組み直す
3. 標準の担当（`usualStaffId`）
   - A：内部に残す。繰り返しを入れて自動で組んだ担当を繰り返しの担当に書く（以後の週は同じ人）。画面で「標準」と呼ぶのはエキスパートだけ
   - B：廃止して毎回組む
4. ベビーシッター型の出し分け
   - A：新しい業種の設定は作らず、ADR-0028 のひな形で「繰り返し」の機能を切る
   - B：業種（型）の設定を新設して入力画面を分ける
5. エキスパート機能の持ち方
   - A：機能 ID `expert`（既定は切）を足し、案を比べる（`compare`）・条件の重み（`rules`）・組み方の標準・予定を組むの4段をその配下にする
   - B：機能を個別に切るだけ（入口が散らばる）

## 決定
1-A・2-A・3-A・4-A・5-A（利用者が推奨どおりに決めた。2026-10-29）。

### ふだんの道（`expert` が切のとき）
1. 〈利用者さん〉・〈スタッフ〉を登録（メニュー「人」。ADR-0067 で予定を組むへ移した基本情報の画面をこの項目へ戻す）
2. 希望日時を入れる
   - 繰り返し（曜日・時刻）：保存すると、今日から翌月末までの回を自動の対象にする。回は今までどおり見るときに計算する（ADR-0053）
   - 単発：予定（月・週・日）のカレンダーで日を選んで訪問を足す。繰り返しは使わない
3. 保存の直後、入れた分だけ自動で組む

### 自動の組み（`lib/autoArrange`。純粋関数。範囲は 2-A）
- 対象：担当なし・ピンなし・伝えていない日・開始日が今日以降の訪問のうち、今の入力で増えた・日時が変わったもの
- 固定：ほかの訪問の担当は、手でも AI でも、すべてピンと同じに扱う（動かさない）。伝えた日は組まない
- 考え方：今の点数の基準（プリセット）。標準が無くても組む（D356 の「標準が無い間は組まない」はエキスパートの画面だけの決まり）
- 反映：store の `update` 1回（1手）で書き、知らせに「N件の担当を組みました」と［元に戻す］。組めない訪問（受けられる人がいない）は担当なしのまま、日の予定の「受けられる人」で手で選ぶ
- 繰り返しの担当：繰り返しを入れて組んだときだけ、その担当を繰り返しの担当（`usualStaffId`）に書く。単発・手直しからは書かない（手直しを黙って覚えない。ADR-0053）
- 走らせ方：保存時に1回。アプリを開いただけ・基本情報が変わっただけでは走らせない（走らせるのは人が入力したとき）。取りこぼし（休み・勤務の変更で担当が外れた分）はホームの「担当なし N件」から［組む］で同じ関数を呼ぶ
- 重い日・月は `monthBatch` と同じく Worker で計算し、待つ間は知らせの帯に進み具合を出す

### エキスパート機能（`expert`。ADR-0028 の機能の1つ。既定は切）
- 入れると、いまのメニュー（ホーム・予定を組む・予定・空き状況・設定）と、予定を組む4段・組み方の標準・案を比べる・条件の重みの入口が出る（ADR-0062・ADR-0063・ADR-0065〜ADR-0067・PRD D350〜D364 のとおり）
- 切のメニューは ホーム・予定・人・空き状況・設定。「予定を組む」は出さず、AI で組むのは入力のときの自動と、ホームの［組む］、欠勤の振り直しだけ
- `compare`・`rules` は `expert` が切のとき使えない（依存。ADR-0028）。初期データ・ひな形の「基本」は `expert` を切で始める。昔のデータ・控えは ID が無いので「入」のまま（ADR-0028）

### ベビーシッター型（4-A）
- ひな形に「単発のみ」を足す（繰り返しの機能を切り、〈利用者さん〉の画面から繰り返しの欄を隠す）。入力は予定のカレンダーで足す単発だけ。足すたびに自動で組む（毎日増える訪問が、その日のぶんだけ組まれる）
- 単発は担当が日ごとに変わってよく、繰り返しの担当には書かない

## 理由とトレードオフ
- 得るもの：初めての人は登録と希望日時の入力だけで予定ができる。毎日増える単発も、入れた分だけ即組まれる。エキスパート機能は残るので、組み方を作り込む使い方も消えない
- 失うもの：提案を見て反映する確認を外すので、結果の確認は知らせと元に戻すに頼る（ADR-0053 の「AI は提案を出すだけ」を、自動の組みに限って「即反映」へ変える。標準の登録・まとめて組む・欠勤の振り直しは今のまま提案）。範囲を固定するので、全体の点数は最適にならない（ほかの担当は動かさない約束との引き換え）
- 見直す条件：デモで自動の結果に「勝手に組まれた」という戸惑いが多ければ1-B（提案の帯）へ戻す。単発だけで繰り返しのひな形が要らないなら 4-A のひな形は不要
