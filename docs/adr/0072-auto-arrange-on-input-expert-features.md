# ADR-0072：希望日時を入れたら入れた分だけ自動で組み、標準・案比べ・条件の重みはエキスパート機能にする

- 日付：2026-10-29
- 状態：採用・一部を ADR-0100 で置き換え（組み方の標準。メニューは ADR-0073・0074・0078、担当なしを組む入口は ADR-0077）
- 関連：ADR-0028・0042・0053・0054・0062・0063・0065〜0067

## 背景
アプリが複雑になった。人と希望日時を入れたら入れた分を自動で組めば足りる。標準・案比べ・条件の重み・予定を組むの段は作り込みたい人の道。ベビーシッター型は単発の予約が毎日増える。

## 決定（利用者が決めた）
### ふだんの道（`expert` が切）
- 繰り返しを保存すると今日から翌月末までの回を自動の対象にする（回は見るときに計算）。単発は予定のカレンダーで足す
- 保存の直後、入れた分だけ自動で組む

### 自動の組み（`lib/autoArrange`・`lib/autoArrangeBatch`・`components/autoArrangeHost`）
- 対象：担当なし・ピンなし・伝えていない日・今日以降の訪問のうち、今の入力で増えた・日時が変わったもの
- ほかの訪問の担当はすべてピンと同じに扱う。伝えた日は組まない
- 考え方は今の点数の基準。標準が無くても組む
- 即反映：store の `update` 1回で書き、知らせに「N件の担当を組みました」と［元に戻す］。組めない訪問は担当なしのまま
- 繰り返しを入れて組んだときだけ、その担当を `usualStaffId` に書く（単発・手直しからは書かない）
- 走らせるのは保存時だけ。重い範囲は Worker で、待つ間は帯に進み具合
- 呼び出しは `pages/usePatternsFlow`・`components/useVisitPanel`

### エキスパート機能（機能 ID `expert`。既定は切）
- 入れると予定を組むの段・組み方の標準・案を比べる・条件の重みが出る。`compare`・`rules` は `expert` に依存
- 初期データ・ひな形「基本」は切で始める。昔のデータは ID が無いので入
- 特性の項目（`#/items`）は条件の重みの画面なので、切では開けない

### 繰り返しの機能（機能 ID `patterns`。既定は入）
- `patternMonthly` は `patterns` に依存
- 切ると〈利用者さん〉の画面の繰り返しの欄（`PatternsSection`）を隠す。今ある繰り返しの回は予定に出続ける
- ひな形 `oneOff`「単発のみ」（先頭。基本と同じで `patterns`・`expert` が切）。業種の設定は作らない

## 捨てた案
入力のたびに提案の帯（ふだんの人には手順が多い）・その日・月を丸ごと組み直す（ほかの担当が動く）・業種の設定を新設（入力画面が二重）。

## トレードオフ
- 失うもの：自動の組みに限って「AI は提案だけ」（ADR-0053）を即反映に変える（標準の登録・まとめて組む・欠勤の振り直しは提案のまま）。範囲を固定するので全体の点数は最適にならない
- 見直す条件：「勝手に組まれた」という戸惑いが多ければ提案の帯に戻す
