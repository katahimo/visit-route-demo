# ADR-0098：担当なしの訪問の組めない理由を型に分け、直し方と直す画面を案内する

- 日付：2026-11-03
- 状態：採用
- 関連：ADR-0089・0093・0095・0096・0028

## 背景
AI で自動に組んでも「担当なし N件」が残るが、組めない原因が利用者に見えなかった。要対応の帯は件数だけ、組んだ後の知らせは「66件の担当を組みました」で残りの件数も理由も無く、2.5秒で消えた。訪問の詳細は全員に「必須の条件に合いません（働ける時間に収まらない）」と並ぶだけで、何時まで働けるか・どこで直すかが無い。勤務日外（土日）の訪問は「担当を替える」の候補がその日に働く人に絞られ、人も文も出なかった。日の予定の担当なしの理由の札はエキスパート機能が切だと出さない。遠方の理由（移動が間に合わない）は evaluate の explain にだけあり、移動時間・遠方（出張）の設定に気づけなかった。

## 選択肢
1. 案1：今ある判定（compile の可否の理由・evaluate の担当なしの理由）を、画面のための純粋関数で型にまとめ、型ごとに短い理由・案内・直す画面を決める
2. 案2：matching に「組めない型」の判定を足し、Problem の infeasible に載せる
3. 案3：理由の札（infeasible の上位3つ）を切でも出すだけにする

## 決定
案1を採る（`lib/unassignedReason`。PRD D430）。
- 人ごとの原因：可でない人は problem.reasons の Infinity の理由の型（直しても入れない型を先に：担当できる人の限定・必須の条件・相性×・最終勤務日の後・欠勤・勤務日外・勤務時間外）。可の人は evaluate の `unplacedCauses`（explain の担当なしの理由と同じ `staffCause` を1人ずつ返す。判定は増やさず、whyUnassigned を分けただけ）の ruleId から、遠方（出張）の日・移動が間に合わない（位置が未登録の組なら位置なし）・1日の上限・入れられる・重なり
- 主な型：入れるのに直すもの（可でない理由の型の数）がいちばん少ない人たちの中で、入れられる人がいればそれ、無ければ多い型（同じなら型の順）。内訳は主な型を先に多い順に人数（「勤務時間外 9人・欠勤 2人」）
- 案内は型ごとに1〜2文。勤務時間外は勤務の時間帯（その人たちの時間帯）と訪問の時間から始まり・終わりをいつにするか、勤務日外は曜日、移動・遠方は `lib/travelReasons` の案内に具体例（東京へ新幹線なら片道 120〜180分）
- リンクは型ごと。移動・遠方は〈利用者さん〉の場所の節を開いて移動時間の欄へフォーカスする URL（`clientTravelHref`、`?focus=travel` を欄が拾って消す）。守れない条件の関連の画面（`lib/hardLinks`）もそろえる。切った機能の行き先は画面で外す（`linkIfOn`）
- 見せ方：訪問の詳細の枠、日の予定の担当なしの札の下（入切とも控えめ）、「担当を変える ▾」の空の項目、「入らない N」の一覧の行、要対応の帯の内訳、自動の組みの知らせ（残りの件数・内訳・［理由を見る］、20秒）
- 予約の読み込みの確認の「勤務日・時間に入らない」も内訳（勤務日外・勤務時間外）を同じ言葉にする

## 理由とトレードオフ
- 得るもの：どの画面でも同じ判定・同じ言葉で、何を直せば組めるかが分かる。matching・solver の問題と採点は変わらない
- 失うもの：理由は表示のたびに計算する（担当なしの訪問ごとに、可の人の列へ入れてみる）。帯は今日から翌月末の担当なしの訪問の日ごとに計算するので、担当なしが多い日は少し重い。主な型は目安で、複数を直さないと組めない場合（担当できる人が勤務日外など）は内訳を見て判断する
- 捨てた案：案2 は matching に画面の都合の型を持ち込み、solver が使わない計算を毎回増やす。案3 は「働ける時間に収まらない（11人）」のような事実だけで、どこをどう直すかが無い
