# ADR-0103：上の帯に「戻る」「進む」を置く・日の予定の地図を入切とも全幅のカードにする・選択肢の多い特性を全幅の列に並べる

- 日付：2026-11-06
- 状態：採用
- 関連：ADR-0073（日の予定の地図をボタンで開く点を置き換え）・ADR-0074

## 背景
- リンク（要対応の帯・人の名前・探すなど）で別の画面へ移ったあと、元の画面への戻り方が分からないという声があった。ブラウザの戻る・Alt＋←は知らない人がいる
- エキスパート機能が切の日の予定は、地図のカードを置かず、右下の「地図」のボタンで開く形だった（PRD D385）。ひな形「すべて」（入）では大きな地図が出るのに、ほかのひな形では出ず、違いが分かりにくい。大きな地図は下にあり、邪魔にならない
- 資格の選択肢が増え、特性の入力の2列のうち資格の欄だけが縦に長く伸び、隣の列に大きな余白ができた

## 選択肢
1. 案A：上の帯の左端にアイコンの「戻る」「進む」を常に置く。地図は入切とも全幅のカード。選択肢の多い複数選択は横幅いっぱいにし、選択肢をそろった列に並べる
2. 案B：画面ごとに「〇〇に戻る」のリンクを足す。地図は表示の切り替えのボタンを足す
3. 案C：今のまま（ブラウザの戻るに任せる・切は地図をボタンで開く）

## 決定
- 案A
- 「戻る」「進む」は `components/HistoryNav`（react-router の `navigate(-1)`・`navigate(1)`）。戻れるかは履歴の番号（`history.state.idx`）、進めるかはこの画面で開いた中のいちばん先の番号で決め、無ければ押せない
- 日の予定は入切とも地図のカード（`plan-map`）を置く。`MapDock` の `target` が null の形（いつも「地図」のボタン）と、浮かせた地図の「全員のルートを見る」は使わなくなったので消す
- 特性の入力（`TraitsEditor`）で、選択肢が6つより多い複数選択の項目は横幅いっぱい（`.field-wide`）にし、選択肢を `.option-checks`（幅のそろった列）に並べる

## 理由とトレードオフ
- 得るもの：Alt＋←を知らなくても戻れる。ひな形による地図の出方の違いが無くなる。資格の欄の横の余白が無くなる
- 失うもの：上の帯にボタンが2つ増える。切でも日の予定のページが地図の分だけ長くなる
- 捨てた案：案B は画面ごとに戻り先を決める手間が大きく、漏れが出る。地図の切り替えのボタンは、地図が邪魔にならないので要らない

## 影響
- PRD D385（日の予定の地図）を直し、D438（戻る・進む）を足す。design の pages.md・pages-common.md・pages-plan.md を直す
- e2e：`scripts/e2e-simple-menu.cjs` の日の予定の地図の段を、切でも地図のカードがある形に直す
