# ADR-0011：当日の急な欠勤を別の記録で持ち、他の人の予定を変えずに空き時間へ振り直す

- 日付：2026-10-13
- 状態：採用（振り直しの結果を訪問に書く形は ADR-0053、入口の欄は ADR-0025・0038）
- 関連：PRD D26〜D35・D167〜D172、ADR-0007・0010

## 背景
利用者から「当日のスタッフの急な欠勤で、他のスタッフのそれまでの予定を極力変えずに、欠勤の人の訪問を振り直したい」と要望が出た。終日だけでなく、途中の欠勤（午前だけ付き添い、早退、遅刻）も扱う。
稼働時間を上書きして全部組み直すか、ドラッグで1件ずつ移すしかなかった。

- 全部組み直すと欠勤と関係ない人の担当・順番・時刻まで変わり、連絡が増える（当日は連絡自体が負担）
- 稼働時間を上書きすると元の時間が消え、「なぜ減ったか」が残らない
- ドラッグでは、誰に移せば入るかを人が探すことになる

## 選択肢
| 案 | 長所 | 短所 | 採否 |
|---|---|---|---|
| 欠勤1-A：稼働時間の上書きに書く | データが増えない | 元の時間が消え取り消せず、理由が残らない | 不採用 |
| 1-B：別の記録（absences） | 消せば元に戻る。メモが残り連絡文に使える | 差し引く処理が2か所 | 採用 |
| 振り直し2-A：挿入だけ（案A） | 他の人は変わらないと保証・テストできる。決定的で一瞬。理由を説明できる | 少し動かせば入る訪問も入らない | 採用（1回目） |
| 2-B：変更の減点つき焼きなまし（案B） | 少し動かして入れられる | 重みが大きいと案A と同じになる | 採用（2回目） |
| 2-C：全部組み直し | 最適に近い | 無関係な人まで変わる | 不採用 |
| 減点：担当が変わる1件を3段（小・中・大）にする | 単純 | 条件の重みの物差しと別 | 不採用（重み w を採用） |
| 減点を採点にも足す | solver と合計点が一致 | 案どうしを比べる物差しが動く | 不採用 |

## 決定
欠勤は別の記録で持ち（1-B）、案A（挿入だけ）で振り直し、「少し動かしてよい」案B を選べるようにする。処理は新コンポーネント `reassign` に置く（運用の規則の変更が matching・solver へ波及しない）。

- データ：`DemoData.absences`（`{ id, staffId, date, from, to, note }`。from が null＝始業から、to が null＝終業まで、両方 null＝終日）。30分単位（午前／午後の境は 12:00）、1人1日1件。Excel に「欠勤」シート
- 差し引き：働ける時間帯を決めるのは `domain/availability.ts` だけ、を保つ。compile が欠勤を差し引き、`Problem` の形は変えない
- 元の案：確定した割当があればそれ、無ければ今の担当
- 振り直す訪問：欠勤の人の訪問のうち、欠勤と重なるものすべて（後ろへずらせば入る訪問も欠勤の人のまま残さない）・欠勤のせいで可でなくなる訪問・残すと strict で回れなくなる訪問
- 案A：他の人の担当・順番・開始時刻は変えず、入れられる人の少ない順に、費用の増えが最小の strict の位置へ1件ずつ入れる。訪問の時刻は変えない（間に合わなければ違反の赤い枠）、件数の上限は超えない。決定的で Worker 不要
- 案B：`Problem.stay` で「変更を減らす」重み w（0〜5・0.5刻み・既定3。担当が変わった訪問1件＝w×10点、開始のずれ1分＝w×0.2点）を solver の費用にだけ足す。採点・点数には入れない（案A・案B・欠勤前を同じ物差しで比べる）。案A を初期解に渡すので案B は案A より悪くならない
  - 案A に入っていた訪問は落とさない：`ProblemStay.keep` の訪問を落とす点を `KEEP_DROP_POINTS`（`DROP_POINTS`×10）にし、他の訪問を落として入れ替えることを防ぐ
  - 保険（`settleAnneal`）：keep の訪問が欠ける・案A の費用が有限でない・案B が案A より高い、のどれかなら案A を返し理由を出す
  - 案A に可でない組・strict で回れない・上限超えの列がある人は、その列だけ案A のまま外して案B を作り、「手で直してください」と出す
- 結果：訪問に担当を書き、担当のいる訪問をすべて固定する。続けて振り直すときは最初の元の案を引き継ぎ、差も「元に戻す」も最初の元の案に対して。欠勤の取り消しでは担当を戻さず、「元に戻す」で戻す
- 候補から入れる（`placeVisit`）：空き時間に入らない人は後ろの訪問の開始が遅れうるので、遅れる件数・最大の分を候補に出し、押したとき確認する
- 連絡の一覧（PRD D35）：元の案と今の案の差から、担当が変わる訪問先・時刻が変わる訪問・仕事が増減するスタッフと、連絡文（コピー・印刷のみ。送信しない）
- 「いまの時刻」は扱わない：「いまの時刻より前に始まる訪問は動かさない」規則にすると、当日の午前の訪問が欠勤の人の列に赤印のまま残った。過去の欠勤は登録しない運用とし、時刻で動かさない訪問は設けない
- 欠勤のせいの訪問（absence・unreachable）だけを欠勤の人のまま残る訪問に数える。notAllowed は必須の違反の赤い枠で出す

## 理由とトレードオフ
- 得るもの：欠勤を消せば元の稼働時間に戻り、メモが残る。案B は solver・Worker・決定性をそのまま使え、`stay` が無い問題は従来と同じ
- 失うもの：
  - 案A は局所的で全体最適ではない（点数は下がりうる）。欠勤と重なる訪問は幅があってもすべて振り直すので、欠勤明けに詰め込まない方を選んだ
  - 案B では進み具合の内部の費用と採点が一致しない。ほかの訪問を外さないと入らない訪問は案B でも入らない（入れ替えは人が候補を見て決める）。「重みが大きいと案A のままになることがある」と画面に出す
  - すでに伺った訪問も欠勤と重なれば振り直す案になる（過去の欠勤は登録しない前提）。時刻が30分単位なので 10:15 の早退などは丸める
- 見直す条件：入らない訪問が多く手で入れる手間が大きいとき。1日に複数の欠勤の時間帯が要るとき。午前に遡った欠勤を登録したい、または始まった訪問を動かしたくないとき。連絡文の言い回し・閾値の要望。案B が遅い（30人・150件で数秒超）とき

## 影響
- 主なモジュール：`reassign`（案A・案B・差・連絡の一覧）、`matching`（欠勤の差し引き・`stay` の減点）、`solver`（初期解 `initial`）、`lib/absences`・`lib/contacts`、欠勤・キャンセルの欄
