# ADR-0075：ほかのソフトの CSV を「形の一覧」で読む（予約システムのスタッフ・顧客・予約）

- 日付：2026-10-31
- 状態：採用

## 背景
ベビーシッターの事業所から、予約システムが書き出したスタッフ・顧客・予約の CSV（匿名化したもの）をもらった。
スタッフ・顧客は名簿として、予約は訪問として読みたい。顧客台帳（ADR-0073）は `rosterCsv` に1つだけ直に書いていたが、
今後も別の会社のソフトの CSV が増える見込みがあり、形を足すたびに読み込みの本体・画面・契約を直すのは避けたい。

予約システムの CSV は UTF-16LE のタブ区切り（スタッフは UTF-8 BOM のカンマ区切り）で、緯度・経度は「38.3, 140.8」の1列、
日付は「2026.3.31」「2026/12/05」、予約時は「AM枠 10:00～12:00」のように書かれる。予約の「新規登録者」は予約を入れた人で、担当とは限らない。

## 選択肢
1. 案A：形ごとに読み込みの関数と画面の入口を作る
2. 案B：形の一覧（レジストリ）を作り、形ごとのファイルは「列名で見分けて、共通の中間の形に写す」だけにする。読み込み・突き合わせ・確認の画面は共通
3. 案C：列の対応を利用者が画面で選ぶ（列の割り当ての画面）

## 決定
案B。
- 名簿：`excel/rosterForms.ts` の `ROSTER_FORMS`（id・label・kind・`toRoster`・`errorMessage?`）。`toRoster` は CSV の表を名簿の列の表に写す。
  あとは今の名簿の読み方（`rosterRows`）で読む。顧客台帳（`ledgerCsv`）もここに載せた
- 予約：`excel/bookingForms.ts` の `BOOKING_FORMS`（id・label・`toBookings`）。`toBookings` は CSV の表を `Booking`（予約番号・日付・開始・所要・名前・取り消し・メモ）に写す。
  `importBookings` が共通で〈利用者さん〉と名前で突き合わせ、ID `bk-〈形のID〉-〈予約番号〉` の単発の訪問（時刻固定・担当なし）を足す・直す
- 列名の比べ方・読まなかった列・同じ名前の分け方（`distinctNames`：同じ名前は全員「名前（ID）」）・誤りの文の列名の直し（`columnMessage`）・`clip`・`RosterTable` は `excel/csvColumns.ts` に共通の部品として置く
- 元のソフトで空のことが多い欄（緯度・経度・住所・メールなど）は、形ごとに `keepBlank` で「空なら今の値のまま」にし、アプリで入れた値を読み直しで消さない
- 同じ名前の顧客は全員に顧客IDを添える（2人目だけに添えると、ファイルの並びが変わったときに人が入れ替わる）。予約の名前がこの分けた人に当たるときは、どの人か分からないので入れない
- 契約：`RosterImportResult.ledger` を `otherForm: OtherFormRead | null`（形の名前 `label` と `skippedColumns`）に一般化。`BookingImportResult` を足す
- 新規登録者は担当にしない（担当は「担当を組む」で決める）。同じ予約番号の訪問は読み直すと直し、担当・ピンは残す

## 理由とトレードオフ
- 得るもの：別の会社の CSV は「形ごとのファイル1つ＋一覧に1行」で足せる（テストは形ごと）。画面・契約・確認の文は変えなくてよい
- 失うもの：列名で見分けるので、列名を変えたファイルは読めない（その形を一覧に足す）。案C の柔軟さは無い。
  顧客の名前で予約と突き合わせるので、同じ名前の顧客がいると予約を入れない（名前と件数を出す）

## 影響
- PRD D396〜D398。design.md の excel・design/contracts.md・design/pages-data.md・design/pages-clients.md
- 予約の CSV の欄はデータの画面（`excel` の機能が入のとき）
- 読まない列（パスワード・世帯の情報・緊急連絡先など）はデータに残さない
- 見直す条件：形が増えて列名の見分けがぶつかる（どちらでも読める列名）ときは、一覧の順か、ファイルを選ぶときに形を選ぶ欄を足す
