# ADR-0053：担当は訪問に持ち、AI は提案だけ、確定は伝えた内容、繰り返しの回は見るときに計算する

- 日付：2026-10-22
- 状態：採用（AI を使う入口と標準の担当は ADR-0062・0063）
- 関連：ADR-0004・0010・0011・0012・0035・0042・0051

## 背景
訪問の状態が定期パターン・展開した訪問・案と記録・確定した割当などの層に分かれ、覚える言葉が多かった。デモなので古いデータは移さない。

## 決定
### データの形
- `Visit` に `staffId`（null＝担当なし）・`start`（組んだ開始）・`pinned`。`pattern.edited` は時刻・日付・所要・種類・メモを変えた回（担当・開始・ピンだけでは edited にしない）
- `DemoData.snapshots`（date → 伝えた内容。`ToldVisit = { id, clientId, staffId, start }`）と `reassigns`（date → 振り直す前の担当 `baseRoutes` など）。AI の案・記録・確定した割当は持たない
- `Pattern.usualStaffId`（繰り返しの担当）。〈利用者さん〉は担当を持たない
- `data.rules` の重み・必須は repair が点数の基準にそろえる
- 前の版のデータは移さず、知らせて初期データで始める（`isOutdated`・`OUTDATED_MESSAGE`）

### 繰り返し（`src/patterns/`）
- `visitsOn`・`visitsIn`：保存した訪問と、利用中の〈利用者さん〉の繰り返しの計算した回（ID `${日}_${パターンID}`。同じ ID の保存した回が優先）。計算した回の担当は繰り返しの担当。`putVisits` は書くとき保存した回にする
- `splitPattern`：分けた日以降の変えていない保存した回は消し、変えた回は ID を付け直す。`removePattern`：今日より前に始まった繰り返しは昨日で終わらせ、変えた回は単発にする
- 〈利用者さん〉を終了にすると続く繰り返しを昨日で終わらせる
- 回の ID が変わったあとは、伝えた内容を同じ〈利用者さん〉・同じ元の日の回に読み替えて比べる

### 日の割当と確定（`lib/dayPlan.ts`・`confirmDay.ts`）
- `writeRoutes` が担当と開始を訪問に書く（提案の反映・ドラッグ・担当を変える・振り直しが使う）
- 訪問ごとの検査 `visitIssues`：担当なし・担当が休み・条件に合わない・時間に間に合わない。重みだけの変更では要対応にしない
- 確定＝`tellDay` が今の担当・開始を `snapshots` に書く。`toldChanges`（連絡の一覧）・`toldStateOf`（`none`・`told`・`changed`）
- 日の状態は まだ伝えていない／確定済み／未連絡の変更あり。月の要対応は 要対応・未連絡の変更・拘束超の3種

### 画面
- 日の予定で担当・手直し・ピン・「確定（伝えた）」（変更があれば「確定し直す（伝えた）」）。開いた日に自動で作らない
- AI は提案を出すだけで［反映する］まで訪問は変わらない。比較（`#/compare`）はその場の提案で、保存しない
- 欠勤の振り直しは `writeRoutes` で書き、`reassigns` に前の担当を残す。最後の段「連絡・確定」で伝えた内容を書く
- 元に戻すは store の履歴（ADR-0054）
- 初期データ：繰り返しは前の月の1日から、昨日までは「伝えた」状態（`withPastTold`）
- Excel：訪問に担当・開始・ピン、繰り返しに担当

### 持たないもの
AI の実行の記録・開いた日の自動作成・この日だけ試す重み・「条件が変わった」の判定・手直しの記憶・条件の変更の控え。

## 捨てた案
層のまま言葉だけ減らす（層が残る）・前の版のデータを移す（移行が重い）。

## トレードオフ
- 得るもの：状態が「訪問ごと」と「日ごと」の2軸になり、どの画面も同じ訪問を読む。確定が現場の意味（伝えた）になる
- 見直す条件：重みだけ変えたとき「組み直すと点が上がる日」を知らせたい声が多いとき
