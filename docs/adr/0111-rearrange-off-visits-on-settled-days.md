# ADR-0111：休みの人の訪問は、決まった日（伝えた日）でも自動で組み直し、希望休のあとも自動で組む

- 日付：2026-11-08
- 状態：採用（ADR-0089 の「伝えた日の訪問は動かさない」を休みの人の訪問に限って外す。ADR-0014 の「希望休で担当は変えない」をエキスパート機能が切のときに限って置き換え）
- 関連：ADR-0011・0013・0014・0072・0073・0089・0107・0108

## 背景
エキスパート機能が切では、自動で組んだ日は今日から1か月先まで決まった（伝えた）扱いになる（ADR-0073）。一方、自動の組みで要対応の訪問を
組み直すのは「伝えた記録の無い日」だけ（ADR-0089 の `isMovable`）。このため、自動で組んだあとに休み（休みのカレンダーの取り込み・希望休・
貼り付け）を入れると、休む人の訪問は「休みの人」の要対応に出るのに、取り込みのあとの自動の組み（D442）でも［要対応を組む］でも組み直せず、
日の予定で1件ずつ手で振り直すしかなかった。月の「休みを追加」（希望休）は、そもそも組みを走らせない（ADR-0014）。
利用者の要望は「自動で組んだあとに休みを入れると予定が外れる。そのあと自動で組み直してほしい。手作業を減らしたい」。

## 選択肢
1. 案A：休みの人の訪問だけ、伝えた日でも組み直してよい対象にする。希望休を付けた日にその人の訪問があれば、取り込みのあとと同じ組みを走らせる
2. 案B：休みを入れたら、その日の伝えた記録を消す（組み直したあとで決まった扱いに戻す）
3. 案C：今のまま（日の予定の欠勤の欄で振り直す）

## 決定
案A（エキスパート機能が切のとき）。
- 自動の組み（保存のあと・［要対応を組む］・読み込み・取り込みのあと）で、担当がその日に欠勤（希望休・カレンダーの休みも）を持つ要対応の訪問は、伝えた日でも組み直す。終日の休みは「休みの人」、時間の休み（AM休みなど）は「間に合わない」「重なり」になるので、種類ではなく欠勤の有無で見る。欠勤の無い人の間に合わない・重なりは今までどおり伝えた日なら動かさない。ピンの訪問・エキスパート機能が入は動かさない
- 保存のあとの組み（D405）もその日の欠勤のある人の要対応を組み直す。日の予定で「欠勤だけ登録」した日も、あとでその日の訪問を保存すると組み直される（保存はその日を直す操作なので）
- 伝えた記録は書き換えない。組み直した訪問は「変更あり」に出る（連絡の一覧から休む人・代わる人へ連絡する）
- 月の「休みを追加」で希望休を付けた日に、その人の組み直せる要対応の訪問（ピンでない）があり、その日が今日〜翌月末なら、その日のその訪問だけを組む（`offDayTargets`・`requestOffArrange`。ほかの日・ほかの要対応は組まない）。欄の文は「ほかの人に自動で組み直します」。組み直せる訪問が無ければ今までどおり日の予定での振り直しを案内する。外したときは組まない
- 日の予定の欠勤の欄の「欠勤だけ登録」は、利用者が振り直さないと選んだので今までどおり組まない

## 理由とトレードオフ
- 得るもの：休みを入れるだけで、休む人の訪問がほかの人に移る（取り込み・貼り付け・希望休とも）。日の予定で1件ずつ振り直す手間が無くなる
- 失うもの：決まった日の担当が黙って変わる（知らせの［元に戻す］で戻せ、「変更あり」に出る）。希望休を続けて付けると、付けるたびにその日の組みが走る（順に待つ）。欠勤のある人の、休みと関係の無い間に合わない・重なりも伝えた日に組み直す
- 案B を捨てた理由：伝えた内容との差（変更あり）が消え、誰に連絡するかが分からなくなる
- 案C を捨てた理由：要望に合わない

## 影響
- PRD D446（D69・D403 を直した）。PRD §4・design.md §2 の「確定を勝手に作り直すこと」「欠勤を入れただけでの振り直し」に例外を書いた
- `lib/autoArrange` の `isMovable` に帯の種類を渡す（`lib/dayStatuses` の `bandIssueKinds`）。希望休のあとに組む訪問は `offDayTargets`、依頼は `lib/autoArrangeBatch` の `requestOffArrange`
- 見直す条件：決まった日の担当を勝手に変えられたくない声が出たとき（休みの人も［要対応を組む］を押したときだけにする）
