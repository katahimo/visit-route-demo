# ADR-0065：標準を決める道を組み方の標準の画面1本にし、「予定を組む」を 条件の重み → 組み方の標準 → 担当を組む の3段にする

- 日付：2026-10-25
- 状態：採用
- 関連：PRD D349・D350・D354〜D357・D233、ADR-0064（日の考え方ごとの案。この ADR で置き換え）・ADR-0063（予定を組む）・ADR-0062（組み方の標準）・ADR-0035／ADR-0010（点数の基準）・ADR-0047（設定のタブの並び）

## 背景
- 条件の重み・組み方の標準・担当を組むは「考え方（重み）を決める → 標準の週を決める → 標準で埋まらない所を埋める」という1本の流れの段なのに、置き場所と働きがばらばらだった
  - 「考え方ごとに案を作って比べる」が2か所にあった。担当を組むの日の範囲（`monthBatch` の `variants`。1日・手のピンが効く・選ぶとその曜日だけ標準）と、組み方の標準の①（`standardDraft.runProposals`。周期の週数・ピンを効かせないひな形・表）。計算も登録（`registerDayStandard` と `registerStandard`）も別
  - 考え方（点数の基準）を替える所が3つ（条件の重みのラジオ・標準の登録・「この案を標準にする」）、さらに担当を組むではその場だけ別のプリセットで組めた
  - 条件の重みは「設定」、ほかの2つは「予定を組む」にあった
  - 担当を組むの画面が、標準の有無で2通りに化けた（標準が無いと週・月は組めず、日だけが考え方ごとの案）
  - 条件の重みの画面に版1の名残（この日だけ試す重み・まとめて作る・自動作成・作り直し）が残っていた
- 利用者の指定：案を比べるとき、表だけでは判断しにくい。今の考え方ごとの案のように、今日の予定と同じ担当ごとの時間軸と地図で見たい

## 選択肢
1. 標準を決める入口
   - A：組み方の標準の画面に1本にする（①案をくらべる → ②表で直す → ③標準にする）。担当を組むの日の考え方ごとの案は無くす
   - B：担当を組むの1日の案に1本にし、標準の画面は表の見直しだけにする。曜日ごとに何度も選ぶ手間がかかる
   - C：入口は2つのまま、計算と登録の決まりだけそろえる。画面の分かりにくさが残る
2. 条件の重みの置き場所
   - A：「予定を組む」の子へ移し、作業の順（条件の重み → 組み方の標準 → 担当を組む）に並べる
   - B：組み方の標準の画面の段に入れ、`#/rules` を無くす。画面が長くなる
   - C：設定に残し、言葉だけ直す
3. 担当を組むの「考え方（プリセット）を選んで組む」
   - A：無くし、いつも点数の基準（標準の考え方）で組む
   - B：残す

## 決定
1-A・2-A・3-A（利用者が決めた。2026-10-25）。比べる段には、担当ごとの時間軸と地図の見せ方を残す（利用者の指定）。

### 流れ（予定を組む の3段）
| 段 | 画面 | 決めること | 書くもの |
|---|---|---|---|
| ① | 条件の重み `#/rules` | 考え方（プリセット）の中身（重み・必須）と、ふだん使う考え方（点数の基準） | `presets`・`scorePresetId`・`rules` |
| ② | 組み方の標準 `#/standard` | 標準の週（誰が・何曜・何時）。考え方ごとの案を比べて選び、表で直して登録 | 繰り返しの担当・標準の開始・`standard`・（案から作れば）`scorePresetId` |
| ③ | 担当を組む `#/arrange` | 範囲（月・週・日）の、標準で埋まらない所の担当 | 訪問（提案を反映したときだけ） |

- メニューの「予定を組む」の子とタブ（`ArrangeTabs`）は 条件の重み・組み方の標準・担当を組む の順。設定のタブから条件の重みを外す（設定は 訪問の種類・特性の項目・管理者設定・データ）。URL は変えない
- 考え方を替えるのは ①（点数の基準のラジオ）と ②（案から作った表を登録したとき）だけ。③ はいつも点数の基準で組む

### ② 組み方の標準：比べる段に時間軸と地図
- 案は今までどおり `runProposals`（期間＝来週の月曜から周期の週数・プリセットごと・ひな形）。各日の問題と割当（`ProposalDay` と同じ形）を案に残す
- ①案をくらべる に「日で見る」を置く：期間の日を選び、タブ（今の標準・案ごと。点・今の標準から担当が変わる件数。いちばん点の高い案に王冠）で切り替え、選んだ案をその日の担当ごとの時間軸と地図で見る（担当・時刻が変わる訪問に印。名前・訪問・区間を押すとその担当に絞る）。部品は今の考え方ごとの案の帯（`ChoiceBand`）の中身を、提案の入れ物に縛られない形にして使う
- 「今の標準」のタブは、同じ日の計算した回を今の標準の担当・開始のまま並べたもの（ひな形どうしで比べる）
- 選ぶのは今までどおり［この案から作る］（下書きへ）→ 表で直す → ［この表を標準にする］。登録の決まり（いつから・入れ替える／残す・考え方を点数の基準に）は `registerStandard` の1つだけ

### ③ 担当を組む
- いつも点数の基準で組み、標準の担当は変えず、標準で埋まらない所を埋める（ADR-0062）。考え方の選ぶ欄は置かない
- 組み方の標準が無い間は、範囲（月・週・日）にかかわらず AI で組まず、「先に組み方の標準を決めてください」の文と［組み方の標準を決める］（`#/standard`）だけを出す。ホームの「はじめに組み方の標準を決める」も `#/standard` へ
- 範囲の提案は1つの形（考え方ごとの案 `choices` は無い）

### 無くすもの
- `monthBatch` の `variants`・`choices`・`apply` の `choice`・`andThen`、`lib/standard` の `registerDayStandard`・`dayStandardPreview`、予定の画面の「〈日〉の案（N つ）を担当を組むでくらべています」の1行、比較の画面の考え方ごとの案
- 条件の重みの画面の版1の名残（この日だけ試す重みの文・`rules-trial-note`・作り直しの帯・`trialPresetOf` を使う表示・「まとめて作る・自動作成・作り直し」の文）

## 理由とトレードオフ
- 得るもの：標準を決める道が1本になり、案の計算・登録の決まりも1つになる。「予定を組む」のタブを左から順に進めば、考え方 → 標準 → 埋める の流れになる。考え方を替える場所が2つに減り、担当を組むの画面は標準の有無で姿を変えない。比べる段で表と時間軸・地図の両方を見て選べる
- 失うもの：
  - 1日の案から1手で標準にする近道は無くなる（案から作る → 標準にする の2手と確認）
  - 案に手で付けたピンは効かない（ひな形のまま）。その日の事情は担当を組む・手直しで扱う
  - 担当を組むで、その場だけ別の考え方で組むことはできない（比べるのは組み方の標準の①か、案を比べるの画面）
  - 設定のタブで条件の重みを覚えた人は「予定を組む」を探す
  - 案の計算は期間の日数ぶん（今と同じ）。日で見るは計算済みの割当を出すだけで、計算は増えない
- 1-B は曜日ごとに何度も選ぶ。1-C・2-C は散らばりが残る。2-B は画面が長くなり、重みの下書きと標準の下書きが1画面で混ざる
