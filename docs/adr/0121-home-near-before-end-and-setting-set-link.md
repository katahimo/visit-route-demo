# ADR-0121：帰りの前は自宅に近い人（勤務の終わりの N分前から）と、設定のひな形をリンクで適用する

- 日付：2026-11-22
- 状態：採用
- 関連：ADR-0026・0028・0092・0101・0116。PRD D455・D478〜D482

## 背景
顧客のご意見2件：
1. 条件「夕方は自宅に近い人」（ADR-0116）は「開始（早）が 17:00 以降の訪問」で固定している。勤務の終わりが人ごとに違う
   （16:00 に上がる人・20:00 まで働く人）ので、「その日の帰りの前の訪問を、自宅の近い人に」したい。どこからを帰りの前とみるかも事業所で変えたい
2. 事業所ごとに、管理者設定の機能の入り切りといくつかの設定をまとめて変えたい。サーバー・ログインは無く（ADR-0001）、
   公開 URL は複数の事業所が同じものを使うので、ある事業所向けの設定を更新で全員に当てるわけにはいかない

## 選択肢
帰りの前（1）：
1. 案A：対象を「訪問の終わり（開始（早）＋所要）が、候補の〈スタッフ〉のその日の勤務の終わりの N分前より後」にする。勤務の終わりは
   compile が使う稼働（勤務時間・その日の上書きから欠勤を引いた時間帯）の最後の終わり。N は条件の行の省略可の欄 `beforeEndMin`（既定60）
2. 案B：時刻の境（17:00）を条件の欄で変えられるようにする（人ごとの勤務の違いに合わない）
3. 案C：その人のその日の最後の訪問の帰りの移動に重みを掛ける（列の費用。ADR-0116 の案H。solver・evaluate の差分評価が変わる）

名前（1）：
1. 案D：「帰りの前は自宅に近い人」に変える。前の名前のままの条件は読み込み（repair）で今の名前にし、Excel の種類・重みの見出しは前の名前でも読む
2. 案E：名前を変えない（夕方に限らなくなったのに「夕方」と出る）

設定をまとめて変える（2）：
1. 案F：コードに「設定のひな形」を持ち（`lib/settingSets`）、`#/settings?apply=<ID>` のリンクを開いた人に確認（変わる項目の一覧）を出して、［適用］で書く
2. 案G：更新で全員に自動で当てる（ほかの事業所の動きが変わる）
3. 案H：設定のファイル（JSON）を渡して読み込んでもらう（ファイルの受け渡しと取り違えの手間。控えの読み込みはデータ全体を入れ替える）
4. 案I：更新の知らせ（ADR-0102）にボタンを置く（全員に見え、押し間違えるとほかの事業所の設定が変わる）

## 決定
- 帰りの前は 案A。境目ちょうどに終わる訪問は含まない（`訪問の終わり > 勤務の終わり − N`）。その日に稼働の無い人（休み・終日の欠勤・勤務なし）は
  勤務の終わりが分からないので対象外（その人はもともと可否で外れる）。勤務の終わりは人ごとなので、同じ訪問でも人によって対象かが変わる。
  開始（早）で見るのは ADR-0116 と同じ（時間に幅のある訪問の実際の開始は組むまで分からず、割当費用は組の前に決める）。
  点（移動1分＝重み×0.2点）・達成（自宅まで15分以内）・必須にできないことは変えない。割当費用なので solver と evaluate の合計点は一致し、再現性も変わらない
- N は条件の行（`Rule.beforeEndMin`。0〜600 の整数。省略可）。無い古いデータ・プリセット・Excel は60。プリセットは型ごとの重みだけなので N を持たない
  （プリセットを当てても N は変わらない）。条件の重みの画面ではその行の重みの下に「勤務の終わりの［60］分前から」を置き、名前と同じくすぐ保存する
  （重みの下書きに入れない。重みと違い点数の基準の考え方と組にしないため）。Excel の条件のシートに省略可の列「勤務の終わりの何分前から」
- 名前は 案D。理由の文は「帰りの前：自宅まで N分」
- 設定をまとめて変えるのは 案F。
  - 確認は独自の確認ダイアログ（ADR-0026）。見出し「設定のひな形「…」を適用しますか？」、本文に「変わる項目（今 → 適用後）」の一覧
    （すでに同じ値の項目は出さない）・切れる機能のデータの件数と効き方（ADR-0028 の D215）・変えないもの。ボタンは［適用］［取り消す］。
    画面の言葉はひな形（ADR-0028）と同じ「適用」
  - 全部同じなら確認を出さず「すでにこの設定です」、知らない ID は「見つかりません」を知らせて何もしない。どの場合も答えたあと URL から apply を消す
  - 書くのは設定（`org.features`・条件・`org.lineTravel`）だけで、store の update を通す（Ctrl+Z・知らせの［元に戻す］で戻せる）。
    〈利用者さん〉・〈スタッフ〉・予定には触らない。データの版は上げない
  - 機能は書く ID だけ上書きし、ほかのスイッチは今のまま（機能のひな形（`applyTemplate`）は全部を書くが、こちらは部分を変える型）
  - 条件は「無ければ足す」（重みは［条件を追加］と同じ点数の基準のプリセットのもの、N は既定）。あれば重み・N を変えない（事業所が直した値を消さない）
  - 車の速さは今の値が地域に合わせた別の値でも上書きし、一覧に今の値を出して確かめてもらう。道路の所要を取ってあれば、車の速さがどの区間に効くかを一覧の下に添える
  - ID と名前は業務の型で、法人名を出さない（AGENTS.md）。最初の1つは `standard-start-no-shift`「ちょうどの時刻で組む・連絡を短く」
    （機能を切：開始時刻をずらして組む・〈利用者さん〉の特性・時間の決め方・〈利用者さん〉への訪問連絡・〈スタッフ〉あての変更の連絡に住所／
    帰りの前は自宅に近い人を足す／車の速さ 30km/h）

## 理由とトレードオフ
- 得るもの：帰りの前は人ごとの勤務に合い、境も事業所が決められる。割当費用のままなので solver・evaluate を変えない。
  設定のひな形はリンクを開いた事業所だけに効き、確認で今の値と新しい値を見てから決められ、間違えても元に戻せる。ほかの事業所は変わらない
- 失うもの：開始（早）で見るので、時間に幅のある訪問を遅らせて組んだときの実際の終わりとはずれることがある。
  N は条件ごとで、人ごとには決められない。設定のひな形はコードに足すたびに版を出す（リンクを送る相手ごとに型を作るのではなく、業務の型にまとめる）
- 捨てた案：案B は人ごとの勤務に合わない。案C は列の費用になり差分評価が変わる。案E は名前と中身が合わない。
  案G は公開 URL を使うほかの事業所の動きが変わる。案H は受け渡しの手間と、データ全体の入れ替えと取り違える恐れ。案I は全員に見え、押し間違えでほかの事業所の設定が変わる
