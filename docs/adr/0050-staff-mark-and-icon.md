# ADR-0050：〈スタッフ〉の印を1つの部品にそろえ、任意のアイコン（1〜2文字）を持たせる

- 日付：2026-10-22
- 状態：採用
- 関連：PRD D298・D299、ADR-0002（データの形）・ADR-0006・ADR-0020（Excel）・ADR-0017（メールアドレスを足したときの流儀）

## 背景
- 〈スタッフ〉の印が画面ごとにまちまちだった（色の点・色の線・小さな四角・〈利用者さん〉と同じ丸・アイコン・印なし）。色の出どころ（`staffColor`。全員を名前の順に並べた位置）は同じなのに、画面ごとに Map を作っていた。〈スタッフ〉のデータに色の欄は無い
- 「編集の欄でアイコンを登録できるとよい。既定は苗字の最初の漢字」という要望
- 制約：データの版は上げない（無い古いデータを既定で読めるなら）。画像は localStorage を圧迫するので持たない

## 選択肢
1. 案A：〈利用者さん〉と同じ丸に頭文字を〈スタッフ〉にも使う
2. 案B：〈スタッフ〉専用の部品（角の丸い四角に1〜2文字）を作り、〈利用者さん〉は丸のまま形で見分ける
3. 案C：色の点のまま大きさだけそろえる

## 決定
案B。
- `components/StaffMark.tsx` と `lib/staffMark.ts`。色は `staffColorMap(data.staff)` の1か所から引き、地図の線・列の上の線・週の帯の縁もこの関数にそろえる
- 形は角の丸い四角、大きさは4段（xs 16・sm 20・md 28・lg 44px）。〈利用者さん〉の丸は変えない
- 印は `aria-hidden`。文字は CSS の `attr(data-text)` で描く（DOM の文字にしない）ので、周りの textContent・コピー・読み上げ・e2e の文字の確かめが変わらない
- 契約：`Staff.icon`（前後の空白なし・32コード単位まで。`default('')`。無い古いデータは ''）。形に合わない値は読み込みを止める（メールアドレスと同じ）
- 見た目で2文字まで（書記素で数え、`Intl.Segmenter` に頼る）の検査は入れる所だけ：画面の保存（`staffIconError`）と Excel の読み込み（行番号つきで止める）。保存データの読み込み（zod）では見ない。環境による数え方の違いで保存データ全体が「壊れたデータ」にならないようにするため
- 既定の文字：名前を空白（全角も）で区切った先頭の語の最初の1文字（苗字の最初の1文字）。空白が無ければ名前の最初の1文字
- Excel：〈スタッフ〉のシートの「メールアドレス」の次に任意の「アイコン」の列

## 理由とトレードオフ
- 得るもの：どの画面でも同じ形・同じ色・同じ文字で〈スタッフ〉が分かる。地図の線・時間軸の帯と色がそろう。〈利用者さん〉とは形で見分けられる。同じ苗字の人はアイコンで見分けられる
- 失うもの：
  - JSON を手で書き換えれば3文字以上のアイコンも読めてしまう（画面・Excel からは入らない）
  - 色は名前の順で決まるので、名前を変えたり人を足したりすると色が替わる
  - 印の文字は CSS で描くので、印だけを選んでコピーしても文字は写らない
  - 細い行・チップの中で 10px の点より少し場所を取る

## 影響
- 設計書：design.md §4 store・§5 の `Staff` の型と Excel の列、design/pages.md の「〈スタッフ〉の印」、pages-staff.md
- テスト：`lib/staffMark.test.ts`、`excel.test.ts`
