# ADR-0012：訪問の種類と繰り返し（定期パターン）で一月分の訪問を持ち、月・週・空き状況で見渡す

- 日付：2026-10-16
- 状態：採用（繰り返しの回を保存せず見るときに計算する点は ADR-0053）
- 関連：ADR-0010・0053

## 背景
訪問は〈利用者さん〉ごとの繰り返しで、一月分を見渡し、問い合わせに空きを即答したい。種類（介護・リハビリなど）で担当に要る条件が変わり、種類は法人ごとに足したい。

## 決定
- 種類（`DemoData.visitTypes`）：名前・色・標準の所要時間・担当に必要な条件（〈スタッフ〉の特性への `Condition[]`）。最大20。訪問・繰り返しは `typeId`（null＝問わない）。compile は種類の条件を満たさない組を必須で外す（`ruleId: 'visitType'`）。条件の型・プリセット・物差しは変えない
- 定期パターン（`DemoData.patterns`）：〈利用者さん〉・種類・曜日・間隔・時間・`from`〜`to`（null＝続く）・いつもの担当・メモ。回の ID は `${元の日}_${パターンID}`。この回だけの変更・取り消しは訪問として残す（ADR-0053）
- 「以降すべて」：その日で分け（元の `to` を前日にして新しい繰り返しを足す）、変えていない回は新しい繰り返しで計算し直す
- 空き状況・問い合わせの試算：先4週の案に仮の訪問を入れて判定
- 月間に点数は出さず状態は色と印。30分ごとの空き人数の混み具合バー
- 別法人は1ブラウザ1事業所のまま、データを分ける

## 捨てた案
Excel で一月分を読み込む（手間）・前の週をコピー（曜日・間隔を表せない）・種類を選ぶと利用者の条件へ写す（種類を変えても条件が残る）。

## トレードオフ
- 失うもの：種類の条件を重みで緩められない。別法人を1データで切り替えられない
- 見直す条件：種類の条件を緩めたい声（条件の型 `typeRequirement` を足す）
