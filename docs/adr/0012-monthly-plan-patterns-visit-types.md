# ADR-0012：訪問の種類と繰り返し（定期パターン）で一月分の訪問を持ち、月・週・空き状況で見渡す

- 日付：2026-10-16
- 状態：採用（繰り返しの回を保存せず見るときに計算する点は ADR-0053）
- 関連：PRD D36〜D57、ADR-0010（点数の基準）、ADR-0053

## 背景
- 週・月の予定を一覧で見たい。新規の問い合わせに「どの曜日のどの時間が空いているか」を即答できず機会を逃している
- 訪問は利用者さんごとの定期パターンがあり、一月分をその繰り返しから作って日時をずらしたい
- 訪問に種類（介護・リハビリ）が欲しい。種類で担当に必要な条件が変わる。別法人（家事代行・ベビーシッター）もあるので、種類は利用者が自由に足せるようにしたい
- 担当に必要な条件は利用者さんの必要条件（`clients[].requirements`）だけで持っていた

決めること：訪問の出どころ・繰り返しの持ち方・種類の条件の効かせ方・別法人の扱い。

## 選択肢
- 出どころ：A 定期パターンから計算／B Excel で一月分を読込／C 前の週をコピー
- 種類の条件：A 種類のマスタの条件を常に必須／B 条件の型 `typeRequirement` を足す／C 種類を選ぶと利用者の必要条件へ写す
- 別法人：A データを分ける（1ブラウザ1事業所のまま）／B 1データに法人を持たせる

## 決定
定期パターンを訪問の出どころにし、種類のマスタの条件を必須で効かせ、別法人はデータを分ける。

- 種類（`DemoData.visitTypes`）：名前・色・標準の所要時間・担当に必要な条件（スタッフの特性に対する `Condition[]`）。最大20。訪問・パターンは `typeId`（null＝問わない）。matching の `compile` は種類の必要条件を満たさない組を必須で外す（理由 `ruleId: 'visitType'`）。条件の型・プリセット・点数の物差しは変えない
- 定期パターン（`DemoData.patterns`）：利用者さん・種類・曜日（複数）・間隔・時間の決め方・`from`〜`to`（null＝続く）・いつもの担当・メモ。パターンの回の ID は `${元の日}_${パターンID}`（決定的）。この回だけの変更・取り消しは訪問として残す（ADR-0053）
- パターンを直す（「以降すべて」）：「いつから」の日で分け（元の `to` を前日にして新パターンを足す）、その日以降の変えていない回は新しい繰り返しで計算し直す
- 空き状況・問い合わせの試算は先4週の案に仮の訪問を入れてみて判定する（ADR-0011 と同じ考え方）
- 月・週の見渡し：月間に点数は出さず、状態は色と印で表す。時刻つきの混み具合バー（30分ごとの空き人数）で空きを見せ、種類で数える人を絞れる。週間は〈スタッフ〉の複数選択・〈利用者さん〉×曜日の表
- 初期データ：利用者さんごとに繰り返し1つ（種類は介護・リハビリ）。リハビリの動きを見せるため資格に理学療法士などを足す
- 別法人：1ブラウザ1事業所のまま、データを分ける。種類は利用者が足す

## 理由とトレードオフ
- 得るもの：
  - 実業務の繰り返しに合い、先の月もすぐ見える
  - 種類のマスタの条件は業務上外せない条件で、条件の型・プリセット・物差しに波及しない
  - 種類を足せるのでどの法人でも同じ画面で使える
- 失うもの：
  - 種類の条件を重みで緩められない
  - 別法人を1データで切り替えられない
  - seed にリハビリがあるので、最適化のベンチマーク（`docs/optimization-benchmark.md`）の数値は seed に依る
- 捨てた案：B は入力の手間が大きく、C は曜日・間隔・期間を表せない。種類3-C は種類を変えても条件が残る
- 見直す条件：種類の条件を緩めたい声（3-B の `typeRequirement`）

## 影響
- 主なモジュール：contracts（`visitTypes`・`patterns`・`Visit.typeId`）、`src/patterns/`（繰り返しの回の計算）、matching（種類の必須）、vacancy、月・週の画面
- PRD §4 は勤務シフトの自動作成・日をまたいだ最適化をやらないとしている
