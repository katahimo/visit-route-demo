# ADR-0105：〈利用者さん〉に期間つきの訪問先（住所2）を持ち、訪問の日で訪問先を選ぶ

- 日付：2026-11-06
- 状態：採用
- 関連：ADR-0016・0075・0093・0096・0101

## 背景
ベビーシッター法人の予約システム（Reserva）の顧客の CSV に「住所2」「住所2[適用開始日]」「住所2[適用終了日]」の列がある。住所は契約者の住所で、住所2 があれば、その期間の訪問先は住所2（帰省先・実家・ホテルなど）。期間が空なら常に住所2。期間は1日だけのものから数か月のものまである。
〈利用者さん〉の場所は1つ（`Client.place`）で、移動の見積もり・地図・道順・メールはすべてこれを使っていた。顧客の正本は予約システムで、事業所は定期的に CSV を読み直す。

## 選択肢
1. 案A：読み込んだ日で住所か住所2 の一方を `place` に入れ、もう一方はメモに残す（読み直すたびに決め直す）
2. 案B：住所2 と期間を〈利用者さん〉のデータに持ち、訪問の日ごとに訪問先を選ぶ
3. 案C：訪問ごとに訪問先を持つ（訪問の上書き）

## 決定
案B。
- 契約：`Client.place2?: ClientPlace2`（住所・緯度・経度・郵便番号・`from`・`to`。日付は YYYY-MM-DD か空。空の端は限らない）。無い古いデータは住所2 なし（保存データの版は変えない）
- 判定は `domain/place2` の1か所：`place2On`（期間の両端を含む）・`placeOn`（その日の訪問先。住所2 の日は移動時間・遠方（ADR-0096）を付けない。これらは住所のもの）・`clientOn`（場所をその日の訪問先に置き換えた〈利用者さん〉）
- 使う所：その日の問題（`matching/compile`。移動の行列・遠方の印）、日の画面の共通の形（`components/useDayModel` の `clients`・`clientById`。日の予定・スタッフの予定・比べる・月・週が使う）、日のメール（`lib/mail`）、訪問の詳細と道順（`components/VisitPanel`・`useVisitRoute`・`lib/prevStop`）。これらで置き換えた〈利用者さん〉は表示と計算だけに使い、データの書き換えには使わない（書くのは store の data から）
- 道路の所要の表（ADR-0101）に住所2 の位置も入れる。まとめて緯度・経度を入れる（ADR-0016・PRD D89）は住所2 も1人分（「〈名前〉（住所2）」）として置く
- 入れ方：予約システムの顧客の CSV（ADR-0075）の「住所2」・期間を名簿の列「住所2」「住所2の郵便番号」「住所2の緯度」「住所2の経度」「住所2の開始日」「住所2の終了日」に写す。CSV の「緯度・経度」は住所2 があれば住所2 の位置。住所2 の列がある CSV で住所2 が空の人は住所2 なし（正本は予約システム）。列が無い CSV・ブックでは今のまま。同じ住所2 の空の位置・郵便番号は今の値を残し、住所が変われば空にする（古い位置を付けない。住所の列も同じ）
- Excel の全体のブック・名簿のブックにも同じ列（移動時間・遠方の次）。書き方シートに行
- 画面：〈利用者さん〉の画面の場所の節に住所2・期間・緯度経度を読むだけで出す（入力は CSV・Excel から）

## 理由とトレードオフ
- 得るもの：毎日読み直さなくても、期間の始まり・終わりの日に訪問先が変わる。先の予定（来週・来月）も期間どおりの訪問先で組める。住所（契約者の住所）を失わない
- 失うもの：場所が日によって変わるので、日を選ばない画面（〈利用者さん〉一覧・地図の点・住所の列）は住所（契約者の住所）を出す。住所2 は画面で直せない（CSV・Excel で直す）。住所2 は1つだけ（期間の違う複数の訪問先は持てない）
- 捨てた案：案A は読み直すまで期間の切り替わりを外し、先の予定は読み直しても外れる。案C は繰り返しの回ごとに持つ必要があり、予約システムの形（顧客ごとの住所2）とも合わない
- 見直す条件：住所2 を画面で直したい・複数の期間つきの訪問先が要る、となったとき
