# ADR-0073：最初の2問（デモ／自分のデータ × 単発／定期）で始め、組んだ予定は1か月先まで決まった扱いにし、画面の情報を例外だけに絞る

- 日付：2026-10-30
- 状態：採用（試作 `docs/prototype/simple-flow.html` で確かめながら段階で実装）
- 関連：PRD D379〜D387、ADR-0072（入れたら自動で組む・エキスパート機能）・ADR-0045（初めて開いたとき・ツアー）・ADR-0053（確定＝伝えた）・ADR-0059（メールで確定）・ADR-0068（名簿の CSV）・ADR-0028（機能の入り切り）

## 背景
- 利用者の声：デモの最初からカレンダーの予定を確定するまでの手順が多い。PoC で操作を説明しにくい。各画面の情報量が多い
  - 業務の手順は「人を登録 → 予定を入れる → 埋まった予定を見る」の3つなのに、組む・確定（伝えた）・標準・提案・反映が段階として並ぶ
  - 単発（ベビーシッター）と定期（訪問介護・看護・家事代行の定期）の機能・言葉が同じ画面に混ざる
  - 画面に点数・理由・件数・進み具合・凡例・印・説明文が常に出る
- 顧客から、介護ソフトの顧客台帳（利用者名・カナ・住所・電話・請求・口座・利用者状態など29列）の CSV をそのまま読み込みたいという要望
- 制約：ブラウザ完結・外部送信を増やさない（ADR-0001・ADR-0016）。同梱するデータは架空だけ

## 選択肢
1. 始め方：A＝最初に2問（デモ／自分のデータ、単発／定期）で設定とデータを決める／B＝今の「基本／すべて」の1問のまま
2. 確定：A＝ふだんの道から「確定」の段階を無くし、自動で組んだ予定は1か月先まで決まった（伝えた）扱い。伝えた記録はメールの送信で残し、決まったあとの変更に「変更あり」／B＝今の確定（伝えた）のボタンを残す
3. ホーム：A＝無くし、予定の画面の上の「要対応」の帯1本に統合／B＝残す
4. 情報量：A＝例外だけ見せる（正常な訪問は時刻・名前・担当だけ。点数・理由・内訳は「詳しく」へ）／B＝画面ごとに個別に削る
5. 顧客台帳の CSV：A＝名簿の読み込みが列名で形を見分け、顧客台帳の形も読む（請求・口座・生年月日は読まない）／B＝変換ツールを別に作る

## 決定
1-A・2-A・3-A・4-A・5-A（利用者が推奨どおりに決めた。2026-10-30）。業種では分けず、予約の形（単発／定期）で聞く。

### 最初の2問（D379〜D381）
- 初めて開いたとき（保存データが無い）に1画面で2問。ツアーの「どこまで使いますか」（D276）を置き換える
- 問1：デモで試す（型に合う架空のデータ）／自分のデータで始める（空のデータと登録の案内）
- 問2：単発の予約が中心（例：ベビーシッター）／定期の訪問が中心（例：訪問介護・看護、家事代行の定期）
- 決まるもの：呼び名（単発＝お客様／シッター、定期＝利用者さん／スタッフ）・最初に開く画面（単発＝週、定期＝月）・ひな形（単発＝「単発のみ」、定期＝「基本」）・デモのデータ
- 設定に「最初の設定をやり直す」（確認のあと2問に戻り、データを作り直す）
- 自分のデータで始めると、1画面1項目の3段（①〈利用者さん〉②〈スタッフ〉③予定）で登録を案内する。①②は「CSV・Excel を読み込む」と「1人ずつ入れる」

### 決まった予定（D382）
- エキスパート機能が切のとき、自動で組んだ日・手で直した日は、今日から1か月先まで決まった（伝えた）扱いにする（自動で記録。確定のボタンは出さない）
- 決まったあとの変更は訪問に「変更あり」の印。連絡の一覧（未連絡の変更）は「変更あり」を押すと出す
- メールで日の予定を送る・予約するときは今どおり伝えた記録を残す
- エキスパート機能が入なら今の確定（伝えた）の操作も出す

### 画面と情報量（D383〜D385）
- メニューは 予定・〈利用者さん〉・〈スタッフ〉・設定 の4つ（エキスパート機能が入なら今のメニュー）。ホームは無くし、予定の画面の上に要対応の帯1本（無ければ出さない）。空き状況は予定の「その他 ▾」から
- 例外だけ見せる：正常な訪問の札は時刻・名前・担当の1行。目立たせるのは担当なし・重なり・休みの人だけ。点数・理由・移動の分数・件数の内訳・凡例・進み具合は「詳しく」の中か、エキスパート機能が入のときだけ
- 主ボタンは1つ、操作の行は2つまで（ほかは「その他 ▾」）。画面の上の説明は1行（初回だけ出し、閉じたら出さない）。標準・提案・反映・ピン・プリセットの言葉はふだんの画面に出さない
- 〈利用者さん〉の詳細は 名前・住所・予定（繰り返し）。相性・担当を限る・段階・決まりごとは「詳しく ▾」で畳む。〈スタッフ〉は 名前・勤務日・勤務時間、資格・特性は畳む。日の予定の地図はボタンで開く

### 顧客台帳の CSV（D386・D387）
- 〈利用者さん〉の名簿の読み込みで、列名から顧客台帳の形（利用者名・利用者カナ・郵便番号・都道府県・市区町村・町名以下・建物名・利用者電話番号・利用者携帯電話番号・利用者状態・備考 など）を見分けて読む。区切りはカンマ／タブ、文字コードは UTF-8／Shift_JIS（BOM 有無とも）
- 読むのは名前・よみ（カタカナはひらがなに）・郵便番号・住所（4列をつなぐ）・電話（備考の先頭に）・状態（利用中＝利用中、ほか＝終了）・備考。請求・口座・生年月日・続柄・顧客番号は読まず、データに残さない
- 読み込みの結果（確認の本文）に、顧客台帳の形として読んだことと「読まなかった列」の一覧を出す。読む列のどれにも当たらない列（請求・口座・生年月日・性別・続柄・顧客番号・ほか）がすべてここに挙がる
- 郵便番号はデータでは7桁の数字（ハイフンなし。clientPlaceSchema）。ハイフン付き・7桁だけのどちらも同じ値になり、画面ではハイフン付きで見せる
- 突き合わせは今の名簿と同じ（名前）。読み込んだあと住所から位置を探すのは今どおり押したときだけ（ADR-0016）

## 理由とトレードオフ
- 得るもの：最初の操作が2問になり、デモは「人を見る → 予定を1件入れる → 担当付きで入った」の3手で説明できる。型ごとに要らない機能と言葉が消える。既存の顧客台帳をそのまま入れられる
- 失うもの：確定の段階を自動にするので、伝え忘れの管理は「変更あり」の印とメールの記録に頼る。ホームの「今日やること」のカードは無くなる。顧客台帳の請求・口座は読まない（このアプリの範囲外）
- 見直す条件：試作と協力者のテスト（作業1つを説明なしで5分以内）で迷いが多い所は戻す

## 影響
- 実装は段で分ける：(1) 顧客台帳の CSV（excel/roster の読み込み）(2) 最初の2問・型ごとのデモデータ・登録の案内・最初の設定をやり直す (3) 決まった予定（自動の伝えた・変更あり）(4) メニュー4つ・ホームの統合・画面の情報量
- PRD：`prd/simple.md`（D379〜D387）。D276・D277（ツアーの1問）は D379 で読む

## 第2段（最初の2問）で決めたこと
- 2問の画面は本文の代わりに出す門（`FirstRunGate`）。保存データが無いと答えるまでデータを書かず、読み直すとまた2問。データの版は変えない（ADR-0053 の「古い版は初期データで始める」はそのまま）
- 案内ツアー（D192）は初回に自動で出さない（利用者の決定）。見たかの記録（`vrdemo:tour:seen`）と「どこまで使いますか」（`TOUR_START_*`）は無くし、設定のデータの「案内をもう一度見る」だけ残す
- e2e の前準備は印 `vrdemo:features:start` = `all` のまま：あれば2問を出さず、今の初期データ＋すべて入で始める（D276）
- 初めに選んでおく答えは「デモで試す」「定期」（今までの初期データと同じ）。「最初の設定をやり直す」は管理者設定のいちばん下に置く
- 空のデータの事業所名は「自分の事業所」、単発の訪問の種類は「見守り・保育」。呼び名は単発＝お客様／シッター、定期＝利用者さん／スタッフ
- 登録の案内（`#/start`）①②の「CSV・Excel を読み込む」は名簿の欄（ADR-0068）をその場で開く（ひな形の「単発のみ」「基本」は Excel を切っているが、ここでは読み込める）
- 保存データが無いとき、2問は深いリンク（`#/staff-view`・印刷・`?id=`・`?do=`）も含めすべての URL で先に出す。答えたあとは（URL にかかわらず）最初の画面（デモ＝予定の週／月、自分のデータ＝登録の案内）へ移る（今の作りどおり。記録だけ）
- 初期状態に戻すは、最後の問2の答え（単発／定期）の印（`vrdemo:booking:last`。DemoData の外・印だけ）が残っていれば「デモ×その答え」で作り直す。印が無い・印 `all` のときは今までどおり定期。やり直しの2問には従のボタン「やめる」（今のデータのまま戻る）を出す

## 第4段で決めたこと（月・週の「予定を入れる」と人のタブ。PRD D388・D389）
利用者が決めた（2026-10-30）。エキスパート機能が切のときだけ（入は今のまま）。
- 月・週の主ボタンは「予定を入れる」（試作の主ボタンと同じ）。押すと引き出しで〈利用者さん〉・（定期）曜日・時刻・くり返し／（単発）日付・時刻・所要を入れて「入れる」。入れ方は繰り返しを使うか（機能 `patterns`）で決まる。保存は新しい仕組みを作らず、定期は〈利用者さん〉の繰り返しを足す処理（`usePatternAdd`。画面の「繰り返しを足す」と共通）、単発はその日の訪問を足す処理（`applyVisitEdit`）を使い、入れたあとは自動の組み（ADR-0072）で担当が付く。日の予定は今の「訪問を追加」が主ボタンのまま
- 操作の行（D384：主ボタン1つ・ボタンは2つまで）は 主ボタン「予定を入れる」＋「欠勤・キャンセルを登録」。「担当なしの訪問を組む N件」は「その他 ▾」へ回した。理由：担当なしは上の要対応の帯から見に行ける・入れた分は自動で組むので、いつも要る操作ではない。欠勤・キャンセルは当日の変更のほかの入口が無い。スマホは操作の行がアイコンだけだが、主ボタンは「予定を入れる」の文字を残す
- 〈スタッフ〉・〈利用者さん〉の一覧の見出しの下に小さいタブを出す：〈スタッフ〉＝一覧・勤務（勤務時間（シフト）・勤務の見込み）・相性、〈利用者さん〉＝一覧・相性。行き先の相性・勤務の画面にも同じタブを出す。メニューは4つのまま。相性は〈利用者さん〉×〈スタッフ〉の1つの表なので、どちらのタブから来たかを画面の中だけで覚え（`components/peopleSide`）、タブとメニューの印を来た側に付ける。予定と相性（`#/basics`）など旧画面のタブは出さない。相性の画面の説明から「点のしくみ」「条件の重み」を外した（切）
