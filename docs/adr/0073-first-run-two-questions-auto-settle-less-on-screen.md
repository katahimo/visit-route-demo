# ADR-0073：最初の2問（デモ／自分のデータ × 単発／定期）で始め、組んだ予定は1か月先まで決まった扱いにし、画面の情報を例外だけに絞る

- 日付：2026-10-30
- 状態：採用（エキスパート機能が入の画面は ADR-0074、メニューの空き状況は ADR-0078、担当なしを組む入口は ADR-0077）
- 関連：ADR-0028・0045・0053・0059・0068・0072

## 背景
最初から予定を確定するまでの手順が多く、単発と定期の機能・言葉が混ざり、画面に点数・理由・件数が常に出ていた。介護ソフトの顧客台帳の CSV をそのまま読みたい要望もあった。

## 決定（利用者が決めた。以下はエキスパート機能が切のとき）
### 最初の2問
- 保存データが無いとき、すべての URL で先に1画面2問（`FirstRunGate`）：デモで試す／自分のデータで始める、単発の予約が中心／定期の訪問が中心。答えるまでデータを書かない。既定の答えは「デモ」「定期」
- 決まるもの：呼び名（単発＝お客様／シッター、定期＝利用者さん／スタッフ）・最初の画面（単発＝週、定期＝月）・ひな形（単発＝「単発のみ」、定期＝「基本」）・デモのデータ
- 自分のデータは登録の案内（`#/start`。①〈利用者さん〉②〈スタッフ〉③予定）。①②の「CSV・Excel を読み込む」は名簿の欄を開く（ひな形で Excel が切でも読める）
- 管理者設定のいちばん下に「最初の設定をやり直す」（2問に戻り作り直す。「やめる」もある）
- 初期状態に戻すは最後の問2の答えの印（`vrdemo:booking:last`）があれば「デモ×その答え」で作り直す
- 案内ツアーは初回に自動で出さず、データの「案内をもう一度見る」だけ。`vrdemo:features:start` が `all` なら2問を出さず全部入で始める

### 決まった予定
- 自動で組んだ日・手で直した日は今日から1か月先まで決まった（伝えた）扱い（確定のボタンは出さない）
- 決まったあとの変更は訪問に「変更あり」の印。押すと連絡の一覧
- メールで送る・予約するときは今どおり伝えた記録を残す

### 画面と情報量
- ホームは無くし、予定の画面の上に要対応の帯1本（無ければ出さない）
- 例外だけ見せる：正常な訪問の札は時刻・名前・担当の1行。目立たせるのは担当なし・重なり・休みの人だけ。点数・理由・内訳・凡例・進み具合は「詳しく」の中
- 主ボタンは1つ、操作の行は2つまで。画面の上の説明は1行（初回だけ）。標準・提案・反映・ピン・プリセットの言葉は出さない
- 〈利用者さん〉の詳細は名前・住所・予定、ほかは「詳しく ▾」。〈スタッフ〉は名前・勤務日・勤務時間。日の予定の地図はボタンで開く
- 月・週の主ボタン「予定を入れる」：引き出しで入れ、定期は繰り返しを足す処理（`usePatternAdd`）、単発は `applyVisitEdit`。入れたあとは自動の組み。日の主ボタンも「予定を入れる」（`lib/exceptionView` の `addVisitLabel`）
- 操作の行は「予定を入れる」＋「欠勤・キャンセルを登録」

### 顧客台帳の CSV
- 〈利用者さん〉の名簿の読み込みで、列名から顧客台帳の形を見分ける（ADR-0075 の形の一覧）
- 読むのは名前・よみ（カタカナはひらがなに）・郵便番号・住所（4列をつなぐ）・電話（備考の先頭に）・状態（利用中＝利用中、ほか＝終了）・備考。請求・口座・生年月日・続柄・顧客番号は読まず残さない
- 確認の本文に顧客台帳の形として読んだことと読まなかった列を出す

## 捨てた案
「基本／すべて」の1問のまま・確定のボタンを残す・ホームを残す・画面ごとに個別に削る・変換ツールを別に作る。

## トレードオフ
- 失うもの：伝え忘れの管理は「変更あり」とメールの記録に頼る。顧客台帳の請求・口座は読まない
- 見直す条件：協力者のテスト（作業1つを説明なしで5分以内）で迷いが多い所は戻す
